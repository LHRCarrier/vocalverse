## 2. 为什么不是「移植」方案

1. **与已拍板移动端方案冲突**：docs/27 §3 路线对比表中 Flutter/RN 重写被**明确否决**（复用率 0、团队无移动端原生经验、页面全重做、1 个月窗口不可能），D1 裁定 Capacitor 8 套壳复用现有 Vue 应用。迁移 Fwitter = 推翻该裁决重新评审（需过 docs/06 ADR 修订流程）。
2. **工程投入错配**：Dart 3 迁移 + Firebase 全家桶替换（→ FastAPI/JWT）+ 领域模型重做，实际能保住的只有 UI 骨架（约 30~40% 代码），剩余全是重写——性价比低于直接按结构重做 Vue 版。
3. **产品错配**：它是「Twitter 产品」的复刻；咱们社区是「帖子+视频+三个领域+投币」的**学英语内容社区**（docs/02），借结构、不借模型。

## 4. 组件粒度参考（对照 docs/31 §4 组件规范）

Fwitter 把帖子卡拆成 8 个子组件，这个粒度值得抄进咱们社区卡：

| Fwitter 组件 | 职责 | 咱们落点（docs/31 现有组件） | 建议 |
|---|---|---|---|
| `tweet.dart` | 帖子卡容器（头像+正文+媒体+互动行） | `.s-card` 族（尚无社区卡规范） | M3 社区卡按「容器/元信息/媒体/互动行」四段拆 |
| `tweetIconsRow.dart` | 互动行：回复/转发/点赞/计数+激活变色+波纹 | `.s-row` / 互动行 | **三态反馈**（default/press/disabled）补进社区互动项；docs/31 硬规则 3 |
| `tweetImage.dart` | 1/2/3/4 图网格布局 | 演示帧现为单渐变图 + 视频封面 | 多图网格（视频帖封面+时长角标已有雏形）按此对照 |
| `parentTweet.dart` | 被引用帖（灰底+省略+跳转） | 无 | 评论楼「引用原帖」形态 |
| `unavailableTweet.dart` | 失效帖兜底（灰卡占位） | 无 | 删帖/违规帖兜底占位 |
| `retweetWidget.dart` | 转发体系 | 无（咱们用「投币」） | 不抄转发模型，但**「转发卡片+原帖引用」的双层视觉**可参考投币/分享展示 |
| `tweetBottomSheet.dart` | 帖子底部操作 sheet | 无 | 帖子更多操作统一用 bottom sheet，菜单项：分享/复制/举报/收藏 |
| `emptyList.dart` / `customLoader.dart` / `customProgressbar.dart` / `rippleButton.dart` | 空态/加载/进度/波纹按钮 | docs/31 硬规则 3（>300ms 出 spinner） | **空态规范**（无帖/无网络/无收藏）按此补齐；加载态已部分覆盖 |

其它可参考：`bottomMenuBar`（中央凸起发布按钮的悬浮 TabBar）——docs/31 §4 `.s-tabbar`（4 项+中央主按钮 spring 弹起）已是其升级版，**无需再看**；`customUrlText` + `link_preview`（链接预览卡）——帖子含外链时参考。

## 5. 交互/状态参考（按价值 P0→P2）

**P0（随 `/m/home` M3 真实流一起落）**

1. **信息流分页状态结构**（`state/feedState.dart`）：游标分页 + 下拉刷新 + 「X 条新帖」提示条 + 滚动位置保持 → 用 pinia 重写等价结构（社区真实流 JOIN 派生，docs/10 注记）。
2. **帖子卡互动三态**：点赞/评论/投币/分享图标 `default/press/active` 三态 + 计数动画（docs/31 硬规则 3 的有交互即有反馈；颜色不作单通道，配数字/图形双通道）。
3. **加载/空态**：>300ms spinner、无帖空态插画+行动按钮、错误重试（docs/31 硬规则 3 + 组件规范 `.s-state` 族）。

**P1（M3 后 / 评论与搜索）**

4. 评论楼：嵌套缩进 + 引用帖灰卡；「回复」与「发帖」共用发帖入口（参考 composeTweet 与 thread 的共用方案）。
5. 帖子操作 bottom sheet：分享（系统分享单）/ 复制 / 举报（表单）/ 收藏——参照 `tweetBottomSheet` 组织。
6. 搜索/词汇速记：Tab 分型（热门/用户/教程）+ 历史清空；参考 `SearchPage` 结构。

**P2（留档，暂不做）**

7. 通知中心分型 tile 结构（关注/点赞/评论/提及）——M3 有真实点赞/评论流后按需启用。
8. 图片查看器黑底 + 双指缩放（帖子图点开）。
9. 主题组织方式（不做深色皮肤，只参考「语义色/字级/组件样式」单文件组织，docs/13 三层 token 已覆盖）。

## 6. 反借鉴清单（明确不抄）

| 项 | 原因 |
|---|---|
| **视觉风格**（2020 老版 Twitter：白色干净流 + HelveticaNeue + TwitterIcon 自绘字体） | ① 老版，非现行 X；② 与 docs/31 Soft UI Evolution（暖色/硬偏移阴影/Plus Jakarta Sans）冲突；③ X 品牌字体/图标有商标问题 |
| Firebase RTDB/Firestore **数据层监听模式** | 咱们后端 = FastAPI + JWT + PostgreSQL（Alembic 唯一 schema 真源）；实时性用 SSE（音频流）/轮询，不做客户端直连数据库 |
| Google Sign-In / 邮箱验证体系 | 咱们走演示账号 + JWT（docs/06）；登录路径已按 docs/31 样板简化 |
| 产品模型（follow/DM/QR/转发/书签） | VocalVerse 社区 = 帖子+视频+三领域+点赞/评论/投币/分享；借结构不借模型 |
| 任何 Flutter 代码/素材 | 团队栈 Vue；且与 docs/24 许可红线一致（只借思路不拷代码素材） |

## 7. 落地建议（对接 docs/31 §5 与 docs/33 SOP）

1. **随 docs/31 铺开顺序**（`/m/home` 重制已排首位之外的社区页改造）：
