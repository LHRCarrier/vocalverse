## 一、拷问方法（几轮、何时判定穷尽）

按部署方法做 **4 轮递进**：

- **第 1 轮（扫表面缺陷）**：逐节通读 docs/14，先抓「写了但没定义」「前后不一致」的硬伤——M2 覆盖缺口、路由冲突、口径登记、与 docs/10 的写归属与删除语义冲突。
- **第 2 轮（打业务逻辑链）**：A 承诺是否被 B 支撑——达成度与「不是复读机」对立、答辩「自定义」是否差异化、指标（互动率/完成率）能否在新会话类型下成立、文档间的口径是否自洽。
- **第 3 轮（算成本/数据）**：内容编写量 vs 交付、演示时间 vs 5 分钟死线、指标究竟算不算得出来、排期人日配平。
- **第 4 轮（打边界与失败模式）**：用户不会用/用不好怎么办、demo 现场失败预案、评委追问（「达成度算不算口语能力」「LLM 只读摘要能问多深」「你的系统会不会自夸」）怎么答、文档自证循环。

**深挖下一轮的追加检验**：第 4 轮结束时，我尝试再追第 5 轮，新增的非琐碎问题仅 **3 个**（B-6 脚手架定位、D-3 语料分档、E-3 用户画像），且其中 2 个与前几轮的 D-2/B-1 同根。按「新问题 ≤2 即穷尽」的约定，判定在第 **4 轮** 达到穷尽（第 5 轮新增的 D-3 与 B-1/D-2 高度同源，实际净新问题 ≤2）。**穷尽结论见第六节。**

### B. 差异点真实性（四个差异点站不站得住）

#### B-1｜达成度 vs「不是复读机」的自洽矛盾：要让达成度命中率高，AI 必须把对话「引导」到这 8 条，这接近带读而不像自由对话。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §1 立论「不是和 AI 聊天（开放不可量化）…也不是跟读复读机（可控但不像对话）」。§2.1 达成度 = 命中 `target_corpus`；§3.4 又要求「自然引导使用，不硬塞」。这三者互相拉扯：AI 若不引导，用户对 8 条低频命中（达成度难看、学习者挫败）；AI 若引导到目标句，就成了变相带读——与 §1 声称避开的两极之一（复读机）高度重合。达成度是**主打**差异点，但它把产品往「可控但机械」这一端拉。
- **候选答案**：A 明确「引导=表达层引导（提出需要该语言点的话题）而非句条带读」，并把达成度定义为「语言点覆盖」（课堂学习视角）；B 接受「引导到目标句」事实，把口播改成「这节课带你把这些话说到位」；C 换成开放对话 + 语义评估，取消固定语料命中。
- **推荐答案**：**A**——把「引导」限定在话题/需求层，让目标表达是**被话题自然引出**而非被句条带出；答辩口径强调「达成度衡量这节课语言点的口语覆盖，不是背句子」。
- **优先级**：P0（这是差异点立论与产品定位的根本矛盾，必须先自圆）。

#### B-2｜「竞品没有」是否成立 + 评委问「达成度算不算口语能力」怎么答——它本质是「说没说出预置词」的表面检查。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §2.1 断言「多邻国/流利说/ChatGPT voice 均无此概念」。但流利说（情景对话+逐句达标）、多邻国均有「目标句型+达标反馈」教学机制，ChatGPT 可用 prompt 让用户复述指定句——**「有没有说出预置表达」不是独占概念**。更致命的是：docs/14 §3.5 定义「命中 = 用户本轮回放中明确说出该表达（ASR 文本为准）」，**未要求语法/语义正确**——一句语法错误但含目标词的话也算达成。这会被一句戳破：「你这不就是把关键词出现与否当成了口语能力吗？」。docs/06 §9.3 虽有「内容相关度不进量化总分」，但「不进总分」≠「这不是能力度量」。
- **候选答案**：A 口径改「习得信号、不计分」，命中要求该轮无致命语法错误（或提供「命中但需纠错」双态）；B 命中仅作「开口覆盖」弱信号，报告给「这节课语言点覆盖/待练」；C 弱化为「你说到了哪些表达」的动机激励。
- **推荐答案**：**A+B**——保持「不进量化总分」，但命中至少区分「说出且无致命语法错」与「说出但有语法错」，报告给覆盖度而非「达成/未达成」二值；答辩口径统一为「学习覆盖视角，不是口语能力分」。**能不能算口语能力 → 明确「不算，是教学覆盖信号」**。
- **优先级**：P0（命中是否要求正确性直接决定指标/报告逻辑怎么敲）。

#### B-3｜教练双人格「角色反驳、教练却表扬」的语义冲突 + 每回合五路反馈是否认知过载。P1
- **为什么重要/矛盾点**：docs/14 §2.2 教练笔记 tier = praise/hint/correct，与角色台词并存。但同一轮里角色可以反驳（如「不，我们没有这个」）而教练给 praise（因为引导用词达标），**同一轮出现「角色否定、教练表扬」的矛盾反馈**——评委在 demo 里一眼看到。且每回合用户同时接受：角色回复 + 教练一句(≤15词) + 三色徽章 + 达成度命中逐条 + 进度条 + 词级错误，反馈密度远超一句口语的消化能力（docs/07 无此密度口径）。docs/07 的 Q29-Q30 只定义了评分细节，没定义「回合内多通道反馈的层级」。
- **候选答案**：A 教练笔记与角色语气绑定（角色反驳时教练给 hint/correct 而非 praise），且反馈分两级（回合内一屏=角色+徽章；教练笔记+达成度折叠）；B 保留全量但默认折叠、可展开；C 砍教练双人格只留角色。
- **推荐答案**：**A**——把「本轮实际质量」作为角色与教练的共同输入，保证同回合同源不矛盾；反馈做层级收起，避免五路同屏。
- **优先级**：P1（开发中可定，但 W2 前端要按这套做，建议早定）。

#### B-4｜答辩「用户自定义内容」不是对 ChatGPT 的差异化——ChatGPT 用一条 prompt 就能让用户粘贴论文并让其提问，且更灵活。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §2.4 断言「竞品全是预制内容库，本功能打开用户自定义内容天花板」「用户自定义内容」是第四王牌。但 ChatGPT voice/纯对话完全可以接受用户粘贴任何文本并扮演考官提问，**无需任何设置**；「用户自定义」不是排他能力，评委一句「ChatGPT 也能让你贴论文让它考你」就击穿。真正的差异应落在「**结构化**自适应阶梯 + 回答质量评分 + 练习闭环」，而非「能做自定义」。
- **候选答案**：A 差异化话术改口：差异不是「能不能自定义」，而是「把自定义论文变成**有阶梯、有评分、有闭环**的英语答辩训练」；B 保留「自定义」作差异化但强化证据；C 砍第四差异点，只留「达成度+双人格+脚手架」。
- **推荐答案**：**A**——把第四差异点从「用户自定义内容」改为「把真实刚需（论文答辩）做成**有考评闭环**的专项训练」；因「自定义」本身人人可做、立不住。此辨析与 G-2（砍谁）联动。
- **优先级**：P0（决定第四差异点到底宣称什么）。

#### B-5｜脚手架与「互动率」检查点互斥：救场轮不计主动轮，但「分配轮数」分母含救场轮 → 越依赖救场互动率越低，救场又拉高完成率。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §2.3 救场轮不计主动轮（互动率分子不收污染）；§7 互动率 = 主动发消息轮数/分配轮数；docs/06 §9.1 同。若「分配轮数」=该会话总轮数（含救场轮），一个全程靠救场的学习者：主动轮少、分母大 → 互动率被压低；而救场又保证「永不冷场」→ 完成率（5 轮或 2min）虚高。**救场的初衷是帮窘迫的学习者，却让他的互动率检查点更难看；两个检查点指标对同一行为给出相反评价。**
- **候选答案**：A 救场轮同时从分子+分母剔除（互动率 = 非救场会话内的主动/分配）；B 互动率分母 =「AI 给过语料后用户有效开口的轮次」；C 拆分：互动率衡量「主动开口」，救场单独作为「功能互动/困难度」指标上报，不与完成率/互动率混。
- **推荐答案**：**C**——互动率衡量「主动开口」本就该把「被救场」排除，并同时从分母剔除（非救场的主动/分配）；救场单独计「功能互动/困难度」，避免与完成率、互动率互斥。否则检查点「互动率」被救场设计污染，数据解释不了。
- **优先级**：P0（指标口径与脚手架耦合，开工前要对齐）。

#### B-6｜L1 提示卡直接给「参考句+中文释义」+ L2 示范播放参考句 = 纯带读，与 §1「不是复读机」相悖，且三级阶梯对 M2 是过度设计。P1
- **为什么重要/矛盾点**：docs/14 §1 明确定位「不是跟读复读机」；§2.3 L1 提示卡显示参考句+中文释义、用户 retry（=跟读该句）；L2 示范 TTS 播放参考句、用户跟读（=逐句带读）；§3.6 又把参考句作为「正确示范」。救场第一、二级就是纯带读，恰恰是 §1 声称避免的模式。且 8s/8s/连续 2 轮触发、与 ASR/processing 并行，对 2 周 M2 是实质复杂度（docs/14 §10 没核算这部分前端/Python 工作量）。
- **候选答案**：A 提示卡改「引导词/句式骨架」而非完整参考句（留一点思考），示范仅在明确跟读学习点才播；B 保留完整参考句但明确「救场=带你过一遍」，口径区分「教学跟读」vs「复读机」；C 砍 L1/L2，只留 L3 代说 + 高亮提示。
- **推荐答案**：**B**——保留救场，但在口径上把「救场带读」作为显式教学步骤，与「不是复读机」定位区分开（救场=定向帮困，非主交互）；同时把 demo 场景触发压到 2 级（提示+代说），避免过度设计挤占时间。
- **优先级**：P1（demo 效果强但复杂度高，W2 前定）。

### C. 学习有效性

#### C-1｜达成度「8/8」基本不可达：8 条语料 vs 8 轮上限几乎一一对应，正常会话最多命中 5~6 条，报告永远残缺 → 负向激励。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §2.1 `target_corpus` 6~10 条（定 8），§3.2 轮次 ≥8 收尾，§5 报告「达成 x/8」。8 轮里若每轮顶多引出 1 条，理想上界=8，但用户分神、AI 换维度、表达差异都让命中数低于 8；「达成 6/8 + 未达成清单+参考表达」对学习者更像「你没做到」的问责，而非「这课的语言点覆盖」。
- **候选答案**：A 每场景 `target_corpus` 降到 4~5 条，让 6~8 轮内可合理覆盖；B 改「覆盖度」口径（按难度层命中即算，不要求全中），报告给「覆盖了哪些/剩哪些待练」；C 保持 8 条但报告用「已覆盖/可挑战」弱化问责。
- **推荐答案**：**A+B**——降语料条数至 4~5 或改「课堂覆盖度」口径，让达成度成为**可完成的正向目标**而非永远残缺的问责单。
- **优先级**：P0（直接影响产品正向引导与报告语义）。

#### C-2｜「再练」不是真正的第二遍：同场景难度+1 但 target_corpus 全档共用、开场只换 2 套——再练是同一批表达的不同配音。P1
- **为什么重要/矛盾点**：docs/14 §5 再练 = 同场景难度+1/换场景；§3.1 target_corpus 全档共用、每场景仅 2 套开场。L3 练完 → 再练到 L4，练的是**同一批 8 条表达、几乎同开场**，只是语速/句长微调。学习上这不是新难度新语料，是重复。docs/07 Q23/Q49 强调「再练」作为闭环一环，若再练=重复同内容，闭环的「进阶」价值被抽空；且 docs/14 §3.2 结束条件是轮次≥8 或用户结束，报告**没有给「换题重练/同一批题再试」的第二遍机制**。
- **候选答案**：A 每难度档独立 target_corpus（至少 L1/L2 与 L3/L4 两套）；B 再练时从同场景更宽语料池抽**未命中过**的表达，让第二遍练不同语料；C 明确「再练=复习同语料」，答辩口径「复习巩固」而非「进阶」。
- **推荐答案**：**B**——再练从同场景更宽语料池抽未命中表达+升难度，让「第二遍」是真新语料；否则闭环退化成重复播放（尤其答辩论题「练一次就结束」——§4.5 只有换题/升倾向，缺对同一批题**先练后评再重练**的第二遍机制，需补）。
- **优先级**：P1（学习闭环的核心，W3 报告/再练开发前定）。

#### C-3｜命中判定双重失真：规则通道漏同义改写（假未达成→冤枉学习者），LLM 兜底温度 0.6 偏不稳。P1
- **为什么重要/矛盾点**：docs/14 §3.5 双通道——规则（归一化后子串/词序）漏同义改写，产生「学习者表达得很好但被判未达成」；LLM 兜底走 §3.4 同一次调用（角色 0.7/命中 0.2 被折中成温度 0.6）。判定命中这**需要稳定**的任务用 0.6 偏高，出现边界抖动（假命中/假未达成）。达成度作为主打差异点，判定自身不稳会让报告失真，冤屈学习者。
- **候选答案**：A 命中判定单独走低温（或与角色拆开），规则通道兜底明确「语义等价命中」边界；B 命中改为「该轮表达覆盖目标语义」的软信号（0/1/部分），报告给「覆盖度」非二值；C 接受现状，答辩口径「以语料命中为主、语义兜底为辅」。
- **推荐答案**：**A**——把命中判定从对话主调用解耦（低温/独立判定），并给「语义等价命中」明确边界；这是主打差异点，不能靠一次性混合调用碰运气。技术细节留给技术官，但「达成度稳定性是业务承诺」这一层判定必须成立。
- **优先级**：P1（开发中定，但影响 W2 前是否拆分调用）。

#### C-4｜水平档只在入学测一次、练习/再练不回流更新——M2 闭环缺「练习→水平」反馈，学习者练多次仍停在 L3。P2
- **为什么重要/矛盾点**：docs/06 §9.2 水平档由入学测试一次判定；docs/14 §5 再练「同场景+1 档」仅指次回难度，未让练习成果回流更新水平档；docs/06 §9.5 水平预测（M3）用练习行为预测「未来水平」，但 M2 没有任何「练习→水平」回写。学习者练 10 次仍 L3，产品「进阶感」缺失，与 §9.5 的进步趋势展示脱节。
- **候选答案**：A M2 加「练习档位回流」（完成会话后重估并提示是否达下档）；B 明确水平档只在入学测试/定期复测更新（M2 不回流，口径写进报告）；C 后置 M3 水平预测再连。
- **推荐答案**：**B**——M2 明确「档位由入学测试+定期复测更新，练习分不直接改档，进步看水平预测（M3）」，先把口径说圆，避免 M2 承诺「练完升档」却没实现。
- **优先级**：P2（口径问题，可后置，但别让 demo 误导）。

### D. 内容与运营成本

#### D-1｜4 场景 ×2 套文案 ×8 条 target_corpus 的「谁写、质量验收归谁、管理端(Java)是否动作」没定义，且与 docs/10 写归属（场景表=Java 写）+ seed 单写豁免待拍板冲突。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §9 W1 内容准备归「组长 + 算法」，W2 seed 场景归 Python/前端；但 docs/10 §4.2 `scenarios` 表写方 = **Java**，§7.3 seed 走 Python seed.py 且「seed 单写豁免」**仍待拍板**（docs/10 §7.3 明确「拍板前 seed 不得对帐号表写入」）。产品核心内容是这些 `target_corpus`（自然度、可引导性、难度梯度直接决定达成度与产品观感），却**无内容质量验收人/验收标准**；Java 场景库 CRUD 在 M2 是否用于内容维护也未说。
- **候选答案**：A 明确内容作者、验收标准（每条表达自然可引导、难度梯度、无语法错）、验收人（组长+前端人工过 2 遍），并拍板 seed 单写豁免；B 内容走 Java 场景库 CRUD 维护（管理端动作，写归属自洽）；C 先定内容，Java 管理端 CRUD 后置 M3。
- **推荐答案**：**A**——先把内容生产/验收的责任人与标准拍死（内容是这个产品的命门），并顺带拍板 seed 单写豁免，否则 W1「内容准备」是空转。
- **优先级**：P0（内容 W1 就要开始写，开工前必须有人/标准）。

#### D-2｜「2 套文案 + 难度参数化」撑不起 docs/07 Q22「不同难度档进入不同开场」——L1/L2 同开场、L3/L4 同开场，demo 无法演示 4 档各自独立开场。P1
- **为什么重要/矛盾点**：docs/07 Q22/ADR 8「每个场景含难度分级、多轮配置；demo 能演示不同难度档进入不同开场」；docs/14 §3.1 每场景只 seed **2 条**开场（difficulty 1~2 / 3~4 各一套）。4 档只有 2 种开场，L1/L2 与 L3/L4 重复；若 demo 想演示 L1 vs L2 的「不同难度档不同开场」，看到的是**一样**的。且难度差异靠 TTS rate/句长/词汇等级这类很细微的参数，观感上「分档」不明显。
- **候选答案**：A 每场景 4 套开场（4×4=16 套，成本高）；B 改「2 套开场 + 参数化」但 demo 只演示**跳档**（L2 vs L4），规避同档重复；C 明确难度观感 = 语速/句长/词汇，开场只分 2 档，答辩口径「难度差异主要体现于对话节奏与词汇，开场按档位粗分」。
- **推荐答案**：**B**——demo 演示跨档（L2 vs L4）放大难度差异观感；同时把「难度差异 = 节奏/词汇/句长」写进 docs/13 验收话术，避免被追问「L1 和 L2 有啥不同」时接不住。
- **优先级**：P1（内容与 demo 编排 W1 前定）。

#### D-3｜L1 与 L4 共用同一批 target_corpus——「专业定制」（案例要求）的难度差异没落到学习内容上。P2
- **为什么重要/矛盾点**：docs/14 §3.1 target_corpus 全档共用；docs/06 §9.2「内容按难度档组织」；案例基础功能强调「专业定制」。「定制」若只体现在语速/句长/词汇等级而不在内容本身，L1 与 L4 练的是一样的句子——作为「专业定制」答辩点偏弱，评委可问「难度分档到底改了什么」。
- **候选答案**：A 每档一套语料（4×4×8=128 条，成本高）；B 至少分 L1/L2 与 L3/L4 两套语料；C 明确「难度 = 交互复杂度+语速+词汇级」，语料共用，答辩口径「难度通过交互与节奏体现，语料按场景主题组织」。
- **推荐答案**：**B**——至少两套语料（入门套 vs 进阶套），让难度档真正改变学到的东西；成本 4 场景 ×2 套 ×8 条 = 64 条，可控，且比「全档共用」的「专业定制」更有说服力。与 D-2 同根，可一并拍板。
- **优先级**：P2（可与 D-2 合并决策；对「专业定制」答辩有帮助）。

### E. 答辩边界

#### E-1｜「发散性提问」无边界 + 「读摘要问深度」的验收不明：LLM 只读 ≤8000 字文本+摘要+大纲，能问多深、问得浅算不算兑现。⚠️ P0（若答辩留在 M2）
- **为什么重要/矛盾点**：docs/14 §4.1 摘要 ≥200 字、论文文本可选 ≤8000 字；§4.2 三级题库含 T3 发散（场景变化/商业落地/未来工作）。8000 字对一篇真实论文是**片段**；LLM 主要读摘要+大纲+创新点。T3 发散问题「无边界」，评委可追问「它问得这么泛，跟读摘要有什么区别」「你凭什么说它『理解』你的论文」。§4.2「摘要+大纲+创新点已覆盖 90% 提问面」是**无依据断言**。「根据当前答辩程度提问」（§4.3）事实是 LLM 读摘要后按回答质量分调度，问得浅不浅没有验收标准。
- **候选答案**：A 收紧：发散题限制在「由摘要/大纲能推出的范围」，并在 knowledge_bank 里给每道题标「依据来源（摘要哪句/大纲哪章）」，让「它问得有据」可审计；B 提高论文文本上限并做篇幅分块（MVP 无 RAG，成本高）；C 把「理解论文」表述为「按你提供的摘要/大纲提问，深度限此」的诚实口径。
- **推荐答案**：**A**——给每道题附「提问依据（引用摘要/大纲原文）」，既是 §4.2 说的「教学材料」，也是可审计的「它确实有据」；并把「根据答辩程度提问」的验收标准写死（见 E-2），防止发散失控与浅问糊弄。若答辩降级为 P1（见 G-2），此边界相应 P1。
- **优先级**：P0（答辩留在 M2 则开工前必须定边界；否则随答辩降 P1）。

#### E-2｜「根据当前答辩程度提问」+「回答质量分」的验收标准不明，且答分链路是 LLM 自证循环。P1
- **为什么重要/矛盾点**：docs/14 §4.4 回答质量 = 0.6×要点命中率 + 0.4×结构质量；要点命中 = 规则 + LLM 边缘兜底（同达成度双通道）；§4.2 knowledge_bank 的 key_points 是 **LLM 生成**。LLM 写标准答案 → LLM 判用户是否命中 → LLM 给结构分，**链路完全自证**，可靠性低；若 key_points 很浅，用户浅答即高分，自适应阶梯（§4.3 ≥80 追问/升层、<60 降层）随之失灵。
- **候选答案**：A 明确「要点命中」规则（归一化+关键概念词匹配）与「结构质量」三子项（结论先行/逻辑链/数据引用）打分标准，各留一条人工校准样例；B 引入少量专家预置的答辩 gold 问答做校验（成本高）；C 把回答质量定位为「软提示」不作硬分数，报告给「建议」而非 0-100。
- **推荐答案**：**A**——写死要点命中规则边界 + 结构质量三子项打分细则，并给 1~2 条样例校准；答辩口径「自研+LLM 融合、可审计」，避免被指「LLM 自证循环」。
- **优先级**：P1（答辩开发前定；规则不写清则答分不可信）。

#### E-3｜答辩目标用户是谁？核心人群（各年龄英语学习者）与「英语论文答辩」这一高阶学术场景错位。P2
- **为什么重要/矛盾点**：docs/06 §9.2 人群 = 儿童/青少年/成人/老年英语学习者；docs/14 §2.4 答辩 =「论文答辩是真实刚需」。但「用英语做毕业论文答辩」是高阶学术英语（academic English）人群的特需，与产品核心的通用口语练习人群**错位**；且答辩面向成人（§8），与儿童/青少年主人群分流。若 M2 demo 主打答辩，会偏离「说得好、唱得准」的通用定位，易被问「你的目标用户到底是练口语的，还是写论文的研究生」。
- **候选答案**：A 把答辩定位为「专项口语训练」而非独立人群，入口标注「面向学术/职场英语高阶用户」；B 主打通用场景，答辩作为「差异化附加」副线；C 砍答辩。
- **推荐答案**：**A**——明确答辩是「高阶专项口语」细分入口，不改变主人群定位；demo 上作为「差异化亮点」而非主故事线，避免与人群定位打架。
- **优先级**：P2（口径问题，但影响答辩是否值得做，见 G-2）。

#### E-4｜docs/14 §4.4 给「回答质量」打 0~100 并驱动自适应阶梯，与 docs/06 §9.3「LLM 只做引导与润色反馈、内容相关度不进量化总分」口径冲突。⚠️ P0（ADR 冲突）
- **为什么重要/矛盾点**：docs/06 §9.3 定稿「场景内容相关度**不进行量化总分**；LLM 只做引导与润色反馈」。docs/14 §4.4 却给答辩「回答质量 = 0.6 要点命中 + 0.4 结构质量」独立打分，且 §4.3 用该分驱动自适应阶梯（≥80 追问/升层、<60 降层）——即 **LLM 在给「内容质量」打分并据此动态决策**，与 docs/06 §9.3「LLM 只做引导与润色」相悖。docs/14 虽强调它「不进 S」，但「进不进总分」≠「LLM 不做内容质量量化」；答辩用了一个被整体口径禁止的内容评分。这是**文档间直接冲突**。
- **候选答案**：A 在 docs/06 §9.3 登记「答辩专项例外：内容质量评分仅在答辩模块、不进通用口语 S」，并把「LLM 只做引导与润色」改为「引导+润色+答辩专项内容质量（注明边界）」；B 回答质量不量化成 0-100，改成「要点覆盖/结构」等级或红黄绿标签驱动阶梯；C 严格遵 §9.3，答辩不评内容质量，阶梯退化为题数/层数调度。
- **推荐答案**：**A**——保留回答质量则须在 docs/06 §9.3 登记「答辩专项例外」并写明边界，否则两文档口径打架，评审必抓；若想严格不冲突，则走 B（不量化、用等级标签驱动阶梯）。
- **优先级**：P0（这是与 ADR 权威文档的直接冲突，须先登记例外或改口径）。

- **优先级**：P0（schema/删除策略决策，先与 docs/10 对齐）。

#### F-2｜论文文本是全新的敏感数据面，docs/06 §9.7 毫无条文——未登记论文数据如何存/存多久/是否需加密。P1
- **为什么重要/矛盾点**：docs/06 §9.7 只覆盖音频 24h、未成年人、公开仓库红线，**无论文数据**（用户自有文本，可能含未发表研究/机密方法）的处理条文；docs/14 §8 只说「用户自有数据、可随时删除、硬删接口」。论文文本+摘要+大纲+创新点会持久化进 defense_profiles（含 thesis_text 可选），是用户上传的最高敏自定义内容，却无存储期限/加密/去标识化条文。这是 docs/06 §9.7 的**合规空白点**，评审易问「你存用户的论文，怎么保证安全」。
- **候选答案**：A 在 docs/06 §9.7 登记论文数据处理（用途限定/可删除/提示勿传未发表/存于用户私有 profile）；B 论文文本不入库，仅存摘要+大纲（用户显式允许才存原文）；C 默认 24h 清理（同音频）。
- **推荐答案**：**A**——docs/06 §9.7 补「论文数据面」条文，docs/14 §8 同步；这是新的合规空白点。
- **优先级**：P1（答辩若留在 M2 则 P0 级，见 G-2）。

#### F-3｜meta 演示（用 VocalVerse 演练 VocalVerse 答辩）有「自夸」与「真实感」双重风险，且课程项目内容撑不起 8 个深度追问。P1
- **为什么重要/矛盾点**：docs/14 §2.4 杀手级演示「用 VocalVerse 演练自己的项目答辩」，§8「演示一律用模拟论文（推荐直接使用 VocalVerse 项目自身内容做 meta 演示）」。风险：① 自夸感——「我们的系统能自己答辩自己」偏秀技术而非演示价值；② 论文内容是你的课程项目/文档，摘要、大纲其实很薄（200 字抽象+章节列表），LLM 只能就项目外层提问，深度有限；③ 若 LLM 问出浅问题或暴露项目短板，演示反噬。
- **候选答案**：A 换真实感强的模拟论文（如「基于 LLM 的口语评测系统设计」抽象样例），规避自夸与薄内容；B 保留 meta 但预生成知识包并精选 5 个能体现深度的摘要小节；C meta 演示仅作屏录彩蛋，主 demo 用自研模拟论文。
- **推荐答案**：**A+C**——主演示用一份结构、深度都合格的「模拟论文」，meta 演示降级为屏录彩蛋；答辩明确「用模拟论文演示能力，meta 是自嘲式收尾」，避免自夸风险与薄内容反噬。
- **优先级**：P1（demo 编排 W3/M4 前定）。

#### F-4｜演示入口与 5 分钟脚本：M2 演示只给「成年中级-场景 + 答辩导师」两个入口够不够，meta 演示的知识包现场生成超时风险。P2
- **为什么重要/矛盾点**：docs/14 §10 D-16 问「两个入口够吗」；docs/06 §9.5 推荐生效用 3 画像；docs/07 Q2/Q49/Q51 强调 5 分钟可复现、无人工救场。知识包生成 §4.2 同步生成耗时 5~10s（docs/14 §10 B-9 已列为技术待定），现场若现生成会卡 demo；且 M2 演示需展示完整闭环（注册→入学→场景→再练）+ 答辩，5 分钟很紧。
- **候选答案**：A 演示预生成知识包（离线缓存）+ 只演示「场景闭环 + 一个答辩入口」，答辩用预置 mock 数据；B 两个入口，现场生成但用预置题目兜底；C 演示只做场景闭环，答辩进 M3。
- **推荐答案**：**A**——答辩演示用预生成知识包（现场秒进），5 分钟脚本聚焦「场景闭环 3 分钟 + 答辩 1.5 分钟 + 收尾」，meta 仅作彩蛋；把「答辩入口」作为差异化亮点但不占主节奏。
- **优先级**：P2（demo 编排，可后置）。

#### G-1｜排期不现实：3 人 2 周塞进「ASR 基准+内容准备+热路径编排+前端 practice+报告页+答辩导师」，答辩放 W3 直接挤压核心闭环；「答辩滑入 M3 首周不挤占唱歌主线」不成立——M3 本身已被 docs/07 Q3/Q6 判为超载。⚠️ P0
- **为什么重要/矛盾点**：docs/14 §9 W2 = 语音热路径编排+前端 practice+seed 场景，W3 = 报告页+答辩导师；docs/04 M2 已要求场景+评分报告+注册/入学/建档+完整闭环。3 人 2 周（约 30 人日）塞进内容准备（算法/组长）+ 热路径编排 + 前端 practice + report + 答辩（增量≈Python 2~3 人日+前端 1~2 人日，即约 5 人日 = 约 17% 人力）。docs/07 Q3「M3 3 人 2 周做唱歌+推荐+报表+埋点数学上不成立」、Q6 还叠加 wav2vec2 门禁；**答辩滑入 M3 首周 = 在已判超载的 M3 上再加压**，§9「不挤占唱歌主线」没有依据。

- **推荐答案**：**A**——把 M2 定义为「场景对话+评分报告+再练闭环」硬 DoD，答辩为 P1 弹性项；明确砍序：先砍答辩、再砍脚手架 L3，达成度保留（核心差异点但扣紧口径），避免 M3 超载加剧。

#### G-2｜砍哪个差异点（达成度 vs 答辩）未拍板——这是 docs/14 最大的未决项，直接决定 M2/M3 资源配置。⚠️ P0

- **候选答案**：A 保达成度、砍答辩（达成度是主线口播差异，答辩是附加）；B 保答辩、砍达成度（答辩能撑 demo 说服力）；C 保双人格+脚手架，达成度降为报告内非主线指标。
- **推荐答案**：**A**——达成度是「口语闭环」的核心差异（与主线评分报告融为一体），答辩是「附加」且差异化弱；先保主线，答辩作为 P1 弹性项。**这个排序要写成 docs/14 的显式原则**，避免开发中摇摆。

#### G-3｜「增量成本估算」只算了答辩，没算 M2 全量——文档缺一条 M2 整体工作量与 3 人配平的核对。P2
- **为什么重要/矛盾点**：docs/14 §9 只有答辩增量（Python+2~3 人日/前端+1~2 人日），没有 M2 主线（热路径+前端 practice+report+seed 内容）的总量估算与逐周配平；约 12 人日主线 + 5 人日答辩 ≈ 17 人日，接近 3 人 2 周可用人日上限，但无逐周配平表，排期风险被低估（叠加 W1 内容准备的隐性工时）。

- **推荐答案**：**A**——补一张「M2 主线人日 vs 答辩人日 vs 3 人可用人日」配平表，暴露超支与冲突点，让「砍谁」有数据支撑。
- **优先级**：P2（可与 G-1 一并处理）。

## 五、与 docs/14 的直接冲突/缺陷清单（指明段落）

1. **§6.1 defense_profiles「硬删=用户数据，无保留」vs docs/10 P7「业务表禁止物理删除」**。（F-1，最直接的 ADR 冲突）
2. **§4.4「回答质量=0.6 要点命中+0.4 结构质量，驱动自适应阶梯」vs docs/06 §9.3「LLM 只做引导与润色反馈、内容相关度不进量化总分」**。（E-4，文档口径冲突）
3. **§6.1「消息流水复用 scenario_messages…全部够用，不改表」但 §2.3/§3.3/§6.3 引入 `hint` 行动** —— docs/10 §4.3 `scenario_messages.action` CHECK 定稿为 `'demo'/'correction'/'retry' NULL`，**不含 `hint`**；且 docs/10 §4.3 说明 action/origin 语义偏「user 行功能互动」，救场类（提示/示范/代说）记到 scenario_messages 需要扩枚举或改语义。§6.1「不改表」与新增 `hint`/救场记录**自相矛盾**。
4. **§3.1 target_corpus 全档共用 + 每场景仅 2 套开场 vs docs/07 Q22/ADR 8「不同难度档进入不同开场」**。（D-2/D-3，后者要求按难度分级、前者只粗分为 2 档）
5. **§7 互动率「同上」对 defense 不成立**：§4.3 明确 user 作答 `origin='respond'`，答辩用户全程「答」而非「主动发消息」→ defense 会话**互动率恒为 0**；§7 却直接套用「主动发消息轮数/分配轮数」，defense 无定义可用的互动率，须排除或重定义。
6. **§3.5「命中=明确说出该表达（ASR 文本为准）」vs docs/06 §9.3「内容相关度不进量化分」**：二者都坚持「不混入内容分」，但 docs/14 的「命中」未要求语法/语义正确，与「内容/语言正确度」未清区分；需明确命中是否含正确性，避免「说错也命中」侵蚀达成度的教学可信度。
7. **§9 排期「答辩滑入 M3 首周，不挤占 M3 唱歌主线」vs docs/07 Q3/Q6「M3 唱歌+推荐+报表+埋点已数学上不成立」**（G-1）：M3 无余量，答辩滑入即加压，「不挤占」无依据。
8. **§6.3 `events.event_type` CHECK 扩展方式未决**（docs/14 §6.1 + §10 C-12 已列为待拷问）：与 docs/10 §4.4 「新事件类型 = 改 CHECK（迁移）+ 更新 docs/06 + 前端契约」的口径一致，但改 CHECK vs 放宽 TEXT 需在 docs/06 同步定稿，避免 schema 漂移。
9. **A-1 覆盖缺口**：docs/14 全文未覆盖 docs/04 M2 的「注册/入学测试/学习档案」与「入学测试→水平档→场景难度」衔接，M2 DoD（docs/07 Q49）无法凭 docs/14 验证。

## 六、答辩口径提示（被评委追问时怎么答）

1. **「达成度算不算口语能力？」** → 不算。它是**教学覆盖信号**（这节课的语言点你开口用了没有），不是口语能力分；口语能力仍由发音/流利度/语法综合分（`S`）衡量，与 docs/06 §9.3「内容相关度不进量化总分」一致。达成度单独展示，让学习者看到「覆盖了哪些/还剩哪些」，不是「得了几分」。
2. **「是不是词频统计？」** → 我们用了**规则（归一化+词序）+ LLM 语义等价兜底**双通道，不是简单关键词出现；并且命中要区分「说出且无致命语法错」与「说出但有语法错」，避免把「说错也命中」算成达成。
3. **「你为什么不做实时多人对练/完整社区？」** → 按 docs/07 ADR 21/22，社交定位「分享+激励」（打卡+成绩卡片+只读动态流+点赞），双人实时对练列为后续扩展；本期把成本投在评分闭环与训练价值上。
4. **「ChatGPT 也能让你贴论文让它考你。」** → 差异不在「能不能自定义」，而在**结构化**：我们提供三级题目阶梯 + 回答质量评分 + 追问答辨闭环 + 成绩报告；ChatGPT 是一问一答，没有「按答辩程度自适应出题 + 逐题评分」的训练闭环。
5. **「AI 只读摘要/大纲，能问多深？」** → 我们给每道题附**提问依据（引用摘要/大纲原文）**，保证它问得有据、可审计；「理解论文」表述为「按你提供的摘要/大纲提问，深度限此」，诚实不夸大。
6. **「你们的答辩数据安全吗？」** → 论文文本存于用户私有 profile，明示用途、可随时删除（软删+内容脱敏），提示勿传未发表内容；未在公开仓库存储任何真实用户数据（docs/06 §9.7 已登记论文数据面）。
7. **「用 VocalVerse 演练自己答辩是不是自夸？」** → 那只是**屏录彩蛋**；主演示用一份结构、深度都合格的**模拟论文**，meta 作为自嘲式收尾，能力展示不依赖自夸。
8. **「4 档难度对 L1 和 L2 有啥不同？」** → 难度差异体现在**对话节奏（TTS rate）、句长、词汇等级**（参数化）；我们按 L1/L2 与 L3/L4 两套语料+两套开场组织，demo 用跨档（L2 vs L4）放大差异观感；语料按场景主题组织（详见 docs/07 ADR 6/7「内容只按难度档组织」）。
