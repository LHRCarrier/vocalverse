## 一、最致命的 5 个问题（每句一行）

1. **「流式录音 → 实时转写 → 即时反馈」是 P0 承诺，但 faster-whisper medium 在 Windows 无 GPU 上 RTF≈1.5~3.0×，CPU 上根本做不到「实时」，而方案没给处理器选型、延迟预算或回退——P0 会在 M2 直接塌方。**
2. **「Java + Python 双后端」没有任何鉴权与职责契约：谁签发 JWT、谁来调用谁、谁来拥有数据库 schema 都没定，Java 还在语音热路径上中继 SSE，这是地基级返工风险。**
3. **wav2vec2 微调被当作「自研加分项」却无任何门禁：整模型微调 20~40h GPU + 对齐管线 + speechocean762 是周末吞掉整个 M3 时窗的黑洞，ROI 远差于「冻结 backbone 只训评分头」。**
4. **`.gitignore` 用全局后缀 `*.wav` / `*.mp3` / `*.lrc` / `*.csv` 且忽略整个 `data/` / `models/`——歌曲库 LRC 种子、行为埋点 CSV、音频测试夹具全被静默挡掉，M1 一提交就报「文件被忽略」。**
5. **Edge-TTS 是无 key、无 SLA、ToS 边界不明的非官方接口，却是唯一 TTS 方案；既无接口封装/备胎，也无「LLM 流式文本与 TTS 音频排队播放」的实现决策——Demo 当天一断即穿，且音频时间轴乱序。**

## 二、分组问题清单

### A. 仓库与目录（monorepo）

**Q1｜monorepo 一级目录到底怎么切？**
- 为什么重要：3 个服务 + 前端 + infra，横切职责含糊会让 CI/权限/文档散架。
- 候选：A. `apps/web` + `services/python` + `services/java` + `infra` + `docs`；B. `frontend` + `backend-python` + `backend-java`；C. 原子仓库。
- 推荐：**A。`apps/web`、`services/python`、`services/java`、`infra`、`docs`、`scripts`。** 理由：`apps/services` 前缀统一「应用/服务」心智，`infra` 放 nginx/compose/wsl，`scripts` 放 Windows 友好脚本。
- 影响：`README.md`、各服务路径、CI path-filter。

**Q2｜Python 与 Java 的职责边界、谁调谁？**
- 为什么重要：docx 说 Java 是「系统架构、工单管理」——这是空话；若 Java 坐在语音热路径上中继 SSE，每跳都增加延迟与复杂度。
- 候选：A. Java 作网关，前端→Java→Python（docx 字面）；B. 前端→Python（语音热路径直连），Java 只管管理端 CRUD；C. Java 全砍。
- 推荐：**B。用户侧语音流式直连 Python；Java 只做管理端（用户/场景/歌曲库/工单/看板）+ 登录发号，不进入录音/转写/评分/SSE 热路径。** Java↔Python 只在管理与配置同步时用 REST。
- 影响：`services/python/app/api/`、`services/java/…/controller/`、`docs/03`。

**Q3｜Java 能不能砍掉或砍到多薄？**
- 为什么重要：3 人 6 周，多维护一个 Spring Boot 是净负担。
- 候选：A. 完全砍掉 Java，全 FastAPI；B. 保留但只做管理端 CRUD；C. 保留且做「工单+管理+认证签发」。
- 推荐：**B+。为满足 docx「后端 Java」，保留一个「薄管理端」Spring Boot：用户管理、场景/歌曲库 CRUD、最小工单(ticket)表、评价看板；并作为 JWT 签发方。** 但**严禁**让它进入语音/流式热路径，且共用一个 DB/Alembic，Java 代码量压到 ~2k 行以内。
- 影响：`docs/02`、`docs/03`、`services/java/`。

**Q4｜内部服务间通信用 REST 还是消息队列？**
- 为什么重要：RQ 会引入运维负担，若不必要就是过度设计。
- 候选：A. 纯同步 REST；B. Redis Pub/Sub；C. 真消息队列(RabbitMQ/Kafka)。
- 推荐：**A。同步 REST + 超时(3s)。** 若将来需要异步评分结果轮询，用 Redis 存任务状态(Poll)，不上 MQ。
- 影响：`services/python`、`services/java`、`infra`。

**Q5｜内部认证：谁签发 JWT、另一方如何验签？**
- 为什么重要：这是双后端最容易烂尾的点。
- 候选：A. Java 统一签发，Python 用共享 secret 验签；B. Python 签/Java 验；C. 独立 Auth 服务；D. 内部调用用 service token。
- 推荐：**A。Java 签发 access JWT(HS256，共享 secret 于 `.env`)，前端拿到 token 后直连 Python 时在同一 JWT 上带过去，Python 用共享 secret 验签，内部 Java↔Python 不额外鉴权（同内网 + service token 头）。** 避免「每次请求先打 Java 换 token」的额外一跳。
- 影响：`services/java`(auth)、`services/python/app/api/deps.py`、`docs/api`。

### B. 语言 / 框架版本

**Q6｜Node 与 Vue3 版本？TS 还是 JS？Vite 版本？**
- 为什么重要：3 人协作 + 类型化跨服务契约，TS 收益远大于成本。
- 候选：Vue 3.x + JS vs TS；Vite 5/6/7；Node 20 LTS vs 22 LTS。
- 推荐：**Node 22 LTS（nvm-windows）+ Vue 3.5.x + TypeScript(strict) + Vite 6。** 包管理用 **pnpm**（快、节省磁盘、无 node-gyp），lockfile 用 `pnpm-lock.yaml`。
- 影响：`apps/web/package.json`、`vite.config.ts`、`.nvmrc`、CI。

**Q7｜Python 版本与包管理器？**
- 为什么重要：PyTorch/crepe 对 Python 版本敏感，包管理器直接影响 CI 可复现。
- 候选：Python 3.11 vs 3.12；pip + requirements vs poetry vs uv。
- 推荐：**Python 3.12.x + uv（`uv.lock`）。** FastAPI `>=0.115`、Pydantic `v2 (>=2.9)`、SQLAlchemy `2.0.36+`、Alembic `>=1.14`。若某依赖在 3.12 无轮子，降到 3.11 作为兜底并写死。
- 影响：`services/python/pyproject.toml`、`Dockerfile`、CI。

**Q8｜Java 版本、Spring Boot 版本、构建工具？**
- 为什么重要：Java 21 虚拟线程对并发友好，但需与 CI 内存/Windows 兼容。
- 候选：Java 17 vs 21；Spring Boot 3.2/3.3/3.4/3.5；Maven vs Gradle。
- 推荐：**Java 21(Temurin) + Spring Boot 3.3.x + Maven(带 `mvnw` wrapper)。** 理由：21 的虚拟线程提升吞吐，Boot 3.3 稳定支持；Maven 可复现且 CI 内存更好控制（Gradle 在 7GB runner 上易 OOM）。
- 影响：`services/java/pom.xml`、`Dockerfile`、CI。

**Q9｜monorepo 是否统一 lockfile/版本清单？**
- 为什么重要：三端版本漂移会让「本地能跑、CI 崩」。
- 候选：各自 lockfile vs 根 `package.json` workspaces vs 版本清单。
- 推荐：**各服务各自 lockfile（pnpm-lock / uv.lock / pom 依赖管理），根目录只放 `.tool-versions`(astral) 或 `.nvmrc` 声明 Node/Python/Java 基准，CI 与本地强制一致。** 前端不用 pnpm workspace 过度工程化（单前端）。
- 影响：根 `.tool-versions`、CI。

### C. 代码质量与规范

**Q10｜Python 静态检查/格式化工具链？**
- 为什么重要：统一规范 + CI 卡门。
- 推荐：**ruff (`>=0.6`，linter + formatter) + ruff-format；类型检查用 mypy（可选，作为 CI 不强制但本地提醒）。** 约定 `line-length=100`。
- 影响：`services/python/pyproject.toml`、`.ruff.toml`。

**Q11｜前端 ESLint/Prettier 配置？**
- 为什么重要：前后端协作、类型与格式统一。
- 推荐：**ESLint 9 flat config + typescript-eslint + prettier；用 eslint-plugin-vue + vue/tsc。** 格式统一交给 Prettier（含 HTML/CSS/TS）。
- 影响：`apps/web/eslint.config.*`、`.prettierrc`。

**Q12｜Java 格式化/静态检查工具？**
- 为什么重要：管理端虽薄，也要 CI 卡 format。
- 推荐：**Spotless(google-java-format) + Checkstyle(可选) 在 Maven `verify` 阶段执行**，而非 pre-commit（Java formatter 太重）。
- 影响：`services/java/pom.xml`。

**Q13｜pre-commit 怎么配才能在 Windows 可用（不依赖 bash-only 钩子）？**
- 为什么重要：Windows 默认无 `/bin/sh`，bash 钩子必挂。
- 候选：husky(需 Node) vs pre-commit(pip)。
- 推荐：**用 `pre-commit`（pip 安装，跨平台），钩子只用纯 Python/跨平台工具：`ruff`、`ruff-format`、`check-yaml`(针对根 + github/workflows 单独校验)、`check-json`、`end-of-file-fixer`、`trailing-whitespace`、`detect-private-key`、`conventional-pre-commit`(Conventional Commits)。** 禁用一切 `.*sh` 钩子；`.bat`/`.ps1` 不纳入 formatter。
- 影响：`.pre-commit-config.yaml`、CI 复用。

### D. CI / CD

**Q14｜各服务 PR 必跑哪些 job？**
- 为什么重要：要「绿了才合」但又不能把 M1 拖死。
- 推荐：**M1 落最小编译门（lint + build + 冒烟），M2 落全量矩阵。**
  - `frontend-ci`：node 22 → `pnpm install --frozen-lockfile` → `pnpm lint` → `pnpm typecheck` → `pnpm test`(vitest) → `pnpm build`。
  - `python-ci`：py 3.12 → `uv sync --frozen` → `ruff check` → `ruff format --check` → `pytest -m "not gpu"` → `alembic heads` 校验一致。
  - `java-ci`：temurin 21 + `mvnw -B verify`（含 spotless:check、单测、Testcontainers 可选探针）。
  - `secret-scan`：trufflehog/detect-secrets。
- 影响：`.github/workflows/*`。

**Q15｜PR 是否 build docker image？何时发布？**
- 为什么重要：PR 每跳 build 拖慢迭代。
- 推荐：**PR 只做 `docker build` 的语法/依赖完整性冒烟（`--no-push`），`push`/发布只在 main 合并后触发（tag 推送 ghcr）。** CI 不依赖任何 docker registry 凭据。
- 影响：`.github/workflows/docker-build.yml`。

**Q16｜CI 如何与「1 人 review + main 禁直推 + dismiss stale」配合？**
- 为什么重要：分支保护要求「required status checks」，否则能被绕过。
- 推荐：**在分支保护里把三条 CI 设为 required status check；CI 在 PR head 上跑，与 dismiss-stale-reviews 天然协同；PR 合并用 squash；`admins` 关闭 enforcement（仅组长可应急直推，须会话报备，与 05 一致）。**
- 影响：GitHub 分支保护设置、`.github/workflows`。

**Q17｜CI 里是否需要真实 API key？**
- 为什么重要：公开仓库、外部 PR 无法获得 secrets，且「API 变 green」会让 demo 依赖外网。
- 推荐：**CI 一律不打真实 key。** 所有模型/评审/ASR/TTS 都走 stub/fake，CI 只测管线逻辑与契约；真实凭据只在 `deploy`/`release` workflow（不进 PR）。
- 影响：`services/python/tests/conftest.py`、workflow secrets 生命周期。

**Q18｜M1 就落 CI，还是后置？**
- 为什么重要：M1 就要培养「绿了才合」习惯。
- 推荐：**M1 落 `.github/workflows/*.yml` 最小三件套（lint+build+冒烟），M2 补 test 矩阵与 docker build。** 理由：CI 是唯一能强制「别合烂代码」的机制，第一天没它，后面全是摊子。
- 影响：`.github/`、`docs/04`。

### E. 测试策略

**Q19｜音频管线如何在 CI 里打桩？**
- 为什么重要：ASR/TTS/评分不能真跑，否则 CI 慢且需 key。
- 推荐：**依赖注入 + settings 开关。** 定义 `ASRClient`/`TTSClient`/`ScorerClient` 抽象接口，`app/core/config.py` 的 `TESTING=True` 时注入 `FakeASR`/`FakeTTS`/`FakeScorer`；用 pytest `fixture` override `app.dependency_overrides`。CI 只验「管线把 stub 结果正确串联 + 评分维度齐全」，不跑模型。
- 影响：`services/python/app/audio/`、`tests/conftest.py`。

**Q20｜单测/集成/E2E 的范围与工具？**
- 为什么重要：避免「只有冒烟没断言」。
- 推荐：**Python：pytest（FastAPI TestClient + 文件 SQLite 或 `:memory:`，建表用 Alembic 或 metadata.create_all）+ pytest-mock。Java：JUnit5 + Spring Boot Test，H2 跑单测，Testcontainers(Postgres) 跑一条集成并加 `@Tag("integration")`（CI 用 profile 开关）。前端：vitest 组件/逻辑单测 + Playwright 一条登录→录音→评分冒烟（走 mock 后端）。**
- 影响：各 `tests/` 目录、`apps/web/e2e/`。

**Q21｜测试数据（音频 fixture）放哪？与 .gitignore 的冲突？**
- 为什么重要：这是当前 `.gitignore` 的实雷。
- 推荐：**放 `services/python/tests/fixtures/`（微秒级合成 WAV 或 base64 `.wav.b64`），并在 `.gitignore` 加反向例外 `!tests/fixtures/**`、`!data/seed/**`、`!**/*.lrc`。** 避免把整段录音入库，用程序生成 1s 纯音/说唱样本。
- 影响：`.gitignore`、`services/python/tests/fixtures/`。

**Q22｜后端单测是否连真数据库？**
- 为什么重要：连真库在 CI/Windows 上不稳定。
- 推荐：**Python 单测用 SQLite（`sqlite+pysqlite://`），集成用 Postgres(Testcontainers Python `testcontainers` 包)；Java 单测 H2、集成 Testcontainers。** 不 mock DB 层（保证 SQL 正确），只 mock 外部模型。
- 影响：`services/python/tests`、`services/java`。

### F. API 契约

**Q23｜统一响应结构与错误码？**
- 为什么重要：三端若各写各的，前端解析逻辑崩溃。
- 推荐：**统一 envelope：`{code:int, message:string, data:object|null}`（成功 code=0）；错误码表 `docs/api/error-codes.md`（如 40001 参数错、40101 未登录、42901 限流、50001 上游超时、50301 ASR/TTS 不可用）。** HTTP 状态码与业务 code 并存（状态码管传输错误，code 管业务语义）。
- 影响：`docs/api/error-codes.md`、Python/Java 统一响应模型与异常处理器。

**Q24｜API 文档与自动生成策略（要不要 codegen）？**
- 为什么重要：codegen 是 3 人项目的常见无底洞。
- 推荐：**不做 codegen。** Python 用 FastAPI `/openapi.json`、Java 用 springdoc-openapi 自动出 `/v3/api-docs`，CI 里各加一条「能生成 schema」的冒烟；契约真源是 `docs/api`（envelope + error-codes + 关键 endpoint 参数），前端手写 TS client + `openapi-typescript` 仅作为**只读类型参考**（不生成运行时）。
- 影响：`docs/api/`、`apps/web/src/api/`。

**Q25｜鉴权：JWT 类型、刷新策略、cookie vs header？**
- 为什么重要：public repo + XSS/CSRF 风险。
- 推荐：**access JWT 15 分钟（header `Authorization: Bearer`）+ refresh JWT 7 天（`httpOnly` + `SameSite=Lax` + `Secure` cookie，/api/auth/refresh）。** 登录发号由 Java；Python 同 secret 验签。不引入第三方 IdP。
- 影响：`services/java`(auth)、`services/python/app/api/deps.py`、前端 axios 拦截器。

**Q26｜CORS 与限流？**
- 为什么重要：public repo + 外网调用，需防滥用。
- 推荐：**CORS 白名单（Vite dev `http://localhost:5173`）。限流用 Redis：登录 5 次/分/IP、LLM/评分 30 次/用户/时、ASR/TTS 各 60 次/用户/时，返回 429 + `Retry-After`。**
- 影响：Python/Java 的 CORS/限流 middleware、Redis key 定义。

### G. 流式与音频

**Q27｜服务端→客户端用 SSE 还是 WebSocket？**
- 为什么重要：决定流式复杂度与前后端协议。
- 推荐：**SSE。** 场景是「服务端→前端单向文本/音频流」，客户端录音后上传；SSE 更简单、自动重连、走 HTTP/1.1。若将来要双向实时（对话打断/双工）再上 WebSocket——本期不做，避免为复杂度付费。
- 影响：`docs/03`、Python `StreamingResponse`、前端 `EventSource`。

**Q28｜前端录音格式、分片、时长/大小限制？**
- 为什么重要：MediaRecorder 输出 WebM/opus，服务器需 ffmpeg 转 16k WAV 给 Whisper。
- 推荐：**`audio/webm;codecs=opus`（Chrome 主选，`MediaRecorder.isTypeSupported` 回退到其他 mime）。v0 录完整段再上传（非流式分片）；单次语音 ≤60s、唱歌 ≤180s；大小上限 20MB，服务器超限返回 413。**
- 影响：`apps/web/src/audio/`、Python 上传接口校验。

**Q29｜流式识别还是「录完再传」？**
- 为什么重要：CPU whisper 流式不可靠，流式识别复杂度大。
- 推荐：**v0 用「录完再传」。** 理由：16k/48k WebM/opus 需先转码，CPU whisper 流式切片易丢帧；录完一次性转写更稳。若 M4 有余量再考虑 VAD + 分块流式（仅为「边录边出字幕」体验）。
- 影响：`docs/04`、`services/python/app/audio/asr.py`。

**Q30｜LLM 流式文本 与 TTS 音频的「排队播放」怎么实现？**
- 为什么重要：两者节奏不同步会导致字幕与语音错位。
- 推荐：**以音频为时间轴权威，文本降级为字幕。** 后端把 LLM 按句切分 → 每句 TTS → 以 SSE 事件流推 `{type:"text_delta",text}` 与 `{type:"audio_chunk",url/base64}`；前端用一个队列依次播放音频，字幕跟随当前音频段。文本与音频不强制实时对齐（音频先到先播，字幕略滞后），避免「断句处被切掉」。用 `audio` `buffered`/`preload=auto` 防卡顿。
- 影响：`services/python/app/agent/streamer.py`、前端 `useAudioQueue`。

**Q31｜音频存储：本地卷 vs MinIO（demo 阶段）？**
- 为什么重要：过度引入 MinIO 会增加 compose/权限复杂度。
- 推荐：**demo 用 Docker 卷挂载 `./data/audio`(本地)。** 多容器共享该卷即可；MinIO 仅在「要演示对象存储/并发」时再引入，否则不加。生产走 MinIO/S3 留接口抽象即可。
- 影响：`docker-compose.yml`、Python `audio_storage.py`。

### H. 模型与延迟

**Q32｜faster-whisper 在无 GPU 上的 RTF 与端到端延迟预算？**
- 为什么重要：这是「实时反馈」承诺是否成立的关键数字。
- 推荐：**默认 `faster-whisper small, compute_type=int8, device=cpu`（VAD 用 Silero 滤静音）。** 参考：modern 8 核 CPU 上 small-int8 RTF≈0.3~0.6，medium-int8≈1.5~3.0（medium 在 CPU 上不可作实时）。**端到端预算：上传 2~4s + ASR≈2s + 评分≈1s + LLM 首 token 1~2s + TTS 1~2s ≈ 7~10s 出第一声**——把 Demo 话术从「实时」改成「录音后 3~5 秒内反馈」，否则必被答辩追问打脸。medium 仅作离线 batch / 有 GPU 时用。
- 影响：`services/python/app/audio/asr.py`、`docs/03`。

**Q33｜Edge-TTS 的可用性/授权风险与备胎？**
- 为什么重要：无 key 非官方接口，MS 随时可能限流或改协议。
- 推荐：**封装成 `TTSClient` 接口，默认 `edge-tts`，`AZURE_TTS_KEY` 存在时切 Azure（或火山）。** CI 不调用真实 TTS。明确标注 ToS 边界与「Demo 保底 = 预生成离线 mp3 素材」。
- 影响：`services/python/app/audio/tts.py`、`.env.example`、`docs/03`。

**Q34｜讯飞评测 API 的免费额度与流式/批量模式？**
- 为什么重要：讯飞 ISE 有 QPS/并发限制且需特定音频格式。
- 推荐：**用讯飞 ISE(语音评测),支持"音素/整句/流利度/完整度"。** 仅跑基线、限并发 2（用 Redis 信号量），音频先转 16k wav/mp3；**把 wav2vec2 作为可选替换而非依赖**。若免费档 QPS 过低，可降级为「整句批量」（录完再评），不做逐字流式。
- 影响：`services/python/app/audio/scorer.py`、配置。

**Q35｜pyin 与 crepe 在唱歌/说话上的参数差异？**
- 为什么重要：唱歌音域远超说话，参数不匹配会评分失真。
- 推荐：**基线用 librosa `pyin`（CPU 快、无 TF），fmin/fmax 说话=75~300Hz，唱歌=65~800Hz；frame_length 2048、hop_length 512。** crepe 备选（更准但拉入 TensorFlow，见 Q44）。唱歌评分建议再叠加能量/清浊音门限避免静音被当 0 音高。
- 影响：`services/python/app/audio/pitch.py`、`docs/03`。

**Q36｜DTW 对 tempo 变化的鲁棒性处理？**
- 为什么重要：用户唱速不同，音准/节奏得分会失真。
- 推荐：**DTW 用 Sakoe-Chiba window（≈序列长度 10%）+ 局部斜率约束；先对参考与演唱的 F0 轮廓做归一化（去掉整体音高偏移），节奏维度用 onset/beat 与 LRC 时间戳的**相对**偏差而非绝对 DTW 时距。** 用子序列 DTW 允许用户从任意句开始。
- 影响：`services/python/app/audio/sing.py`。

### I. 数据库

**Q37｜核心表草案与字段归属？**
- 为什么重要：字段归属错位会让双后端整天改 schema。
- 推荐：**统一 PostgreSQL，Alembic 是唯一 schema 真源。** 表：`users`、`user_profiles`(cefr_level, learning_goal, tags, avatar_url)、`placements`(测试结果)、`scenarios`(title, scene_type, difficulty, system_prompt, tags)、`scenario_messages`(session 会话)、`sessions`(对话/练习会话头)、`attempts`(口语练习尝试：audio_url, transcript, overall_score, pronunciation/fluency/completeness jsonb, created_at)、`scores`(各维度细分，含音素级)、`songs`(title, artist, level, audio_url, lrc_url)、`lrc`(song_id, offset_ms, text, seq)、`sing_attempts`(逐句音准/节奏/发音分)、`events`(埋点：user_id, event_type, payload jsonb, created_at)、`reports`(聚合报表)、`tickets`(工单，满足 docx)、`refresh_tokens`(可选)。
- 影响：`services/python/alembic/versions/`、Java JPA 映射。

**Q38｜迁移工具：Alembic 统一管还是 Java+Python 各自管？**
- 为什么重要：两套迁移器必然 drift。
- 推荐：**Alembic 统一管整个 schema。** Java 用 JPA `ddl-auto=none`（只映射，不建表），Java 不做任何 DDL；CI 加「Java 实体与数据库 schema 一致性」冒烟（或至少 `validate` 探针）。
- 影响：`services/python/alembic/`、`services/java`（application.yml）。

**Q39｜Redis 用途清单？**
- 为什么重要：Redis 是"可选"却在多处被引到，需明确化。
- 推荐：**会话(LLM 多轮上下文，`session:{id}` TTL 30min)、缓存(scenario/song 列表、推荐结果 TTL 5min)、限流计数(INCR+EXPIRE)、SSE 缓冲/广播(可选)、评分任务状态(Poll)、认证黑名单(可选)。** 不存业务主数据。
- 影响：`services/python/app/core/cache.py`、`docker-compose.yml`。

### L. 对 docs/02 与 docs/03 的**反对意见**（逐条）

### M. Windows 开发环境坑

**Q53｜ffmpeg / 音频转码。**
- 为什么重要：WebM/opus → 16k WAV 是必做转码，Windows 原生无 ffmpeg。
- 推荐：**用镜像自带 ffmpeg 的 python 镜像（`python:3.12-slim` + `apt-get install ffmpeg`）或 `imageio-ffmpeg` 自带二进制；CI 用 container 跑，本地用 `winget install ffmpeg` 或 `choco`，并给 dev.ps1 加检测。** 不要手写路径。
- 影响：`services/python/Dockerfile`、`scripts/dev.ps1`。

**Q54｜pyav / sounddevice 要不要？**
- 为什么重要：`sounddevice` 依赖 PortAudio DLL，服务端根本不需要（录音在浏览器端）；`av` 若不需要就别引。
- 推荐：**服务端不装 sounddevice（只在浏览器端录音）；只读音频用 `ffmpeg`/`soundfile`；不用 `pyav` 除非高级解码。** 避免 PortAudio/动态库坑。
- 影响：`pyproject.toml`。

**Q55｜torch/torchvision 轮子太大（含 CUDA）。**
- 为什么重要：CI/本地拉 CUDA 版本会超时且白占几个 G。
- 推荐：**只装 CPU 版 `torch`（`pip install torch --index-url https://download.pytorch.org/whl/cpu`，或 `uv` 配 `--index`），不装 torchvision；wav2vec2 CPU 推理用小一点的 `facebook/wav2vec2-base`。** 训练在云 GPU 独立环境，与本地解耦。
- 影响：`pyproject.toml`、CI。

**Q56｜crepe 依赖（TensorFlow）。**
- 为什么重要：TF 在 py3.12 兼容性差、体积大，且和 torch 共存易冲突。
- 推荐：**基线不引 crepe（用 pyin）。** 若要 crepe，隔离在独立 venv + `requirements-crepe.txt`，主 pyproject 不引 TF。
- 影响：`pyproject.toml`、`services/python`。

**Q57｜node-gyp 与原生依赖。**
- 为什么重要：某些 npm 包触发 node-gyp 需 Visual Studio Build Tools。
- 推荐：**前端全部纯 JS/TS，不引入需要原生编译的依赖；避开 `sharp`/`node-sass` 等，若必须用 `@vitejs/plugin-vue`(纯 JS)。** 需要时提示安装 VS Build Tools + Python。
- 影响：`apps/web/package.json`。

**Q58｜Java 在 CI 跑测试的内存。**
- 为什么重要：GitHub Actions `windows/ubuntu-latest` 约 7GB，Spring context 加载 + JVM 易 OOM。
- 推荐：**Maven 设 `MAVEN_OPTS=-Xmx1024m`、surefire forkCount=1 `-Xmx512m`、关 Gradle daemon（若用 Gradle 则 `--no-daemon`）。** Testcontainers 只跑一条集成，用 `@Tag("integration")` 默认跳过，CI 单独提。
- 影响：`services/java/pom.xml`、CI。

**Q59｜Docker Desktop 资源（WSL2 内存）。**
- 为什么重要：默认 WSL2 可能只 2GB，跑 PG+Redis+双 JVM+Python 直接卡死。
- 推荐：**`.wslconfig` 设 memory=8GB、processors=4；compose 给 JVM 加 `-Xmx512m~1g`、Python 限资源；关 GUI 后台省内存。** dev 热重载用 venv 跑 Python 而非容器，大幅省内存。
- 影响：`infra/dev/.wslconfig`、`docker-compose.yml`、`docs/04`。

**Q60｜字符集 / 行长 / LF。**
- 为什么重要：Windows 换行 + git autocrlf 会污染 diff。
- 推荐：**沿用 `.gitattributes`（已对 py/ts/vue/java/json/yml 设 `eol=lf`，`.bat/.ps1` 用 crlf）已达标；但补 `.editorconfig`(indent=2 前端 /4 后端) + `git config core.longpaths true` + `core.autocrlf input`。**
- 影响：`.editorconfig`、`.gitattributes`、`scripts/`。

- AD-27｜TTS：`TTSClient` 接口，默认 edge-tts，`AZURE_TTS_KEY` 存在切 Azure；CI 不调真 TTS，保底预生成离线 mp3。
- AD-28｜"排队播放"：以音频为时间轴权威、文本作字幕；按句切分→按句 TTS→SSE 推 text_delta + audio_chunk，前端队列顺序播放（audio preload=auto）。
- AD-29｜音频存储：demo 用本地卷 `./data/audio`（多容器共享）；抽象 S3 接口，MinIO 可选不加。
- AD-30｜发音评分基线：讯飞 ISE（16k wav/mp3）+ Redis 并发信号量(2) + 整句批量；wav2vec2 作可选替换。
- AD-31｜self 加分项降险：冻结 wav2vec2 backbone 只训评分头（GPU 5~10h），硬门禁：M3 P0/P1 全绿才做，绝不阻塞答辩。
- AD-32｜F0：librosa `pyin`（fmin/fmax：说话 75~300，唱歌 65~800；强清浊门限）；crepe 仅隔离可选、不引 TF。
- AD-33｜DTW：Sakoe-Chiba window(≤10%) + 局部斜率约束 + 音高归一化 + 子序列 DTW + 相对节奏偏差（用 onset/beat 与 LRC）。
- AD-34｜数据库：Alembic 统一管 schema；Java JPA `ddl-auto=none`（只映射不建表）；CI 加一致性探针。
- AD-35｜表清单：users/user_profiles/placements/scenarios/scenario_messages/sessions/attempts/scores/songs/lrc/sing_attempts/events/reports/tickets/refresh_tokens。
- AD-36｜Redis：会话(30min)/缓存(5min)/限流计数/评分任务状态/SSE 缓冲(可选)；不存主数据。
- AD-37｜配置：根 `.env`(gitignored)+各服务 `.env.example`；Pydantic Settings 读 `APP_` 前缀；compose `env_file`。
- AD-38｜安全：GitHub Secrets 仅 deploy/release 用；trufflehog CI + detect-private-key pre-commit；demo 全用合成音频、录音默认不持久化、转写文本不涉 PII。
- AD-39｜可观测：loguru/logback JSON + `X-Request-Id`；`/healthz`+`/readyz`(Python)、`/actuator/health`(Java)；compose `depends_on: service_healthy`。
- AD-40｜启动与端口：`scripts/dev.ps1`(幂等，含护栏)+`docker compose up -d`；本地热重载 Python 用 venv；端口 5173/80/8000/8080/5432/6379。
