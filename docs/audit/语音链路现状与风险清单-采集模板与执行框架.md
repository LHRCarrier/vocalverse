# 《语音链路现状与风险清单》采集模板与执行框架

> 文档版本：v1.0 ｜ 适用范围：ASR / TTS / ISE 全链路健康审计
> 维护方：语音平台组 ｜ 本文件为**新增审计产物**，不修改任何现有代码与文档。

---

## 0. 文档说明

### 0.1 目标

用同一套口径，对语音链路的三大组件（ASR 识别 / TTS 合成 / ISE 评测）完成「可用性、密钥、模型」三个维度的全量盘点，产出可回溯、可复盘的**盘点台账**与**风险清单**，并给出整改闭环的推进节奏。

### 0.2 使用方式

1. 先通读第 2 章「检查项定义明细」，确认阈值口径（基准值可按业务调整，调整须在第 4 章台账备注中注明理由）。
2. 复制第 4 章「空白盘点台账」，逐项填入实测数据。
3. 按第 3 章「执行框架」五阶段推进，配套脚本见《语音链路审计-自动化测试脚本思路》。
4. 每次审计留档一份台账快照，用于趋势对比（建议按 `YYYYMMDD` 归档）。

### 0.3 术语表

| 术语 | 含义 |
| --- | --- |
| WER | 词错误率 =（替换+删除+插入）/ 参考词数；中文场景建议改用 CER（字符错误率） |
| CER | 字符错误率，中文识别质量的主口径 |
| RTF | 实时率 = 处理耗时 / 音频时长；RTF < 1 表示快于实时 |
| TTFT | 首包时延（流式首帧 / 首 token 返回耗时） |
| MOS | 主观平均意见分（1–5 分制） |
| P50 / P95 / P99 | 时延分位数 |
| 黄金语料 | 已标注参考答案的固定评测集，用于 WER / 评分一致性回归 |
| manifest | 模型发布清单（路径 → 版本、MD5、发布时间、兼容 API 版本） |

## 1. 审计模型

### 1.1 组件 × 维度检查矩阵

| 组件 | 可用性（A） | 密钥（K） | 模型（M） |
| --- | --- | --- | --- |
| **ASR 识别** | A01 可用性 / A02 时延 / A03 并发 / A04 WER·CER / A05 RTF | K01 有效期 / K02 权限 / K03 存储与轮换 | M01 MD5 / M02 版本 / M03 存储容灾 |
| **TTS 合成** | A01 可用性 / A02 时延 / A03 并发 / A04 合成质量 / A05 合成 RTF | K01 有效期 / K02 权限 / K03 存储与轮换 | M01 MD5 / M02 版本 / M03 存储容灾 |
| **ISE 评测** | A01 可用性 / A02 时延 / A03 并发 / A04 评分一致性 / A05 评测 RTF | K01 有效期 / K02 权限 / K03 存储与轮换 | M01 MD5 / M02 评分策略版本 / M03 存储容灾 |
| **通用横切（C）** | C01 日志告警 / C02 数据合规 / C03 容灾降级 / C04 容量配额 / C05 供应商 SLA | — | — |

共 **38 个检查项**：ASR 11 + TTS 11 + ISE 11 + 通用 5。

### 1.2 编号规则

`<组件>-<维度><两位序号>`，例如 `ASR-A04`、`TTS-K01`、`ISE-M03`；通用项以 `C-` 开头。

### 1.3 状态与风险分级

**采集状态（4 态）**

| 状态 | 含义 |
| --- | --- |
| ✅ 通过 | 实测值满足阈值，无风险 |
| ⚠️ 告警 | 实测值逼近阈值（≥ 阈值 80%），未触红线，需关注 |
| 🔴 风险 | 实测值不满足阈值 / 触红线，需整改 |
| ⬜ 未采集 | 本期未覆盖（注明原因与补采计划） |

**风险等级（4 级）**

| 等级 | 定义 | 处置时限 |
| --- | --- | --- |
| P0 致命 | 密钥泄露、模型损坏、服务不可用等直接事故 | 立即处置 / 停用 |
| P1 高 | 红线指标不达标，存在近期事故风险 | 24–72 小时 |
| P2 中 | 阈值不达标但可控，或存在隐患 | 1–2 周 |
| P3 低 | 建议项 / 优化项 | 计划内 |

> 阈值均为**默认基准**（近场普通话、内网调用、商用级服务），各团队须评审确认；采集方式说明「自动」指可由配套脚本执行，「人工」指需人工确认/抽样。

## 3. 执行框架

### 3.1 角色与职责

| 角色 | 职责 |
| --- | --- |
| 审计负责人 | 统筹排期、统一口径、评级、出具报告 |
| 组件负责人 ×3 | ASR / TTS / ISE 各自提供数据、确认阈值、认领整改 |
| 安全与合规 | 密钥、数据安全、合规项 |
| 运维 / SRE | 监控、容量、容灾、模型存储 |

### 3.2 五阶段执行流程

| 阶段 | 输入 | 关键活动 | 输出 | 参与人 | 建议时限 |
| --- | --- | --- | --- | --- | --- |
| 0 准备 | 上期台账、架构图 | 确定范围与环境（预发/生产）、责任人；确认黄金语料与阈值；脚本与环境就绪 | 审计计划、基线 | 审计负责人 + 全员 | 2 天 |
| 1 静态盘点 | 配置、权限、部署清单 | 密钥有效期/权限/存储、模型版本/路径/manifest 一次摸底（人工+脚本） | 静态盘点表 | 组件负责人 + 安全 | 2 天 |
| 2 自动化巡检 | 脚本、黄金语料 | 跑可用性/时延/并发/WER/RTF/MD5/磁盘等自动项，输出 JSON | 巡检数据 | 运维 + 组件负责人 | 1 天 |
| 3 业务验证 | 巡检数据 | 真实流量抽样、MOS 试听、评分一致性复核、容灾演练 | 验证记录 | 组件负责人 | 2 天 |
| 4 汇总评级 | 各阶段数据 | 回填台账、判定状态与风险等级、出具风险清单与报告 | 台账 + 风险清单 + 报告 | 审计负责人 | 1 天 |
| 5 整改闭环 | 风险清单 | 派发整改工单、设定时限、复查与回归、归档快照 | 工单 + 复查记录 | 组件负责人 + 审计负责人 | 按等级 |

### 3.3 巡检节奏

| 频率 | 范围 | 产物 |
| --- | --- | --- |
| 每日 | 健康检查、错误率、密钥剩余天数预警、磁盘水位 | 自动日报 |
| 每周 | 时延/并发基准回归、MD5 抽查、容量趋势 | 周报 |
| 每月 | WER/CER、合成质量、评分一致性回归 + 台账更新 | 月报 |
| 每季度 | 全量审计（38 项）、权限复查、密钥轮换确认、容灾演练 | 全量台账 + 风险清单 |

### 3.4 红线速查表（P0/P1 判定）

| 红线 | 判定 | 处置 |
| --- | --- | --- |
| 密钥明文出现在仓库/日志/配置文件 | 命中即 P0 | 立即吊销并轮换，全员排查泄露面 |
| 模型文件 MD5 与 manifest 不一致 | 命中即 P0 | 停止加载该模型，回滚上一版本 |
| 密钥已过期或 ≤ 7 天到期 | P0 / P1 | 立即轮换 / 加急轮换 |
| WER/CER 相对基线劣化 ≥ +1pt 且无变更记录 | P1 | 定位变更，回滚或修复 |
| 磁盘水位 ≥ 90% | P1 | 扩容或清理，4 小时内处理 |
| 容灾演练超过 12 个月未执行 | P2 | 排期演练 |

### 3.5 审计产物清单

- 盘点台账（本模板第 4 章，按 `YYYYMMDD` 归档）
- 风险清单（含整改工单与责任人）
- 审计报告（结论摘要 + 趋势对比 + 整改建议）
- 巡检数据快照（JSON / CSV，供趋势分析）

## 4. 空白盘点台账

> 使用说明：
> - 复制下方表格到审计文档，逐行填写「实测值 / 状态 / 风险等级 / 责任方 / 采集时间 / 证据与备注」。
> - 「期望值」来自第 2 章默认基准；若调整，在备注注明理由并留痕。
> - 状态取值：通过 / 告警 / 风险 / 未采集；风险等级取值：P0 / P1 / P2 / P3 / 无。
> - 采集时间格式：`YYYY-MM-DD`；证据列建议写日志路径、命令输出、报告链接。
> - 每次审计必须保留一份归档快照，不允许原地覆盖。

## 5. 附录：常用数据来源命令速查

### 5.1 可用性 / 时延

```bash
# 健康检查 + 总耗时（单次）
curl -s -o /dev/null -w "http_code=%{http_code} total=%{time_total}s\n" https://asr.internal.example/healthz

# 多轮时延抽样（P50/P95/P99 由脚本汇总）
for i in $(seq 1 100); do curl -s -o /dev/null -w "%{time_total}\n" https://asr.internal.example/v1/recognize; done > latencies.txt
```

### 5.2 模型文件

```bash
# Linux
md5sum model.bin
# Windows（审计机为 Windows 时）
certutil -hashfile model.bin MD5

# 磁盘与目录
df -h <model_dir>
du -sh <model_dir>
stat -c '%a %U %G %n' <model_dir>/model.bin
find <model_dir> -type f -perm -002 -print   # group/other 可写 = 权限风险
```

### 5.3 密钥

```bash
# 证书有效期
openssl x509 -enddate -noout -in /path/cert.pem

# 云平台 Key 列表（示例）
aliyun ram ListAccessKeys --UserName svc-asr-prod    # 阿里云
aws iam list-access-keys --user-name svc-asr-prod    # AWS

# 仓库硬编码扫描
gitleaks detect --source . --log-opts="--all" --report-format json --report-path gitleaks.json
git log --all -p -S "AKIA" --oneline | head -50
```

### 5.4 监控数据（Prometheus 示例）

```bash
curl -s 'http://prometheus.internal:9090/api/v1/query' --data-urlencode 'query=sum(rate(http_requests_total{job="asr"}[5m]))'
```
