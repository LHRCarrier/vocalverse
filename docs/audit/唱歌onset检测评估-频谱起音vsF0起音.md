> 性质：**音频链路评估报告**（docs/audit 模块）· 2026-09-10 · 执行人：AI 代签（正式署名待组长确认）

> 可能检出不足，建议评估 F0 起音兜底"。

## 1. 背景与问题

评分口径 v3 的 `bpm_ratio`（item7）依赖**两侧同量纲的音符级 onset**：参考侧 = 提取期入库的
`pitch_ref.onsets_ms`（pyin-v2），用户侧 = `librosa.onset_detect`（频谱通量 + 峰值拾取）。

假设是"F0 缺失场景（柔起音/连唱）会导致用户侧检出不足"。**实测推翻了该假设的一半**：

## 2. 实测数据（合成素材，12 音符、真值 120 BPM，±60ms 容差匹配）

| 素材形态 | 频谱起音：检出/P/R/F1 | F0 起音：检出/P/R/F1 | BPM 误差（频谱 → F0 → 组合） |
|---|---|---|---|
| 断奏（80ms 停顿） | 39 / 0.31 / 1.00 / 0.47 | 12 / 0.92 / 0.92 / **0.92** | 67.5 → 2.8 → **2.8** |
| 连奏（无停顿） | 22 / 0.50 / 0.92 / 0.65 | 10 / 0.90 / 0.75 / **0.82** | 2.8 → 2.8 → **2.8** |
| 柔起音 300ms | 22 / 0.09 / 0.17 / 0.12 | 12 / 0.92 / 0.92 / **0.92** | 5.0 → 2.8 → **2.8** |
| 连奏 + 柔起音 | 36 / 0.31 / 0.92 / 0.46 | 13 / 0.85 / 0.92 / **0.88** | 67.5 → 2.8 → **2.8** |
| 断奏 + 噪声 SNR≈10dB | 46 / 0.17 / 0.67 / 0.28 | 13 / 0.85 / 0.92 / **0.88** | 43.0 → 2.8 → **2.8** |
| **同音重复（la×12）** | 43 / 0.28 / 1.00 / 0.44 | **1 / 1.00 / 0.08 / 0.15** | 88.3 → **None** → **15.8** |
| 相位声码器处理（非真实场景） | 47 / 0.11 / 0.42 / 0.17 | 11 / 0.27 / 0.25 / 0.26 | 88.3 → 12.9 → 12.9 |
| **平均 BPM 误差** | **51.8** | 4.8（含 None） | **6.1（无 None）** |

真实录音（6 段，无 ground truth，仅形态核对）：频谱起音检出 39~151 个（对 6 句歌明显过多），
F0 起音 42~86 个；BPM——频谱 110~170（离散大）、F0 与组合 125~144（落合理区间）。

## 3. 三个反直觉结论

1. **现状的病根不是"检出不足"，而是精度太低**：12 个真值音符被检出 22~47 个（P=0.09~0.50）。
   BPM 之所以"看起来还行"，靠的是 IOI **中位数的抗噪**，而非检测准确——一旦假点聚集偏向短间隔，
   就会出**倍速事故**（断奏 187.5 / 同音重复 208.3，真值 120）。
2. **F0 起音不能替代频谱起音**：它在换音明显的 5 类形态上显著更好（F1 0.73 vs 0.36、BPM 误差 2.8），
   但**同音重复是硬盲区**（音高不变 → 无跳变 → 全漏 → BPM None）——而"la la la"型重复是儿歌/流行歌常态。
3. **融合的层次很关键**：onset 列表 union（fuse）实测**最差**（平均误差 48，假点互相污染）；
   交集（intersect）在高置信场景好，但依赖频谱命中（柔起音时频谱全灭 → 崩）。
   唯一稳健的做法是**在 BPM 层仲裁**，并引入"八度校正"与"时长比粗估"作参照。

## 4. 采纳方案（已实施）

```
用户侧两路 onset：频谱起音（onsets_ms）+ F0 起音（f0_onsets_ms）
        ↓ bpm_from_onsets 各自出 BPM
combine_bpm(b_flux, b_f0, approx_bpm)：
  ① 都不可用 → None（回落时长比，诚实降级）
  ② 仅一路可用 → 该路 + 八度校正（bpm×2^k 中取与 approx 最接近、且 ∈[40,240]）
  ③ 两路可用且比值 ∈[1.5,2.3]（八度分歧）→ 取与 approx 更近者
  ④ 其余 → F0 路（假起音显著更少）
approx_bpm = 参考 BPM × (参考时长 / 用户时长)   # 粗估：足以区分半速/倍速
```

- 实现：`app/audio/pitch.py:f0_onsets_ms`（纯函数：音高跳变 + 有声段起点 + 跨短静音桥接 ≈96ms、
  跳变阈值 60 cent、去抖 120ms）、`app/audio/sing.py:combine_bpm`；
- 实测收益：**平均 BPM 误差 51.8 → 6.1**，且不再出现 None；最差真实场景（同音重复）88.3 → 15.8；
- `bpm_source` 值域：`onset-f0` / `onset-flux` / `onset-arbitrated` / `duration`（可追溯用了哪条路）。

## 5. 风险控制（必须与 BUG-4 一起看）

`bpm_ratio` 在 BUG-4 修复后**参与句窗口缩放**——若八度仲裁判错，窗口会被成倍拉长/缩短 → 音准被拉歪。
故 `sing.py:window_scale` 对参与缩放的 ratio **clamp 到 [0.67, 1.5]**（超出按边界值，等价于"最多按 1.5 倍
伸缩窗口"）；`combine_bpm` 的八度校正也已限制在 [40, 240] BPM 合理域。

## 6. 已知边界（未覆盖，留待真机数据）

- 评估素材是**合成音色**（谐波叠加 + 包络），不含真人的滑音/装饰音/颤音尾；真实录音只做了形态核对
  （无 ground truth），故"F1 0.73"应理解为"合成条件下的下界参考"；
- 相位声码器抹平瞬态的场景（F1 0.26）**不是评分链路的真实输入**（用户上传 → ffmpeg 转码不走声码器），
  仅作极端参考；
- 参数（跳变 60 cent / 桥接 96ms / 去抖 120ms）由本批素材标定，**真机抽检（SG-14）后应复核**。
