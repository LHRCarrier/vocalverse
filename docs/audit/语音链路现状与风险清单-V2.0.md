## 1. 执行摘要

### 1.1 总体结论

> **一句话结论：语音管线当前处于「演示级可用、上线级不可用」状态——核心卖点（ISE 真实评分）从未跑通、全站评分为硬编码假分；部署配置存在未提交的致命损坏；默认密钥公知且两端失配可伪造任意令牌；健康检查首轮 0/4 采集使可观测性近乎为零。**

### 1.2 综合健康度评分

评分模型：38 检查项四维加权（可用性 40% / 密钥 25% / 模型 25% / 通用 10%），未采集计 0；V2.0 结合代码实证对可判项重新评估。

| 维度 | 权重 | 说明 | 维度得分 |
| --- | --- | --- | --- |
| 可用性 | 40% | RTF 实测达标但并发护栏缺失、首声预算不成立、真实 ISE 未跑通 | 25% |
| 密钥 | 25% | 无真密钥入库（正面），但默认密钥公知失配、demo 密钥全缺 | 35% |
| 模型 | 25% | 无 MD5 清单、License 未决、供应链治理缺失 | 20% |

### 1.3 Top 3 致命风险

| 排名 | 风险编号 | 风险 | 等级 | 一句话影响 |
| --- | --- | --- | --- | --- |

### 1.4 关键结论要点

- **ISE 是最大黑洞**：密钥三件套全空 → 恒走 FakeScorerClient 假分；且评分路径无 ffmpeg 转码（WebM/opus 原字节直发讯飞），真密钥接入后预期持续报错（R-01/R-13/R-19）。
- **部署不可复现**：migrate 命令损坏未提交、DB 密码三处漂移、/readyz 空壳、whisper 500MB 冷加载超健康检查窗口（R-02/R-11）。
- **安全失守面广**：报告越权可拖走全站转写、裸端点无鉴权无限流、音频鉴权下 401 无声、宿主端口全开+Redis 无密码（R-05/R-06/R-07/R-16）。
- **性能承诺未兑现**：并发信号量 2 零实现、会话内存态、SSE 无心跳、首声 3~6s 预算推算 6.1~7.6s（R-04/R-10/R-12/R-18）。
- **质量与合规无基线**：WER/Spearman 未采集、BGM 场景 VAD 未启用、模型 MD5/License 治理缺失（R-08/R-09/R-14/R-15）。
- **正面项（保留）**：全仓无真密钥入库、secret-scan CI 真实生效（SEC-09/CI-10 复核通过）、uv.lock 全量 sha256 锁定、RTF/TTS 延迟具备实测文化（POC-1/POC-3）。

## 4. 指定风险根因分析（更新版）

### 4.1 模型文件缺失 License（R-15）

分层根因（在 V1.0 基础上补充子代理实证）：

1. **引入环节无 License 关卡**——无 license-check CI、模型 manifest 无 license 字段（实证：全仓无 License 扫描配置）。
2. **许可认定自相矛盾**——speechocean762 在 docs/06:220 记为 CC-BY，而审计口径记为学术用途，**同一数据集两种认定并存**，说明从未做外部核实（[D] 对抗复核确认矛盾存在）。
3. **许可证类型混用**——faster-whisper(MIT)、transformers(Apache-2.0)、edge-tts(**GPL-3.0**，pyproject.toml:21)、speechocean762（学术/CC-BY 未决）。
4. **音色权益缺口**——edge-tts 封装微软非官方服务，除 GPL 外叠加服务条款争议；Azure 备胎已配置但零分支，无授权评审。

**建议**：外部核实 speechocean762 许可并统一 docs 口径；edge-tts 法律评审或换商用授权 TTS（Azure 分支接线）；manifest 增 license 字段；License 扫描入 CI。

### 4.2 ASR 背景音乐场景 WER 劣化（R-09）

分层根因（新增实证）：

1. **VAD 承诺未落地**——docs/06:116 声明 Silero VAD，但 `asr.py:45` 无 `vad_filter`，全仓 grep 无 VAD 实现（[D] 对抗复核确认）。
2. **训练-生产分布偏移**——whisper small 通用模型未针对 BGM/跟唱微调，无增强语料。
3. **评测口径缺失**——WER 基线从未建立（R-08），BGM 分档黄金语料不存在，劣化无量化手段。
4. **声学掩蔽 + 无前端分离**——无音乐/人声分离、无自适应 VAD 分场景参数。

**建议**：启用 vad_filter 并采集带 BGM 样本实测 WER 基线；建 BGM 分档黄金语料；强 BGM 时降级提示「环境嘈杂」。

### 4.3 ISE 假分链路（R-01，V2.0 新增核心发现）

根因链：

1. **密钥缺失**——三件套全空（.env 实测 `<EMPTY>`），配置即 Fake。
2. **Fake 门禁设计缺陷**——base.py:125-128 缺 key 即走 FakeScorerClient，且 Fake 门禁仅校验 app_id+api_key，api_secret 为空仍构造 ISEClient 参与签名。
3. **假分恒定值**——Fake 返回 88/90/86/85 硬编码分，与「不伪造分数」契约（docs/10 §4.3）**直接冲突**。
4. **转码链路缺陷叠加**——即使填真密钥，无 ffmpeg 转码（R-13）仍会持续报错。

**建议**：填真实密钥端到端跑通并记录实测；无钥时明示 Fake 口径而非假分；评分路径补 ffmpeg 转 16k wav；修 Fake 门禁校验逻辑。

### 4.4 密钥失配与公知（R-03）

根因链：

1. **默认值入库**——config.py:31-33 与 application.yml:24-26 硬编码默认 JWT/service-token。
2. **两端失配**——Java 签发 / Python 验签的共享 secret 在两端 .env 不一致（.env:10 与 :15 失配），验签必败（worklog:168 实测 401）。
3. **compose 不注入**——容器环境不注入密钥，运行时回退默认值，公知密钥生效。

**建议**：重建随机密钥；统一两端默认值；compose 强制注入并 fail-fast（无密钥拒绝启动）。
