### 1.3 设计系统现状（docs/13 已拍板，与市场主流方向一致）

- **色彩**：绿主色 `#16A34A` + 柠檬黄 `#FACC15` 激励 + 橙 `#FB923C` 评分——**这正是 Duolingo 类型的"活力游戏化"配色逻辑**（绿=进步、黄=奖励、橙=分数），且 docs/13 明确引用多邻国为方向基准；
- **字体**：Nunito（圆润无衬线，多邻国系），断网回退系统栈；
- **圆角/间距**：8/12/胶囊 999，4 基元间距，内容宽 1080——与 Duolingo 的"圆润卡片 + 大圆角按钮"语言一致；
- **可视化栈**：ECharts 报表 + P5 仅品牌动效 + D3 唱歌细图 + **不引入 Three.js**（2D 拍板）；
- **浅色单主题**，深色为扩展。

**分析：** docs/13 的方向选择本身就是对市场的正确判断（详见 §2.2 Duolingo 佐证）。重构时**不需要推翻视觉品牌**，需要的是：① 把该语言贯彻到每一个页面（当前实现大量 `text-xs` 红字条、裸 `<NCard>`、硬编码 hex `#667085` 散落模板 = 语言执行打折）；② 补无障碍（全站 0 个 `aria-`）；③ 补空态/引导态（docs/13 §8 验收表尚未达标）。

### 1.4 体验现状（docs/19-M2 UX 拷问的 9 个 P0——重构的真正主战场）

> 一句话：**这个 MVP 的"教学设计"超过绝大多数学生项目，但"人机交互"停留在能跑通的水平。**（docs/19-M2 结论）

| # | P0 问题 | 用户感受 |
|---|---|---|
| P0-1 | 「停止录音」是假按钮，每轮被强制占用 15 秒（8 轮 = 2 分钟尬等） | "它卡住了吗" |
| P0-2 | 用户永远看不到自己说了什么（SSE 无 transcript 字段，用户气泡是死代码） | 口语产品的元罪 |
| P0-3 | 麦克风被拒 = 页面变砖，且无任何引导 | 直接弃用 |
| P0-4 | 错误文案是给后端看的："HTTP 429" | 关页面 |
| P0-5 | 流断了 `phase` 永久卡 busy（看门狗未实现） | 页面死亡 |
| P0-6 | 首声延迟 7~13s（TTS 串行在 LLM 之后），等待期无分段状态 | 沉浸感归零 |
| P0-7 | 全链路无任何"开口羞耻"缓解：无热身、无试音、无示范、无重录 | 第一分钟劝退目标用户 |
| P0-8 | 学习闭环断裂：报告无下一步、无历史对比、无打卡 | 没有理由明天回来 |
| P0-9 | 核心页评分卡组件未注册（`NCard` 缺 import），反馈模块渲染残缺 | "没做完" |

**FTUE 账**：从打开网页到第一次开口 = **8 次点击 / 4 次页面切换 / 15 秒强制等待 ≈ 90~120 秒**（目标 ≤2 步 ≤20 秒）。

**分析：** 这 9 个 P0 全部是**交互层的账**，全部可以在 2 人日内修完（docs/19-M2 §5 给了排期表）。**重构如果只做"换一套好看的皮肤"，等于把一辆没装刹车的车重新喷漆。** 本报告的重构建议以"修账 + 重排信息架构"为第一优先级，视觉升级为第二优先级。

## 2. 商业同类产品设计调研

### 2.1 AI 口语陪练/发音教练类（与 VocalVerse 重合度最高的品类）

#### 2.1.1 Speak（speak.com）——场景扮演对话的"现成教科书"

**事实**（仓内 docs/19-Speak 已深析，本处只提炼 UI 设计层面）：

- **屏幕结构**：课程制主页（LESSON 单位）→ 视频教师示范 → 跟读操练 → 快问快答 → 角色扮演（Live Roleplays）→ 智能复习（Smart Review）。四段式课是一节课的主流形态，**自由对话只是高潮段**；
- **对话界面的核心设计**：
  1. **任务目标清单**：每个角色扮演顶部常驻 2~3 个 objectives（如"问出保修期""砍价成功"），完成打勾——"把不知道该说什么变成知道该说什么"；
  2. **分级提示**：卡壳时三级台阶——①中文提示 ②英文关键词 ③完整示范句可跟读，**逐级记录使用次数并计入评分**；
  3. **即时纠正 = 提供更自然的替代说法**，不打断、不评判；
  4. **无限重来、无压力重说**（"the freedom to go again as many times as you need"）；
  5. **开口量仪表盘**：主页一个大数字"你本周开口 N 句"——把北极星指标做成用户可见的进度；
- **等待/延迟处理**：「对话感觉缓慢且不自然」是第一代的官方自认；第二代转 Speech-to-Speech；**重计算全部异步化**（能力图谱更新、错题入队列、生成补强课程、深度学习报告全部在会话后）；
- **反例（不能抄）**：评分过于宽松——用户故意说错仍被判对，公开评测称其"更像抽认卡而非口语练习"；"Made for You"（最个性化功能）反而锁在 Free Talk 之后。

**分析：** Speak 的对话 UI = **"目标 + 三级提示 + 轻纠正 + 无限重说"的受控对话**，且它用"课程结构稀释延迟暴露面"。VocalVerse 的 docs/14 已经吸收了这套（任务目标 = 语料覆盖度、二级救场 = 分级提示），但**前端呈现没有跟上**：我们的"救场提示卡"是 8 秒超时弹一张黄卡（永远取语料第一条、丢中文释义、带 `( )` 占位符），而不是"用户主动可点的三级台阶"。**重构的对话页应按 Speak 的交互模式重做呈现层，而非补丁式修提示卡。**

#### 2.1.2 ELSA Speak——发音诊断的"可信度榜样"

- **界面特征**：逐词/逐音素反馈（词卡 + 音素编辑器 + 正确示范），单词级红绿高亮、音素级评分、重音/语调可视化；
- **可信度设计**：公开宣称评分引擎与专家人工评分在 **±1 CEFR 等级内 93.88% 一致率**，提供 ELSA Proficiency Score（EPS）映射 CEFR/IELTS——"敢对齐你在意的标准"是信任状；
- **移动端**：App 形态；Web 端主打品牌/企业 API。

**分析：** ELSA 证明了"严格且可解释"可以成为卖点。Speak 的全部教训 + ELSA 的全部优势 = 一个设计空间：**对话中给鼓励性宽松分，报告/复盘页给严格真实分**（docs/19-Speak §6 已提出"双轨评分"，docs/19-M2 §3.2 给出"评分默认收起"的交互方案）。重构的评分 UI 应默认"一屏只有一句人话 + 一个徽章"，把三维分数、音素级细节收进可展开层。

#### 2.1.3 其他同品类一句话速览

| 产品 | 一句话设计要点 | 可借鉴等级 |
|---|---|---|
| Loora / Praktika | AI 数字人外教，全屏"通话"式界面，真人影像/虚拟人 + 字幕；视觉走"沉浸通话感"而非聊天流 | 对话页可参考"全屏沉浸"气质，但**3D/数字人与 docs/06 §9.2 的 2D 拍板冲突，不引入** |
| BoldVoice | 口音训练，音素级纠音 + 母语者示范视频，层级化课程 | 音素反馈卡样式可参考 |
| Talkpal / Hallo | 多角色 AI 语伴，语音通话 + 文本双模态；口语练习常与"场景选择"并列 | 场景选卡的信息架构 |
| 流利说® | **无 Web 学习端（App 独占）**；课程化跟读 + 视频配音 + 真人语伴 PK；界面以"课程路径+每日打卡+AI 老师评分报告"为主结构 | **结构性机会**（我们做 Web）；配音玩法是"唱歌评分"的近亲——跟读/配音卡片样式可直接抄 |

#### 2.1.4 口语类共性模式（行业标配清单）

1. **先示范再开口**：跟读、示范音频、视频教师——用户开口前必先"听过一遍"；
2. **目标化任务**：每个练习有 1~3 个可打勾目标（防"不知道说什么"）；
3. **分级提示而非直接给答案**：提示本身是学习资源，使用要计量；
4. **无惩罚重说**：重来不丢分、不扣进度；"AI 不会评判你"是用户反复自发提及的心理安全感；
5. **轻纠正 + 重复盘**：对话中只给替代说法/鼓励，严肃分析后置到报告；
6. **开口量游戏化**：以"说句数"而非"点击次数"为进度指标；
7. **错误/等待状态有"人话"兜底**（Speak 三代都在解决延迟感，这是体验的生命线）。

### 2.2 游戏化语言学习类（Duolingo 设计系统是"活力配色"的出处）

#### 2.2.1 Duolingo 设计系统（为何 docs/13 的方向选对了）

- 官方品牌规范（[design.duolingo.com](https://design.duolingo.com/)）：**Feather Green `#58CC02`** 主色 + Macaw 蓝 `#1CB0F6` + Bee 黄 `#FFC800` + Cardinal 红 `#FF4B4B` + Fox 橙 `#FF9600` 的功能色系；圆润无衬线字体（Nunito 系）、定制吉祥物 Duo、角色插画资产、大圆角卡片与胶囊按钮——**"活力游戏化"配色 + 圆润几何语言**；
- **学习路径（path）**：单元 → 关卡 → 圆节点（每一节点一个短 lesson），主线路径 + 支线（故事/复习/挑战）；主页 = 路径 + 顶部 streak/宝石/宝箱三件套 + 底部排行榜入口；
- **激励系统**：streak（连续天数，含 streak freeze 防挫败）、XP、宝石、心（错误扣除）、每日任务（quest）、联赛（league）周榜、徽章页（成就收集册）；
- **教训面**：NN/g 等评测指出路径过长/内容重复导致疲劳、动画频繁导致分心——**游戏化是"剂量"问题**；
- **AI 化**：Duolingo Max（Explain My Answer / Roleplay / Video Call），2025-01 起 "Lily Calls You" 主动来电。

**分析：** 我们 docs/13 的色板（绿/黄/橙）与字体（Nunito）就是"多邻国系配方"的合法改编（色值不同、语义相同）。行业已验证这套配色对"坚持练习"类产品的动机设计有效。**重构建议保留品牌语言，但要"减脂"**：当前实现的动画/激励几乎为零（连 streak 都没有），Duolingo 的教训反而是"过度激励伤体验"——我们的问题在另一端：**0 激励**。

### 2.3 唱歌评分/K 歌类（M3 /sing 页的直接参照物）

#### 2.3.1 K 歌产品界面结构（全民K歌/唱吧/Smule/StarMaker）

**事实**（来源见文末：腾讯新闻《全民K歌的录唱功能拆解》、myDrivers 鸿蒙版五维打分报道、Smule 官方博客）：

- **录唱主流程**：选歌（分类/榜单/搜索）→ 伴奏试听 → **练唱模式**（不评分、可反复）→ 正式录制（人声+伴奏混合监听）→ 评分 → 演唱结果页（听回放/看分项/发布）→ 分享海报；
- **K 歌界面四要素**：①**滚动歌词**（逐行高亮 + 当前句放大，卡拉 OK 逐字进度由 LRC 时间戳驱动）；②**伴奏控制**（伴奏/人声音量、消原唱开关、变调变速）；③**录音控件**（实时音量条 + 波形 + 计时）；④**可中途暂停/重录**；
- **评分呈现**：总分段位（S/A/B/C 或星级）+ **分项**（全民K歌为"音准/节奏/气息/技巧/情感"类多维度；鸿蒙版更新加入"五维打分"）+ 逐句得分热区 + **与好友/原唱 PK 对比**；
- **结果页动作**：一键回放（自动播用户演唱）、重新录制、发布动态、生成**成绩分享卡片/海报**（品牌化设计，Smule 与全民K歌均为主推功能）；
- **进阶形态**：Smule 的 **Recording Recap**（官方博客"See Your Voice Like Never Before"）——对演唱录音做**可视化分析**（音高/音准的可视化复盘），说明"把声音画出来"是 K 歌产品公认的增值点。

#### 2.3.2 音准/节奏可视化的具体画法（我们的 pyin+DTW 需要抄的呈现层）

| 画法 | 内容 | 代表 |
|---|---|---|
| **钢琴卷帘 + 音符块** | 参考旋律为音符块（横向 = 时间，纵向 = 音高），用户音高为叠加曲线 | Yousician（乐器/声乐课的实时音符轨道）、Simply Piano |
| **音高轮廓叠加** | 参考旋律线 vs 用户演唱线，双侧或差量着色（绿=准/黄=偏/红=跑调） | Smule Recording Recap、K 歌"调音师"回放 |
| **逐句色卡** | 每句一个色块（深绿→黄→红）对应得分，滚动歌词旁挂逐句得分 | 全民K歌逐句热区 |
| **节奏条/节拍对齐** | 音符 onset 标记 vs 用户发声 onset 的偏差条 | Yousician 节奏反馈 |
| **双轨对比回放** | 原唱与用户音轨分上下两条波形，同步播放 | Smule 合唱/原唱开关 |

**开源参照**：UltraStar 家族（Deluxe/WorldParty，桌面开源 K 歌游戏，双轨显示 + 逐音符评分）；Web/TS 社区移植（ultrastar-es 系）；**nightingale**（[github.com/rzru/nightingale](https://github.com/rzru/nightingale)，GPL-3.0，Tauri + Rust/React 壳 + Python/PyTorch 分析进程）——UVR/Demucs 人声分离 → WhisperX 逐词对齐 → **实时麦克风音高对参考旋律打分（星评）→ 每首歌排行榜**；歌词转写只做显示不打分。**它与我们 docs/06 §9.4 口径（pyin 基频 + DTW + 音准/节奏/发音三维）在"音高曲线 vs 参考旋律"这个核心上同构**，可作为界面与流程的地图。

#### 2.3.3 共性模式（唱歌页行业标配）

1. 练唱/正式两段式（先低压力练，再计分录）；
2. 滚动歌词 + 当前句放大 + 可点某句重听（LRC 驱动）；
3. 音准可视化 = "参考旋律 + 用户曲线"双轨（用户逐帧 F0 是否落库**决定能不能画**——见 docs/singing/22 轴线 E 的 P0 未决项，重构前必须先拍板）；
4. 逐句得分卡 + 总分段位 + 每歌排行榜/历史最佳；
5. 结束自动回放 + 重录 + **分享卡片**（成绩海报是 K 歌产品的传播核心）；
6. 变调/变速/消原唱（我们的 TTS/音轨素材允许时再考虑，P2）。

### 3.4 音频可视化技术选型（重构必看）

| 需求 | 推荐 | 理由 |

| 录音采集 | 现有 MediaRecorder（webm/opus） | 已稳定，保留 |
| 波形显示/回放缩放 | [wavesurfer.js](https://wavesurfer.xyz) | 成熟、轻、插件完善（区段/标记） |

### 3.5 移动端/PWA 硬约束清单（重构的"别忘了"清单）

1. iOS Safari 录音必须在**用户手势内**调用 `getUserMedia`，且要求 HTTPS/localhost（非安全上下文直接 `undefined` → 现 P0-3）；
2. iOS 授权后 `AudioContext` 常为 **suspended**，必须手势内先 `resume()` 再录/播；
3. 自动播放策略：无手势禁止 TTS 播放（现 P0-6 的静音开场根因之一）；
4. iOS 切后台/锁屏会断录音——录音期间提示保持前台；
5. **一切录音/播放都绑定用户手势 + 先 resume AudioContext**；
6. PWA：现无 manifest/service worker，若要"安装到桌面"需要新建（P4）。

## 4. 重构建议（推荐方案）

### 4.1 重构范围四象限（先定性再动手）

```
            修体验(快)                         换视觉(慢)

高│ ① P0×9 交互修复        │ ④ 视觉系统升级         │

  │   (IA: 首页/hub/路径) │  (换框架=负收益, 不推荐) │
```

### 4.6 落地顺序（建议 5 阶段）

1. **阶段 1（P0 交互修复，≈2 人日）**：录音真停止 + VAD + 倒计时；SSE 补 `asr_text` 回显；看门狗 + onClose；errorCopy 映射表；麦克风拒绝面板；`NCard` 等组件注册修复；权限 try/catch —— 直接抄 docs/19-M2 §5 排期；
2. **阶段 2（信息架构，≈2~3 人日）**：新首页（免登录试玩卡 + 价值主张）+ 注册表单 + hub 改"路径化" + 首页激励三件套（本地 streak）；
3. **阶段 3（对话页 Speak 化，≈3 人日）**：目标清单、三级提示、热身轮、分段等待、评分收起、工具条（重读/慢速/示范）；
4. **阶段 4（视觉收尾，≈2 人日）**：无障碍（aria/focus/contrast/字号）、动效减脂、空态与引导态、深色沉浸对话页（可选）；
5. **阶段 5（M3 页面**，与后端并行）：/sing（依赖 docs/singing/22 P0 拍板：逐帧 F0 落库、参考旋律轨、轮询契约）→ /stats（lieflat 迁移）→ /report 增强（词级错误表/雷达/分享卡）。

**总成本估**：阶段 1~4 ≈ 9~12 人日（不含 M3 后端），对"重构建前端"的定位是**渐进式重写**：保留全部契约/测试/基建，只重拍交互与信息架构——风险远低于推倒重来。

| 唱歌页设计依赖后端契约未拍板（逐帧 F0 等） | 先与 docs/singing/22 的 P0 决策联动，前端仅做静态高保真 |
| 免登录试用与 JWT 守卫/埋点口径冲突 | 试用会话走独立 kind/匿名 token，方案先行登记 docs/06 |
| 「做深了」评分可信度 vs 「做宽了」范围失控 | 评分对齐四六级/雅思口径仅为包装文案；评分算法不动（docs/06 §9.4） |

## 5. 答辩口径（被问"为什么这么改"）

> "重构的理由不是技术栈落后，而是**人机交互停在能跑通的水平**：我们审过的 9 个 P0（不能停止录音、看不到自己说了什么、出错只见 HTTP 429、练完不知道下一步）里，任何一个都足以让真实用户流失。市面上的答案已经被验证：Speak 用'目标清单 + 三级提示 + 无惩罚重说 + 轻纠正重复盘'把开口门槛降到零；Duolingo 用'路径 + streak + 任务'把回来练习变成习惯；K 歌产品用'滚动歌词 + 逐句音准曲线 + 分享卡'把唱准变得可看、可传播。我们保留已验证的技术栈（Vue3 + TS + naive-ui + 契约生成管线），重拍的是**信息架构与交互层**——这套组合（教学设计深度 + 行业标准交互）在同类学生项目中是差异点。视觉延续多邻国活力方向（docs/13 拍板），因为它的配色逻辑正是为'坚持练习'的动机设计，且我们已用 token 三层架构控制实现成本。"
