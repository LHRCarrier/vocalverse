# 41 · 社区内容 S2 实施设计（关注 + 通知真实化 · 定稿）

> **状态**：定稿（2026-09-06，基于 docs/37 定稿 §5 预留 + docs/39 裁决 + docs/38 §5 企业模板）。
> **范围**：① 关注（follows 实体化 S1 已建表 → S2 接口）；② 通知中心「通知」tab = 互动通知**派生 + mergeKey 聚合**（不建表）；③「关注」tab = 推荐关注管理 + 关注流；④「私信」tab 维持演示帧（IM 范围，S3 后另议）。

## 1. 数据与实现要点

- **follows**：S1 已建表（uq、ix_followee、CHECK 自关注，已预热）；Java 补实体/Repository；取消关注=物理删行（幂等）。
- **关注流**：`posts.followingFeed(me, ts, id)` —— 复用 S1 Criteria 模式（status visible + keyset DESC）；**J-06（2026-09-08）**：作者过滤由巨型 `authorIds IN` 改**相关 EXISTS 子查询**（follower=me AND followee=p.author_id，命中 `ix_follows_followee`）——关注集数万级时 IN 列表不再索引失效/seq scan；作者信息/互动态复用 `buildViews`；未关注任何人 → `countByFollowerId` 快检短路（不跑 SQL）。
- **推荐关注（J-06 收敛）**：`GET /follows/recommendations?limit=`（默认 50、上限 100，服务端 clamp）——候选 = users 分页（排除自己），**作者批量 loadAuthors + 关注批量 `findByFollowerIdAndFolloweeIdIn` 一次判定**（旧实现全表加载 + 每用户 3 次查询的 3N+1；量级证明详见 CommunitySocialTest 往返断言）。**遗留登记（J-06 后半）**：候选无画像/同领域筛选算法（全库按 id 序取前 N），规模增长按「同领域/同兴趣/同级别」过滤 + keyset 游标（P2 后续项）。
- **互动通知（派生）**：数据源 = `post_interactions` + `post_comments`（仅我可见帖、**评论仅可见态**（J-04，2026-09-08：`findMine` 补 `c.status='visible'`——此前只过滤父帖状态，软删/隐藏评论仍进通知「复活」且点击无法定位；与 `comments()` 展示路径口径对齐）、排除自身动作）；**mergeKey = (postId, action, 当日 UTC)** 聚合 like/coin/share → 「张三 等 N 人赞了你的内容《…》」（docs/38 §5 模板）；评论**逐条**带内容；排序=组内最新时间 DESC（同刻按 itemId ASC 稳定）；**阈值游标** = base64(ts|itemId)；演示窗口 = 近 50 条交互 + 50 条评论内存聚合（量级登记，超窗截断）。
- **J-03 已实施（2026-09-10）**：原「演示窗口=近 50+50 + 内存聚合」的正确性/性能问题已修——互动组与评论流全部改 **DB 层 keyset 分页**（互动组 `GROUP BY post_id|action|当日UTC` + `ORDER BY (latest_at DESC, merge_key ASC)`；评论 `(created_at DESC, id DESC)`），「最新互动者」用 `ROW_NUMBER` 窗口函数按组取第一行；每页 SQL 往返恒定、内存 O(limit)，**第 51 条及更早不再丢失**。回归证据：`CommunitySocialTest` 跨窗口 2 例（改前 10/60、50/60 必红）+ `CommunityPgIntegrationTest.explain_notification_queries_use_indexes`（命中 `ix_post_interactions_post_action` / `ix_post_comments_status_post`）。游标语义不变（`base64(micro(ts)|mergeKey)`）。**剩余登记（P2，规模升级时再评估）**：① 若互动量级到百万级，可引入物化通知表/每日聚合（迁移 + 写方联动）；② 通知带作者头像（S4）。

## 2. 契约（docs/21 已登记 · 50 op）

| 方法/路径 | 说明 |
|---|---|
| PUT / DELETE `/api/v1/community/follows/{userId}` | 关注/取关（幂等；自关注 42203；目标不存在 40402） |
| GET `/api/v1/community/follows` | 我关注的人（AuthorView + followedAt + youFollowBack 互关） |
| GET `/api/v1/community/follows/recommendations?limit=` | 推荐关注（候选分页排除自己 + followed 标记；limit 默认 50/上限 100；按 id 序演示） |
| GET `/api/v1/community/following-feed?cursor&limit` | 关注流（keyset `{items,next_cursor,has_more}`） |
| GET `/api/v1/community/notifications?cursor&limit` | 互动通知（聚合/逐条混合，阈值游标同构） |

错误码复用：40402（用户/内容不存在）、40302（越权）、42203（自关注/参数非法）；无新增码。
