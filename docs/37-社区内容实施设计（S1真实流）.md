### 3.2 计数与幂等约定（P0 已闭环）

1. **统一可见谓词常量**：`status='visible'`（Java 一处定义），feed/详情/评论/计数查询共用，防漏过滤（D-Q2）；非 visible 内容的互动/评论端点返回 404（或幂等返回当前态，不双计）；
2. **计数同事务**：互动行写入/删除与计数增减放同一 `@Transactional`；自减用 `like_count = GREATEST(like_count - 1, 0)`（防并发多减，C-05）；
3. **互动矩阵**：like = toggle（`PUT/DELETE /likes`，幂等，删行 + 计数同事务）；coin = **仅 `PUT /coins`**（不可取消，唯一键兜底重复请求幂等返回）；share = `POST /shares` 一人一帖一次（唯一键，第二次返回当前态不加计）；**checkin 卡仅开放点赞**（评论/投币/分享对 `kind='checkin'` 拒绝，B-08/A-08）；
4. **J-01 并发幂等（2026-09-08 修订）**：like 插入/unlike 删行改 **DB 层原子语句**——`INSERT ... ON CONFLICT DO NOTHING`（返回 0=已存在，不双计不报错）与 `DELETE ... WHERE`（返回 0/1 行数）。替代「先查后插 + catch DataIntegrityViolationException」：① check-then-act 在 PG READ COMMITTED 下两次并发 like 会双双查空，第二个 INSERT 撞 `uq_post_likes_post_liker` → 未捕获异常 → **500**（唯一键兜底形同虚设）；② catch 冲突后 Hibernate 已把事务标 rollback-only，提交期仍抛 UnexpectedRollbackException；③ unlike 无条件递减会让并发双击取消双减计数、与事实行漂移（GREATEST 只兜底到 0 不防漂移）。修后：like_count 以「本次是否真实插入/删除行」为唯一增减依据，并发双击/双击取消均只生效一次。
4. comment_count = 未删评论数（软删不计数）= 评论列表 total（A-04）。

**错误码（B-03/C-11，先登记后用）**：`40402` 帖子/评论不存在｜`40302` 越权（非作者/非作者可见）｜`42203` 参数非法（复用 422 段）｜`40904` 重复表态冲突（兜底）。**不得占用 40101**。

**内部 REST（docs/21 §5 登记第二条）**：`POST /internal/checkin`
- 请求（**camelCase**，与 Java Jackson 默认对齐 · B-02）：`{userId, practiceDate, sessionId, snapshot{overall, pron, gram, fluency, turns, durationS}}`；
- 身份头：`Authorization: Bearer <service-token>`（与 SecurityConfig 实测一致；docs/21 §4 R-17 表述同步修正为代码口径）；
- 语义：**幂等 upsert** —— `(author_id, checkin_date)` 存在则 `practice_count+1`、`overall=GREATEST(旧,新)`、其余更新为本次（仅记录）；否则插入 `posts(kind=checkin, domain=NULL, status='visible')`；NativeQuery `INSERT ... ON CONFLICT (author_id, checkin_date) WHERE kind='checkin' DO UPDATE ...`（C-03）；
- 超时 3s；`raise_for_status()` + 结构化告警日志（**禁止静默吞错** · B-10）；失败**不阻塞**练习完成；P2 登记「当日完成但无卡」补扫（`checkin_synced_at` 标记来源，C-17）。
