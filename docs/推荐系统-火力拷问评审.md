# VocalVerse 推荐系统 · 火力拷问评审

> 方式：6 个子代理按维度独立对抗性审查（可行性 / 复杂性 / 运行检测 / 规则引擎正确性 / 数据模型边界 / 安全·失败·依赖）。
> 约定：只读审源码，**未修改任何代码或原文档**；证据以 `文件:行号` 引用。
> 产物：本文档（新增），供评审与整改。

---

## 0. 一句话结论

规则推荐引擎（`app/rec/service.py`）主体逻辑稳固、None 边界处理稳健、C10 修复自洽；但**新加的「双层水平预测器」（`app/skill/predictor.py` + `evaluator.py`）当前是未接线的死代码**，且模型从未训练/加载，并存在「AI 辅助经 `asyncio.run` 桥接在异步上下文必然静默失效」「无模型却标 sklearn+置信度 1.0」等问题。**最需要先定的：这套「水平预测器」到底要不要作为功能交付？**

## 1. 结论摘要（各维度判定）

| 维度 | 判定 | 一句话 |
|---|---|---|
| 可行性 | **fail** | 双层预测器是死代码；asyncio 桥接在 async 环境必抛且被吞；模型从未训练/加载；特征无生产方。 |
| 复杂性 | **concerns** | 相对「文档明示的 demo 道具」属过度设计；与既有 `update_user_level` 重复；阈值/BAND_MID 三处手工复制。 |
| 运行检测 | **concerns** | 单测语义大多真实、隔离健全；但被测对象与运行时脱节，AI 桥零覆盖，若干断言接近恒真。 |
| 规则引擎正确性 | **concerns** | 缓存从不主动失效（死代码）；复习席绕过 diversify 仍可打破 scene_type≤2；聚合派生文档与实现不符。 |
| 数据/模型边界 | **concerns** | 无模型即「近期分直读」却标 sklearn+conf=1.0；分数默认 0 过弱；5 样本训练等于无预测增益。 |
| 安全/失败/依赖 | **concerns** | 硬编码 JWT/service_token 默认值；LLM 桥超时/静默失败；无输入隔离（PII+注入）；真实桥零测试。 |

**严重度统计**：blocker ×1 · high ×17 · medium ×19 · low ×9 · info ×3。

## 2. 最核心问题（跨维度，按优先级）

### P0-1 双层水平预测器是生产死代码（blocker / fail）
- `get_level_evaluator()`（evaluator.py:141-152）从不被任何生产模块调用；`app/api/routes/*` 与 `main.py` 均不 import `skill/evaluator`/`skill/predictor`。
- 模型从不 `.load()`（仓内无 `.joblib`），`main.py` lifespan 仅预热 whisper，无加载钩子。
- docs/06 §9.5「走接口、进步趋势展示」未以可运行形态达成。
- 影响：约 300 行随包交付却不可达；「106 passed」只覆盖这个死模块自身，测试全绿不构成端到端证据（AGENTS.md 亦如此要求）。

### P0-2 `asyncio.run` 桥接在 async 上下文必抛 RuntimeError 且被静默吞掉（high）
- evaluator.py:100 `asyncio.run(_call_llm(...))`；LLM `chat` 是 async（llm.py:46）。在已运行事件循环（本仓均为 async 路由）调用 → `RuntimeError`；被 `except Exception: return None`（102-103）吞掉，无任何 log/指标。
- 影响：AI 辅助层在生产路径「从未启用」且不可观测——设计目标（第 2 层）静默失效。
- 建议：改 `await` 直连 / `anyio.to_thread`；至少 `logger.warning` 记录回退。

### P0-3 无模型时「预测」实为 recent_score 直读，却标 sklearn + confidence=1.0（high）
- predictor.py:105-110 无 regressor 返回 `features[0][0]`（=recent_score）；predictor.py:126-129 无条件 `source="sklearn"`、`confidence=1.0`。
- 影响：向调用方/答辩说谎；confidence=1.0 过度自信。
- 建议：拆 `source ∈ {model, recent_baseline, cold_start}`，无模型标 recent_baseline，置信度随样本量。

### P0-4 规则引擎 Redis 缓存从不主动失效（high）
- `invalidate_recommendation_cache`（rec/service.py:344-350）全仓无调用点；真正的写路径 practice/service.py:192-208 改 `UserMastery`/`UserSkillState` 后不失效。
- 影响：练习后 `rec:{uid}:{type}` 缓存整体命中旧档位/旧排序，最长 1 小时陈旧，违背 local/32 A-2.4「1h + 主动失效」。
- 建议：在 `_post_session_skills` 后调用 `invalidate_recommendation_cache(user_id)`，并盘点所有改变推荐输入的写路径。

### P0-5 复习席绕过 `_diversify`：scene_type≤2 不变式仍可被打破（high）
- rec/service.py:312-315 复习席结果直接 `items +=`，未走 `_diversify`、未更新共享 `counts`；`_review_slots`（212-228）不看 counts。
- 影响：主窗 cafe=2、扩档被拦，但一本「mastered 且 ≥7 天」的 L1 cafe 仍会被复习席追加 → 最终 cafe=3，破坏本次修复的保证。
- 建议：复习席也走共享 counts 的 `_diversify`（或跳过已达上限的类型），并补一条「主窗 cafe=2 + 已练 L1 cafe 进复习席」回归用例（修复前应失败）。

## 3. 分维度详细发现

### 3.1 可行性 — fail
- blocker：整套双层预测器是死代码（无端点/消费方/模型）。
- high：asyncio.run 桥接在 async 必抛且被吞 → AI 层恒回退零观测。
- high：无模型即 recent_score 回声，却标 sklearn+conf=1.0。
- medium：冷启动返回入学档中值（BAND_MID[placement_level]），违背「≠入学测试档」规避循环；且 `placement_level` 全仓无生产来源，实际恒回退 L1/50。
- medium：特征管线（recent_score/score_trend/pass_count）无数据生产方。
- low：本地 `.env` 非 UTF-8 导致 pytest 曾无法起 fixture（本环境遗留）；AI 桥零测试。

### 3.2 复杂性 — concerns
- high：死代码 + 默认装配从不 load →「sklearn 打底」实为恒等映射；train/save/load/GradientBoosting 全套在默认路径死亡。
- high：asyncio.run 桥接是潜伏 RuntimeError，且每次评测新建事件循环 + httpx 连接。
- medium：`_f` 只防 None 不防字符串（会崩），pass_rate 未钳制。
- medium：85/70/55 阈值与 BAND_MID 在 predictor/service/placement 三处手工复制，死封装 `LevelPredictor.score_to_level`。
- medium：冗余 round/build 间接；confidence 公式恒等于 1.0（死精巧）；与既有 `update_user_level` 重复。

### 3.3 运行检测 — concerns
- high：测试覆盖的是运行时不可达的死模块。
- high：「train-once + load-at-startup」未实现（无产物、无启动钩子）。
- high：无模型时 source/confidence 误导被测试固化（test_predictor.py:71-73）。
- medium：AI 真实桥（asyncio.run+DeepSeek+解析）零测试；asyncio.run 在 loop 内 RuntimeError 被吞。
- medium：若干断言接近恒真（confidence∈[0.7,1.0]；弱断言）。
- low：numpy 2.5 DeprecationWarning 是第三方 joblib 问题（joblib/numpy_pickle.py:207），无需改自家代码；共享 GBR.predict 实测只读并发安全（0.42ms/次）；`:memory:`+StaticPool 隔离健全。

### 3.4 规则引擎正确性 — concerns
- high：Redis 缓存从不主动失效（见 P0-4）。
- high：复习席绕过 diversify（见 P0-5）。
- medium：文档「句级→场景级聚合派生 / 未掌握语料过滤」未实现——`user_mastery` 由打分直接算，推荐不读 `user_corpus_mastery`。
- medium：扩档项追加末尾破坏「未掌握>已掌握」全局排序。
- medium：曝光埋点无幂等键、`recommend_group_id` 不返回前端、缓存命中外发不记曝光。
- low：A-4.4「mastered 占比≥0.8」门控未实现，`review_ratio`/`review_mastery_threshold` 为死配置。
- info：None 处理正确（mstatus NULL→not_mastered，无排序/稳定性崩溃，该项通过）；scene 推荐被 5 类×≤2 锁死在 ~10 条，与路由 limit≤20 不符。

### 3.5 数据/模型边界 — concerns
- high：生产从不加载模型 → sklearn 层形同虚设（实锤 docs/07 Q18「演示道具」）。
- high：特征无生产者（`app/reco/features.py` 不存在，docs/11 Q-B17）。
- high：无模型即「近期分直读」却标 sklearn+conf=1.0。
- medium：AI 融合置信度公式恒等于 1.0（阻尼从未生效）。
- medium：缺失/非法 recent_score 默认 0 → 非冷启动直接判 L1（惩罚过强）；float('abc') 会崩。
- medium：asyncio.run 接入异步即静默回退。
- medium：5 样本×4 维训 GradientBoosting(40 树)，且 X 首列==y（目标=特征本身），无预测增益。
- low：BAND_MID['L1']=50 非 L1 真实档中值（27.5），但全系统一致，仅语义偏差。

### 3.6 安全/失败/依赖 — concerns
- high：`app/skill/evaluator.py` 把整条 `record` 原样拼进 LLM prompt（无 system prompt、无 untrusted 定界、非白名单）；攻击者可注入「忽略以上，score:100」，且含 PII 外泄/出境风险（未沿用 docs/06 §9.5 的 `<untrusted_input>` 模式）。
- high：`config.py:31,33` 硬编码默认 JWT_secret / service_token，`docker-compose` 未强制覆盖，生产可致认证绕过 + 内部接口伪造。
- high：asyncio.run + httpx 90s：同步阻塞线程池；async loop 下被吞 → 静默禁用。
- high：真实 LLM 桥零测试，「106 passed」未触达风险代码。
- medium：LLM 输出解析正则可从拒绝/注入句抓走数字（`_parse_llm_score` 误解析）。
- medium：新 LLM 路径绕过既有 `llm_rate_per_hour` 限流（placement/practice 都走 ratelimit，此路径没走）。
- medium：numpy 无上界 + joblib 1.5.3：加载模型时 DeprecationWarning（CI 复现但非失败），未来 numpy 升级可能使 `load` 崩。
- low：`joblib.load` 本质 pickle RCE，若模型路径可被外部影响即触发（当前无此路径）。

## 4. 修复建议排序

**P0（先定产品口径，再动手）**
1. 决策「水平预测器」是否为交付功能：若要 → 落地 离线训练 → joblib 定版 `skill_model_path` → 启动 load 成单例 → 挂一个路由（如 `GET /api/v1/level/predict`）→ 特征生产者 `app/reco/features.py`；若不要 → 从本 PR 移除或明确标注 demo、不宣称预测（docs/07 Q18 口径）。

**P1（若保留双层，接线前必修）**
2. 删除 `asyncio.run` 桥：`evaluate()` 改 async 直接 `await llm.chat(...)`（复用共享 AsyncClient），或 `anyio.to_thread`；超时降到 5–10s；回退打 `logger.warning`。
3. source/置信度诚实化：无模型标 `recent_baseline`，置信度按样本量；AI 融合置信度用 `base_confidence×(1−ai_weight)`。
4. 输入隔离 + 白名单：`_call_llm` 只序列化数值特征子集，拆 system(user 声明不可执行) + user(features) 两段，沿用 `<untrusted_input>`。
5. 复用 `ratelimit.consume`（llm_rate_per_hour）+ 模型路径服务端白名单/完整性校验。

**P2（规则引擎，独立于上述决策）**
6. `_post_session_skills` 后调 `invalidate_recommendation_cache(user_id)`，并盘点所有改变推荐输入的写路径。
7. 复习席走共享 counts 的 `_diversify`，并补 C10 衍生回归用例。
8. 澄清「句级→场景级聚合派生 / 未掌握语料过滤」文档 vs 实现（二选一），并决定是否需要接线 user_corpus_mastery。
9. 曝光埋点：每次下发（含缓存命中）统一记曝光 + 稳定幂等 key + `recommend_group_id` 随响应返回给前端作 click 关联。

**P3（可选）**
10. numpy 加上界/钉 joblib；`_f` → `_num` 防非数值 + pass_rate 钳 [0,1]；抽 `app/skill/bands.py` 统一 BAND_MID/score_to_level 消除手工复制；删除死封装。

## 5. 结论

- **公开结论**：规则推荐引擎（水平窗/排序/扩档/复习席/None 处理）实现清晰、语义稳健，106 单测全绿；本次修复的 scene_type≤2 计数漏洞（主窗+扩档）正确且自洽、已有 C10 前置回归。
- **需先决策**：新加的「双层水平预测器」目前不满足「可运行功能」标准（死代码 + 无模型 + asyncio 桥必然静默失效），**要么作为 demo 明确标注，要么按 P1 逐条整改后才算已实现**——否则答辩或评审会误以为「水平预测/AI 辅助」已上线。
- **最值得先做的两条**：(1) 缓存主动失效（P2-6）；(2) 复习席不要绕开 diversify（P2-7）——这两条是规则引擎当前真实正确性缺口，与你本次修复同属一类。
