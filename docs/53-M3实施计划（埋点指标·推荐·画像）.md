## 2. 关键决策（本计划新增）

1. **指标口径修订（P2）**：采用开源分析工具的通行定义（GA4/PostHog/Plausible 三家一致口径）——
   **「参与会话」= 时长 >10s 或 有关键事件 或 ≥2 个 page_view**；`跳出率 = 1 − 参与率`。
   原 docs/06 §9.1 的「进场景/歌曲页 30s 无有效事件」在场景对话下线后无数据源，且与业界口径不一致，故修订；
   完成率/互动率按现玩法重写：**完成率**（唱吧：整首上传完成 / 发起；酒馆：≥1 玩家回合 / 开局；答辩：答满或 ≥2min）；
   **互动率**（酒馆：玩家回合 / DM 回合；自由对话：用户回合 / 总回合；唱吧：有跟唱句数 / 总句数）。
2. **推荐算法（P3）**：数据量（demo 3~5 账号）不支持协同过滤 → 采用**内容型冷启动**（业界在数据稀疏/冷启动下的推荐基线做法：
   TF-IDF + 余弦相似度 + 侧信息匹配；参考 arXiv 2504.02288 EASE-with-side-features / SEMCo 一系论文的结论：
   冷启动用内容特征 + 启发式基线优于强行 CF）。实现 = sklearn TF-IDF（标题/标签/描述）+ 水平匹配（user_skill_state/CEFR）
   + 掌握度惩罚（user_mastery）；模型/向量启动加载（joblib 持久化），严禁每请求重训（docs/06 §9.5 已定）。
3. **埋点维度（P1）**：`level/age_group` 取用户档案快照；`channel` 由前端按运行环境传（web/pwa/ios/android/other）；
   `server_offset_ms = 服务端接收时间 − 客户端 occurred_at`；`browse_session_id` 前端每次 App 会话生成（sessionStorage），
   贯穿 page_view/impression/click（CTR 与跳出率的会话去重键）。
4. **游客埋点（P1）**：仅 `page_view` 允许未登录上报（`events.user_id` 本可空）；其余事件仍要求登录。
5. **生产者为空的事件（P1）**：`fun_action`（原场景对话语义）与 `corpus_hit` 随对话下线退役，**保留枚举兼容历史行、不再新上报**（写入 docs/06 §9.1）。
