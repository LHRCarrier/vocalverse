## 0. 一句话结论

设计稿 v1 的**主体方向成立**（媒体服务独立、jsonb 内联、只做详情页划词），但**三处阻断级错误必须改**：
① `sha256` 全局唯一 + 软删会让同内容永久传不上去；② 暴露 `bigserial` 的 URL 与「不可猜」的匿名读理由自相矛盾；③ 64MB 视频上限被 nginx `client_max_body_size 20m` 挡在网关。
另有 **Python 日志零输出**、**媒体 URL 在打包壳必破**、**错误码未登记且自相矛盾** 三条「照稿实现即坏产物」。

**阻断级合计 23 条**（并发 3 / 日志 3 / 数据 3 / 联动 6 / 模块 3 / UI 5），已在 `docs/47` v2 逐条处置。

## 3. 设计稿 §11 待定项裁定

| 待定项 | 裁定 | 理由 |
|---|---|---|
| A 上传归属校验 | Java 只校验 URL 前缀 + 形状；归属由 `public_id` 不可猜 + Python 侧 owner 校验（DELETE）兜底 | 跨服务查表破坏写方矩阵（`docs/10 §3.1`）；S4 升级签名 URL |
| B `media` jsonb 内联 vs 关联表 | **维持 jsonb 内联**，但每个 item 现在就带 `id`（public_id） | 零迁移成本；S4 若要按媒体反查可无损回填 |
| C 匿名读 | **本期接受匿名读**（URL 含随机 `public_id`），并登记签名 URL 为 S4 | 原生 `<img>/<video>` 带不了 Bearer（docs/06 §11 同款问题）；视频走 blob 会失去 Range 拖拽 |
| D 视频封面 | **客户端首帧抓帧**（`<video>` + canvas，同源无 taint） | 不引入 ffmpeg 依赖；失败则退渐变占位 |
| E 划词范围 | **只详情页**（正文 + 评论） | 列表整卡可点 + 摘要 line-clamp 截断 → 划词与跳转互斥 |
| F items 上限 / 头像端点 | `items ≤ 9`；头像**复用同一上传端点**（`kind=avatar`，客户端裁方形 ≤512px） | 一套校验/存储/限流；头像只是 kind 不同 |

## 4. 已采纳的加固项（非阻断但成本低、收益高）

- 上传**分块写盘**（1MB chunk，不 `await file.read()` 全量）+ uuid 临时名 + `os.replace`
  （Windows 上目标被读句柄占用会 `PermissionError`，需 try/except + 先判存在）；
- 魔数嗅探（不信任客户端 `Content-Type`/文件名）：image `jpeg/png/webp/gif`、video `mp4/webm`；
- 日志字段：`request_id / user_id / media_id / kind / mime / size / sha256[:8] / dedup / elapsed_ms / code / reason`，
  **禁止**记录原始文件名、二进制、完整 storage_path；
- 匿名 GET 的 404 也记 `info`（带 public_id 前 8 位）用于排查，但不记 UA/IP（避免日志洪泛放大）；
- `EventName` 补齐 + `source='community'` 进 payload；
- 详情页互动回写：`patchItem` 对不在 feed 里的帖是空操作 → 详情页自己持有状态（`usePostDetail`）。
