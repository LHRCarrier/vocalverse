## 3. 本轮优化（P0 + 高影响 P1；不镀金）

### 3.1 让机制在真局里发生（后端为主）

| 措施 | 契约 |
|---|---|
| **结算确定性路径** | 新增 `POST /api/v1/trpg/campaigns/{id}/quests/{name}/settle`（body 可选 `outcome`）：服务端直接执行结算（幂等——已结算返回既有结局），落结局系统卡；`GET /campaigns/{id}` 增加 `finished`/`finished_at` 与任务进度字段 |
| **道具来源** | 新增 `grant_item(name,qty,effect,consumable,owner?)` 工具；场景卡生成/应用白名单允许 `item.{名}.qty|effect|consumable`；prompt 规则 12（战利品/购买/搜刮必须调工具） |
| **人物状态机** | `enter_character` 直接 `active`（`arriving` 只保留给未来的立绘任务）；提取器懒注册不再标 `pending`（pending 仅用于未知实体确认流）；`exit_character` → `cleared` + 离场事件 |
| **推进靠规则不靠自觉** | `roll_dice` 增加可选 `quest` 参数：成功 +1（余量≥5 再 +1）、失败推进威胁钟 +1；系统判定并落表 + 发 `quest` 事件（对齐 BitD 的「效果决定格数」） |
| **战报可见** | `attack` 命中/未命中落 `trpg_sys="dice"` 系统卡（复用判定卡渲染；文案含「命中/失手」），刷新仍在 |
| **判定卡去内部键** | `apply_dice_delta` 的 summary 用显示名（`主角 HP 7（-5）`），不再输出 `pc.主角.hp=7` |
| **结算防重** | 已 `done/failed` 的任务再次结算 → 幂等返回，不再新发结局卡；DM 规则补「已结算任务不得继续推进」 |

### 3.2 把状态搬进玩家视线（前端为主）

| 措施 | 契约 |
|---|---|
| **常驻迷你状态条**（VN-HUD 口径：小、可忽略、开箱即见） | dock 上方一行：任务名+进度格+「威胁」文字标签 / 在场人数 / **线索入口**（点开主持台·任务线索页）；默认折叠，点击展开完整钟与在场条 |
| **阅读区优先** | 折叠时正文可视区 ≥ 55% 屏；流式节流跟随滚动 + `turn_end` 兜底滚底；内容区 `padding-bottom` 覆盖停靠区高度 |
| **动作面板常驻且去重** | 通用行动常驻（无实体/道具也在）；合并 dock「推荐行动」为一行（保留 dock 只做输入）；chip 横滑 + 渐隐；攻击目标仅在遭遇激活时出现；点击后乐观 toast |
| **结算入口** | 钟满时面板出现「收尾本幕」→ 调 settle 接口（失败回退文本行动）；结算后卡片区显示「已完结」条 + 「开新篇章」（切换/新建剧本） |
| **尾声兜底** | 消费实时 `ending` 事件（追加/定位尾声卡），系统卡路径保留；任务名去重 |
| **HP 归属** | 玩家 HP 仅取 `pc.*.hp`；敌人 HP 只进遭遇卡 |
| **推荐行动动态化** | 按场景/在场/任务生成（如 观察{场景} / 与{最近NPC}交谈 / 推进{任务}），状态变化即更新 |
| **在场条语义** | PC 永不 arriving；离场置灰 + 展台状态标记（在场/已离场） |

### 3.3 调研依据（本轮新增）

- **工具可靠性靠结构**：强制 `tool_choice`（具名/required）、工具面收窄、**extract-then-act**（模型提议、代码校验执行）、
  路由分类器（trpg-agent 的 roll router / F&F 的 post-processing 状态判定）——本轮据此把「结算」做成确定性接口、
  把「推进」绑定到掷骰规则；来源：AI/TLDR Tool Calling Best Practices (2026)、The Prompt Bench Function Calling Patterns、
  `arxiv 2606.06284`（工具目录越大选择越差）。
- **移动端叙事 HUD**：文本框占底部约 1/4、常驻元素最小化（进度/状态用小指示器而非大面板）、44px 触控目标、
  safe-area、正文行宽/字号优先——本轮据此折叠大块状态面板、改为迷你条 + 详情抽屉；
  来源：Fuwanovel《UI Design – An Anatomy of Visual Novels》、Kigyo Visual;Conference 讲稿、StoryBot 移动端适配记录。

## 4. 验收标准（本轮 DoD）

1. **真局触发**：新开一局真实对话，两回合内出现至少 1 次 `quest` 事实更新（掷骰成功推进）或 `item.*`/`npc.*.hp` 变化；
   打「我攻击X」必须产生判定卡 + 状态变化（不再被纯叙事拒绝）。
2. **可结算**：钟满时点「收尾本幕」→ 出现尾声卡 + 已完结条；再点幂等；刷新后结局仍在；开新篇章可用。
3. **状态可见**：PLAY 态滚动到底时，任务进度/在场/线索入口始终可见（常驻条内）；正文不被打字面板遮挡。
4. **在场语义**：PC 不显示「正在赶来」；`enter_character` 后实体为 active；离场有标记。
5. **门禁**：Python `ruff check/format` + pytest 全绿；Web `lint/typecheck/test:run/build` 全绿；两端用例覆盖新契约。

## 5. 不纳入本轮（避免镀金）

- 跑团 XP 并入 `stats/progress`（口径未定）；NPC 情绪/记忆三轴；属性/法术全栈；动态难度；
  立绘挂/卸 UI（媒体选择器）；多 PC 的「我是谁」显式标记；语音环境排查（另开）。

### 6.2 二次修复（本轮）

- **语言/语音**：TTS 默认音色写死 `en-US-JennyNeural`（`config.tts_voice`）→ 切中文后语音语言不对。
  新增 `voices.default_voice_for_lang`（zh → `zh-CN-XiaoxiaoNeural`），`stream_turn` 把 `lang` 传入 `_tts_chunks`：
  用户显式 `voice_name` 优先，否则按输出语言取默认音色。
- **结算幂等（P1-1）**：`_sync_task_clue_from_op` 容忍重复任务行（保最早、清多余）+ `create_task` 按标题 upsert +
  成功结果只在提交后追加；卡片重复应用不再产生重复任务。回归：重复行下结算幂等、二次结算不新发卡。
- **道具可见（P1-3）**：DM 快照新增「行囊」行（`item.*` 优先、`pc.*.inventory` 兜底，上限 6）。
- **攻击目标（P1-5/N5）**：根因 `DOMAIN_ENTITY_KIND.get(domain, "npc")` 把 `encounter.main.*` 注册成 `npc.main`；
  已修（encounter 不注册实体 + `RESERVED_ENTITY_NAMES` 过滤）；`attack` 仅接受在场 npc/pc 实体，
  拒绝自身/其他 PC/已离场/内部名，错误文本列出可用目标。
- **NPC 反击（P1-4）**：prompt 规则 13——敌方伤害必须走 `attack(attacker=NPC, target=PC)` 或 `roll_dice effects`。
- **判定卡骰面（N4）**：`/roll` 摘要补骰面（`d20=14 +2 = 16 vs 12 成功`）。
- **契约**：`GET /campaigns` 列表项补 `finished/finished_at`；前端改读 `state.campaign.finished`（刷新不丢已完结条）。
- **UI**：页内四视图（大堂/角色卡/纪事/跑团）落地；chip 溢出渐隐提示；展开迷你条滚动补偿不再盖正文。

### 6.3 仍欠（下轮候选）

- 正向钟推进经济学偏慢（威胁钟结构性更快）；「余量≥5 再 +1」不可预期（建议展示规则或改固定档）。
- 阅读区 48% → 55% 目标未达（底部停靠区仍厚）。
- 旧局 legacy `pending` 实体仍显「正在赶来」（新注册起才按新语义；可加一次性迁移清理）。
- 迷你条折叠态不显示 tick reason；无钟任务显示 0/6 的假格。
- 结算为顺序幂等（前端已 pending 禁用；并发双击仍无 DB 唯一约束兜底）。
