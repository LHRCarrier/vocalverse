## 2. 事实表契约（facts，全部走 `state.py` 唯一写入口）

| key 格式 | 值 | 写入方 | 说明 |
|---|---|---|---|
| `quest.{名}.progress` | `"3/6"`（当前/总格） | 工具（system） | **LLM 提取器禁写**（writer 白名单：`progress/kind/stage` 仅 system） |
| `quest.{名}.kind` | `positive\|threat` | 工具 | 威胁钟=倒计时（满格触发坏结果） |
| `quest.{名}.stage` | 章节/阶段名 | 工具 | 如「调查 / 对峙 / 收束」 |
| `quest.{名}.status` | `active\|done\|failed` | 工具 + 提取器（原有） | 结算后置 done/failed |
| `npc.{名}.hp` | 整数 | 工具（effects 增量） | 新增 State 域（`STATE_DOMAINS += npc`，属性白名单 `hp/status`） |
| `item.{名}.qty` | 整数 | 工具 | 数量 |
| `item.{名}.owner` | `pc.{名}` | 工具 | 持有者（用于背包过滤） |
| `item.{名}.effect` | 文本（≤60） | 工具 | 效果描述（叙事 + 数值约定由 attack/use_item 解析） |
| `item.{名}.consumable` | `true\|false` | 工具 | 用后是否扣减 |
| `encounter.{id}.status` | `active\|done` | 工具 | 遭遇开关 |
| `encounter.{id}.order` | JSON 数组 `["pc.主角","npc.地精"]` | 工具 | 先攻序（系统排序，LLM 不写） |
| `encounter.{id}.turn` | 整数下标 | 工具 | 当前回合指向 order 的下标 |
| `encounter.{id}.round` | 整数 | 工具 | 第几轮 |

- 白名单登记：`constants.DOMAIN_PROPERTIES` 扩 `quest: (progress, kind, stage, status)`、
  新域 `item`、`encounter`；`DOMAIN_ENTITY_KIND` 中 `item→task`（实体登记用），`encounter` 不登记实体。
- **LLM 约束**：`facts.check_key_whitelist` 增加 writer 维度（`writer="llm"` 时 `progress/kind/stage/order/turn/round/qty` 一律拒绝），
  默认参数保持旧行为；提取器调用处传 `writer="llm"`。

## 3. 工具契约（`tools/*.py`，一文件一个；outcome 结构沿用 `{text, status_stage?, ...}`）

| 工具 | 入参 | 行为 | outcome 附加 |
|---|---|---|---|
| `tick_clock` | `quest`、`delta`(1~3，可负)、`reason` | 读 `progress` 与总格，系统做算术（0..N 夹取）；满格 → 提示 DM 可结算 | `quest: {name, progress, segments, kind, reason, full}` |
| `complete_quest` | `quest`、`outcome`(`strong\|weak\|miss`，可省 → 由进度自动判定) | 结算：置 `status`；生成尾声（模板 + 结局档位文案）；营地 `finished_at` | `ending: {quest, outcome, title, text, epilogue}` |
| `enter_character` | `entity`、`role?`、`note?` | `ensure_entity(pending=True)` + 若无可展示立绘 → 标 arriving；同场景去重 | `character: {name, kind, status:"arriving", note}` |
| `exit_character` | `entity`、`reason?` | 实体 `status=cleared` | `character: {name, kind, status:"departed", reason}` |
| `attack` | `target`、`weapon?`、`vs?`、`effects?`、`damage?` | 命中判定（d20+mod vs `vs`，缺省 12）→ 命中则 effects/damage 写回（复用 `apply_dice_delta`）；产出战报文本（去公式） | `encounter: {kind:"attack", attacker, target, hit, damage, targetHp}` |
| `use_item` | `item`、`target?` | 校验 `qty>0`；consumable 扣 1；效果写回（hp 回复等） | `item_used: {name, qty, effect, target?}` |
| `start_encounter` | `participants[]` | 建 order（按 d20+敏捷？无属性 → 随机+固定序）、round=1、turn=0 | 同下 |
| `next_turn` | — | turn 前进（回绕则 round+1） | `encounter: {kind:"turn", order, turn, round}` |
| `end_encounter` | `outcome?` | status=done | `encounter: {kind:"end", outcome}` |

- 频控/去重：`turn.py` 对同回合重复 `quest/character/encounter` 事件按 key 去重（沿用 portrait 的做法）。
- 失败不打断：沿用注册表错误隔离；`attack` 目标不存在 → 错误文本让 DM 如实告知。
- **prompt 规则**：`prompts.py` 增规则 8~11（进度钟/结算/人物进出场/战斗与道具使用时机；禁止每回合 tick）。

## 4. 立绘接入（本轮范围）

- `trpg_entities.portrait_media_id`（String(64)，nullable）——`POST/DELETE /api/v1/trpg/campaigns/{id}/entities/{entity_id}/portrait`（body `{media_id}`，owner 校验，媒体归属校验）。
- `show_portrait` 返回 `media_id` + `url`（`/api/v1/media/{public_id}`）；无挂图 → 仍返回实体名（前端按名字命中内置素材）。
- **异步生成不在本轮**（等文生图服务商拍板）；`enter_character` 的 «正在赶来» = 实体 pending + 前端占位，不含生图任务表。

## 5. SSE 事件契约（`events.py` ↔ `apps/web/src/audio/trpg-sse-types.ts` 手写镜像同步）

```ts
{ type:'quest';     quest:string; progress:string; segments:number; kind:'positive'|'threat'; reason?:string; full:boolean }
{ type:'ending';    quest:string; outcome:'strong'|'weak'|'miss'; title:string; text:string; epilogue:string }
{ type:'character'; name:string; kind:'npc'|'pc'; status:'arriving'|'active'|'departed'; note?:string|null }
{ type:'encounter'; kind:'start'|'attack'|'turn'|'end'; order?:string[]; turn?:number; round?:number;
                    attacker?:string; target?:string; hit?:boolean; damage?:number; target_hp?:number; outcome?:string }
```
- 持久化：`ending` 额外落系统卡（`trpg_messages.kind=system`、`trpg_sys="ending"`，payload 同事件）→ 刷新仍在；
  `quest/character/encounter` 靠 facts/entities 刷新恢复，不落系统卡。
- 前端 `TrpgSseEvent` union 增加四类；`useTavernSession` 的 switch **只做委派**（见 §6）。
