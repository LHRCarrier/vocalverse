# 英文歌打分 · 系统集成拷问报告（轴线 B：Python API 契约与异步）

> 完整逐问 Q/A，主报告见 `docs/singing/22-英文歌打分系统集成拷问报告.md`。

## 0. 拷问目标
核查唱歌模块端到端形态、端点结构、异步化实现、上传校验、鉴权限流、错误码与契约流程；区分【事实】/【推断】/【未决】。

## 1. 问题清单
Q1 整首 vs 逐句形态｜Q2 端点设计（复用 /sessions vs sing 专线；SING 承载）｜Q3 异步化形态与任务状态机｜Q4 上传校验与 16k 转码｜Q5 鉴权/限流｜Q6 错误码｜Q7 契约流程｜Q8 离线参考旋律是否已实现｜Q9 create_session 是否接受 SING｜Q10 逐句 ISE 调用 vs 限流配额｜Q11 ISE 非 16k wav 缺口｜Q12 前端 /sing 与录音上限。

## 2. 逐问结论
- **Q1 形态=整首跟唱【事实】**：一次上传整首→服务端异步逐句评分→逐句结果。证据：docs/02:41「选歌→录音→基频提取→DTW对齐→逐句评分→报表」、docs/01:43、docs/10:182-184（一行=一首歌）、docs/07:88 完成率「整首逐句评分结束」。不做口语式「逐句重录/SSE 每轮上传」。
- **Q2 端点【事实+未决】**：`sessions` 表已承载 `kind='sing'`（base.py:154-157、practice.py:88、迁移 0001/0002），`sing_attempts.session_id` 挂 sessions（practice.py:204-205）。但**`create_session` 只处理 DIALOG/DEFENSE**（service.py:53-66），SING 走 `else→400(unsupported kind)`；**`SessionCreate` 无 `song_id`**（routes/practice.py:42-47）；返回体也无 song_id。端点命名/前缀（是否新增 `/api/v1/sing/**`、有无 `immersion`）无文档依据，待拍板。**
- **Q3 异步化【事实】**：docs/06 §8:121 ⑤「唱歌/长音频评分走 **Redis 任务状态轮询**（M3 必项，不许同步等待）」；docs/06:189 Redis 用途含「评分任务状态」。现状仅 `defense.py:72` 用 `asyncio.create_task(runner())`（进程内 asyncio，状态存 DB 列），**无 Redis task store、无 poll 端点**。**推荐**：状态机 `queued→processing→done|failed`；结果持久到 `sing_attempts`（DB，Python 写）+ Redis/内存只存进度；CPU 密集（pyin/DTW/numpy）必进 `asyncio.to_thread`（`asr.py:69` 先例）；上传端点幂等（同 session 重复提交返回同 task_id）、任务完成则重复轮询返回既有结果。
- **Q4 上传校验**：上限 180s/20MB（config.py:59,54）；`validate_audio_bytes`（upload.py:17-27）只做字节上下界（40002/41301）；**180s 时长校验需解码算时长**（CPU，放 to_thread）；**下界**建议整首给专属（如 ≥5s）；16k mono wav 转码放在**算法侧**（进入评分前统一转，复用 `asr.py:63-69` ffmpeg 模式）；落 `audio_dir`（24h TTL）。
- **Q5 鉴权/限流**：唱歌端点用 `Security(get_current_user_id)`（避免 R-1 的 `Depends` 缺陷）；`bucket_limits`（ratelimit.py:92-99）无 sing 桶→需新增；`<audio>`/Bearer 不兼容（R-5）唱歌回放复用。
- **Q6 错误码**：现有无任何唱歌专属码。需新增：`40904`（参考旋律未就绪/缺失）、`41302`（时长超限，可选）、`50002`（提取/算法失败，可选）；**先登记 `docs/api/error-codes.md` 再用**（AGENTS.md）。
- **Q7 契约流程**：must 走 docs/21 §7——改代码→`refresh-openapi.ps1`→`pnpm gen:api`→同步 docs/21 §2.1 + docs/api + error-codes→CI 三关卡（python-ci 快照==`app.openapi()`、frontend-ci `pnpm gen:api` 后 `git diff` 空）。
- **Q8（关键派生）离线参考旋律提取未实现**：`song_pitch_refs` 只有模型无写方；`pitch_ref_status` 全站恒 `'missing'`（content.py:164-166）；Java 只把它 ready→missing，**无 Python 离线任务翻 missing→building→ready**。→ 音准（0.5 权重）无米下锅，默认链路最重阻塞。
- **Q9** `create_session` 对 SING→400 + `SessionCreate` 无 song_id → **现契约无法建唱歌会话**。合入需改：SING 分支（校验 song published + pitch_ref_status）、`SessionCreate.song_id`、返回体 song_id。
- **Q10（隐藏炸弹）逐句 ISE 限流配额**：发音复用 ISE（`cmd:"ssb"` 单句评分），一首歌几十句（`expected_lines`），`ise_rate_per_hour=60`（R-16 指 ADR 实为 30/h）→ **单首歌打穿整小时配额**，连唱即 429。需拍板：全句发音（独立 sing 桶放宽）vs 抽样句；与 R-16 一并裁决。
- **Q11（继承缺口）ISE 非 16k wav**：`orchestrator.py:161 _safe_score` 把原始 webm/opus 字节直接传 `scorer.score()`；`ise.py` 不转码。唱歌发音继承；需评分算法侧统一转 16k mono wav。
- **Q12 前端**：`/sing` 路由=`PlaceholderView`（router/index.ts:53-58）；recorder.ts:112 已按场景传上限（唱歌 180s）。前端结构预留、无唱歌视图/API 调用。

## 3. 未决缺口
| # | 缺口 | 候选 |
|---|---|---|
| B-1 | 端点命名/路由划分未定 | 复用 POST /sessions(kind=sing)+新增 /api/v1/sing/** |

## 4. 结论
唱歌是**整首跟唱**（非逐句重录）；schema 层已就绪，但**服务层/契约层三处断链**（拒 SING、无 song_id、离线旋律提取无实现），且**逐句 ISE 配额是隐藏炸弹**；异步化必须走 Redis 任务状态轮询（M3 硬约束）；端点合入必须走 docs/21 §7 × CI 三关卡。
