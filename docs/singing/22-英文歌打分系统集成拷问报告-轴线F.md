# 英文歌打分 · 系统集成拷问报告（轴线 F：运维/测试/合规/并发）

> 完整逐问 Q/A，主报告见 `docs/singing/22-英文歌打分系统集成拷问报告.md`。

## 0. 拷问目标
拷问唱歌模块叠加在既有 R-1..R-16 整改项与「Python 单写者 + Java 管理端」架构之上是否放大/引入新风险。结论：schema 已建，唱歌逻辑/端点/并发门禁/清理全部未实现；本报告拷问「即将实现部分」与既有基线的冲突面。

## 1. 问题清单
Q1 唱歌 CPU 热路径并发（to_thread/信号量/--workers 1/SSE 心跳/队列）｜Q2 配置/门禁｜Q3 测试/打桩/基准脚本/契约三关卡｜Q4 合规硬约束（24h 清理/商用音乐/LRC 版权/产物）｜Q5 可观测（trace/限流/readyz/埋点）｜Q6 交叉风险（R-1..R-16 叠加）｜Q7 单写者/归属（pitch_ref_status 谁写；get_audio 漏 sing）｜Q8 算法可信度与基准。

## 2. 逐问结论
- **Q1【事实/部分未决（G1）】**：唱歌三项均为 >10ms CPU（pyin/DTW/numpy），**必须进 `anyio.to_thread`**（docs/06 §8:121；`asr.py:69` 先例）；但唱歌无任何 to_thread 包装（`orchestrator.py:586-590` 直接 `await scorer.score()`）。180s pyin RTF>1（docs/09 §3.2-3:61），同步 1~3 分钟。**全仓无 Semaphore**（docs/20 §3.4:201 自认 P1-4）→ 需独立 CPU 信号量（建议 sing=1~2，与 whisper/ISE 分桶）。`--workers 1` + 180s 同步 CPU 会阻塞整进程、对话 SSE 心跳断（`practice.py:161-174` StreamingResponse **无 ping**）。**线程模型两档混写未拍板**：docs/06 §8:121「Redis 任务状态轮询」vs docs/19-架构 §7:350「建议 arq/RQ 级（别上 Celery）」。**推荐**：进程内 `asyncio.create_task`/`Queue` + sing 信号量 + Redis 任务态（P0-1）+ 前端轮询；跨进程再升 arq/RQ；**禁止静默同步等待**。
- **Q2【已核实】**：无 `APP_SING_*`、sing 限流桶、sing 缓存目录；extractor 硬编码 `'pyin'`；`.env.example` 只 `APP_MAX_SING_SECONDS=180`；根 `.env.example` 无 sing 项。**新增 APP_* 需三处同步**（config 默认 / .env.example / docker-compose 回退值），AGENTS.md 明令一致。`docker-compose.yml` python-api 只挂 `./data/audio`，**无 hf-cache 卷**（docs/06 §8:120 承诺未实现）。唱歌无大模型下载（librosa 提供 pyin）。
- **Q3【已核实】**：无唱歌 Fake（stubs.py 只有 FakeASR/TTS/Scorer/LLM；base.py 无 `get_sing_scorer`/`get_pitch_extractor`）；CI 靠 `APP_TESTING=true` + 注入 Fake。评分公式 `0.5音准+0.2节奏+0.3发音` 应做纯函数单测（≥50% 门禁，docs/06 §6:100）；`pytest -m "not gpu"`。`scripts/poc/` 无 `pyin_rtf.py`（ASR RTF 有 POC-3）。契约三关卡：python-ci（快照==app.openapi()）、java-ci（ContractSnapshotTest）、frontend-ci（pnpm gen:api 后 git diff 空）；新增 sing 端点必须跑 `refresh-openapi.ps1`。
- **Q4【已核实，部分未决】**：**24h 清理只有惰性、无定时任务**（practice.py:240-243；main.py lifespan 仅 ASR 预热）→ 未回放音频永久驻留（docs/19-商业 P-03:415 🔴，要求补 lifespan 周期+启动扫描）。商用音乐**仅 DB 级 CHECK**、无应用层校验（content.py:175；建议 Java 写入口强制白名单）。LRC 版权可逐句审计（line_text+source），但**无《素材授权清单》文档**（docs/19 §6.2:344）。`pitch_ref_status != 'ready'` 应返回「生成中/缺词」不静默算分（content.py:163-166）。产物 = `song_pitch_refs`(DB JSONB) + 用户唱音频(data/audio) + F0 序列，**无清理策略**。
- **Q5【已核实，部分未决】**：`trace.py` RequestId 中间件复用即可（子任务日志须带 request_id）；`ratelimit.py:92-99` 无 sing 桶（需新增，防刷长任务）；**`readyz` 恒真**无真实 PG/Redis 探测（health.py:18-27；docs/20 D10/R-10 目标态未落地）→ 唱歌任务态降级到内存却显示 ready，编排误判。`EventTypes` 10 类（test_m2_core.py:319 断言恰好 10 类）；唱歌**无专属事件类型**（复用 practice_complete(kind=sing)），加新类型会破坏「恰好 10 类」测试。
- **Q6【已核实，部分未决】**：**R-5 音频回放 Bearer 头与 `<audio>` 不兼容**（practice.py:234；docs/20 D11/ docs/21 R-5 目标态=签名 URL 或 Blob，未落地）→ 唱歌回放「全剧无声」，最强叠加风险；**R-8 越权 + get_audio 归属漏 `SingAttempt`**（practice.py:248-257 只查 Attempt/ScenarioMessage）→ 唱歌用户自己的音频 403；长任务+ise 桶瞬间打满；错误码无 sing 码；orchestrator run_turn 只 dialog/defense，无 sing 分支。
- **Q7【事实，文档冲突（G6）】**：`content.py:163-166`/docs/11 Q-B11 写「`pitch_ref_status` 由 Python 离线任务翻转」，但 docs/10 §3 / docs/20 §4.1:219 明确 **songs 为 Java 独占写**（Python 只读）→ **违例**：Python 写 Java 拥有表字段，会被 M-2 探针（docs/20 §4.4:259）打回。**需拍板**：内部 REST 委托 Java（推荐）或破例 Python 直写。`get_audio` 归属漏 sing_attempts（同 Q6）。
- **Q8【已核实，未落地（G9）】**：无基准脚本；人工抽检「5 首×5 句、2 人 0-100、相关 r≥0.7」（docs/06 §9.4:156）**无验证材料**。docs/19-产品定位 **P0-5:121-140** 对「0.5 音准权重与英语能力无关 + 版权死结」强质疑；§8:296 建议砍或转影子跟读（shadowing，DTW/基频可复用）→ **战略级开口，需组长拍板**「做深 / 砍转影子跟读」。

## 3. 未决缺口
| # | 缺口 | 候选 |
|---|---|---|
| G1 | 线程模型（Redis 轮询 vs arq/RQ）未拍板 | A. create_task+sing 信号量+Redis 任务态+轮询（推荐）；B. 升 arq/RQ；C. 同步等待（禁止） |
| G2 | sing 信号量不存在 | asyncio.Semaphore(1~2) 独立桶 + to_thread 包 pyin/DTW |
| G3 | SSE 心跳缺失 | 事件循环永不阻塞 + 路由补 ping |
| G4 | `readyz` 恒真 | SELECT 1 + PING + degraded |
| G5 | 音频回放 Bearer 不兼容 + get_audio 漏 sing | 签名 URL / fetch+Blob；归属并入 sing_attempts |
| G6 | `pitch_ref_status` 写归属冲突 | 内部 REST 委托 Java |
| G7 | sing 限流桶缺失 | 新增 sing 桶 + 全局预算熔断（可选） |
| G8 | 24h 音频清理任务缺失 | lifespan 周期任务 + 启动扫描 |
| G9 | 唱歌不可信/战略性存疑 | 做深（补抽检 r≥0.7）或砍转影子跟读 |
| G10 | 素材授权清单 & 唱歌错误码未登记 | 建《素材授权清单》；唱歌新码先登记 error-codes |

## 4. 结论
最高风险三件事（按威胁）：① **线程模型/信号量**（无 to_thread+信号量+异步化，--workers 1 下 180s pyin 同步阻塞全进程、对话 SSE 断）；② **音频回放鉴权**（R-5 签名 URL 未落地 + get_audio 归属漏 sing_attempts）；③ **合规承诺未兑现**（24h 定时清理缺失 + 素材授权清单缺失 + pitch_ref_status 写归属冲突）。须组长拍板：G1、G6、G9。落地顺序：先定三拍板→实现 sing 编排→修 get_audio 归属与 R-5→补定时清理与授权清单→写 pyin_rtf.py 基准+抽检→过契约三关卡→登记错误码。
