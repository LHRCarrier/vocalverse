# 英文歌打分 · 系统集成拷问报告（轴线 C：数据模型与存储）

> 完整逐问 Q/A，主报告见 `docs/singing/22-英文歌打分系统集成拷问报告.md`。

## 0. 拷问目标
以 `sing_attempts` 为核心核对字段完备性、逐句 vs 整首建模、榜单/成绩存储、埋点事件、大 JSON 存储、级联/生命周期、24h 音频清理、迁移与 SQLite 兼容；区分【事实】/【推断】。
**前置纠正**：`sing_attempts` 已建模并已入首次迁移（`practice.py:190-230` / `0001_initial_schema.py:808-866`），**非未建模**。核心结论落在「明细粒度缺项 / 榜单存储未定 / 音频回放未接线 / 版本可追溯性缺失」四处。

## 1. 问题清单
Q1 字段设计：逐句 vs 整首、独立 vs 合并、segment_breakdown/error/duration 是否存在｜Q2 榜单存哪、评分对象 user vs profile｜Q3 埋点要不要新 EventType、完成率口径｜Q4 大 JSON 存储/写入频率/索引｜Q5 级联/生命周期/lrc 重写｜Q6 24h 清理与 audio_url｜Q7 迁移与 SQLite 兼容。

## 2. 逐问结论
- **Q1【事实】**：`sing_attempts` = 一行=一次整首、独立表（不并 attempts）、逐句在 `lines` JSONB `[{seq,start_ms,end_ms,pitch_score,rhythm_score,pron_score,synced,skipped}]`、`alignment` JSONB、写归属 Python 独占。字段 `id/user_id/session_id(SET NULL)/song_id(RESTRICT,NOT NULL)/lrc_id(SET NULL)/audio_url/duration_s/overall·pitch·rhythm·pron_score(Numeric(5,2),NULL 允许)/is_complete/expected_lines/lines/alignment/created_at`（不可变行，无 updated_at）。**我提议的三项 schema 中不存在**：`segment_breakdown`（用户逐帧/逐音符音高偏差）**未存**、`error`（失败快照）**无**、`duration_ms` 实为 `duration_s`。
- **Q2【事实+推断】**：**无 scoreboard 表**（grep 无命中）；`reports` 是四指标聚合，非逐歌榜单；文档（docs/07:337）只要求「含对齐」，未要求榜单。评分对象=**user**（`user_id` FK），**非 profile**。**推断**：若做榜单→实时聚合 `sing_attempts` +补索引（不做冗余表）；不做则维持现状。
- **Q3【事实】**：`EventTypes`=10 类（base.py:179-194），无 sing 专属。唱歌完成率由 `sing_attempts.is_complete + expected_lines` 直接计数（docs/11 Q-B02），**非事件推导**。**无需新增 EventType**：复用 `recording_start/complete、score_event、practice_complete(kind=sing)`；但需补一张 M3 唱歌埋点核对表。
- **Q4【事实+推断】**：`song_pitch_refs.pitch_ref` 是**逐句**参考 F0 数组（`{f0s,notes}`，lrc_id 唯一 1:1），hop 512@16k、行级大小可控、JSONB 合理；`sing_attempts` 写入=整首 1 个 INSERT。**用户逐帧 F0 不落库**（`lines` 只存聚合分）→ 前端 D3 唱歌图（docs/06:71）画不了逐帧用户曲线。**推断**：demo 阶段不落逐帧，只画参考旋律+逐句分；若逐帧可视化确定为 M3 DoD，再于 `lines[].segment_breakdown` 按句存帧数组。索引无 `(user_id,song_id)` 组合、无 `(song_id,overall_score DESC)`。
- **Q5【事实/推断】**：song 下架不改 `sing_attempts`（内容只上下架，`song_id` RESTRICT=误删护栏）；`song_pitch_refs` 随 lrc CASCADE 重建；**lrc 重写后旧跟唱 `lrc_id` 置 SET NULL**，失去所评 LRC 版本锚点（可追溯性弱化）。建议：补 `lrc_version`/`scoring_version` 快照列，或 lrc 保留历史行；旧分一律不作废。
- **Q6【事实，确认缺口】**：`sing_attempts.audio_url`（String512, NULL）存在；24h 惰性清理（config.py:69 `audio_ttl_hours=24`、practice.py:240-243 删文件+41001；只删文件、DB 行+audio_url 保留）。**但 `get_audio`（practice.py:244-257）归属校验只查 `Attempt`/`ScenarioMessage`，漏 `SingAttempt`** → 跟唱主人回放误 403（P1）。
- **Q7【事实】**：`sing_attempts` 已入 `0001`，需无新迁移；SQLite create_all 兼容（test_models.py:38）；改约定必须先改 docs/10 §4.3 → 改 model → 新迁移（一 PR 一迁移，禁改 0001）→ alembic check 零 diff。**两处文档漂移**：docs/21:54 `sessions.kind∈practice/defense/placement` 与模型 `SessionKinds(dialog/sing/defense)` 矛盾；docs/06:187 `env.py compare_server_default=False` 与 docs/10 §7.2 不一致。

## 3. 未决缺口
| # | 缺口 | 级别 | 建议 |
|---|---|---|---|
| G-1 | `get_audio` 归属校验漏 `SingAttempt` | 高 | owned 判定补 SingAttempt（M3 唱歌前必接） |
| G-2 | 逐帧/逐音符音高偏差（segment_breakdown）未存储 | 高（待拍板） | 拍板「画逐句柱状」或「lines[].segment_breakdown 按句存帧」 |
| G-3 | 榜单/历史最佳无存储与索引 | 中 | 拍板是否做榜单；做则实时聚合+补索引 |
| G-4 | `sing_attempts` 无 `error` 失败快照 | 中 | 仿 attempts 加 `error` JSONB |
| G-5 | lrc 重写后 `lrc_id` SET NULL 失版本锚点 | 低-中 | 加 `lrc_version`/`scoring_version` 快照列或 lrc 保留历史行 |
| G-6 | M3 唱歌埋点核对表不存在 | 中 | 立项时补 |
| G-7 | docs/21:54 `sessions.kind` 与模型不符 | 低 | 同步文档 |
| G-8 | 24h「惰性清理」无定时任务，音频永久驻留 | 高（合规） | lifespan 周期清理+启动扫描（docs/19 M-04） |

## 4. 结论
`sing_attempts` 建表成功且建模正确（一行=整首、独立表、lines JSONB 逐句、写归属 Python）；四处需补（G-1 归属、G-2 逐帧、G-3 榜单、G-4/5 error/版本）。成绩属 user；无需新增唱歌 EventType；评分对象 user、非 profile。
