# 47 · 社区内容闭环（S3）实施设计

> 状态：**定稿 v2**（2026-09-09）· 上游：docs/37（S1 真实流）· docs/40（S1 计划）· docs/41（S2 关注+通知）
> v1 → v2 依据：`docs/48-社区内容S3拷问报告.md`（6 路拷问，23 条阻断级，逐条处置见其 §1）
> 本文件只覆盖 **S3 = 内容生产与消费闭环**（媒体 + 详情 + 头像 + 划词），S1/S2 既有契约不变。

## 0. 一句话

把社区从「只读流 + 纯文本发帖」补成闭环：**发帖（图文/视频）→ 详情页 → 互动/评论 → 作者头像与资料 → 社区正文划词查义**。

## 2. 边界与非目标

**做**：媒体上传（图/视频/头像）· 帖子详情页 · 媒体宫格/灯箱/播放 · 我的资料（头像）· 社区划词查义 · 删自己的帖。

**不做**（明确登记）：
- 嵌套评论楼、私信真实化、作者主页、内容审核后台（S4/M3）；
- 对象存储 S3/MinIO（沿用 docs/06 §8「本地卷 + 预留抽象」）；
- **社区批注**：划词只做「查义 / 加生词本 / 朗读」。理由——读书域批注依赖服务端权威 char offset（docs/45 §3），社区正文无该坐标系（docs/48 §5）；
- **媒体物理文件 GC**（DELETE 只软删；GC 三条件设计登记 S4，见 docs/48 B19）；
- **列表页划词**（整卡点击 × 摘要 line-clamp 互斥，docs/48 B12）；
- 通知带头像（`NotificationItem` 无 `AuthorView`，docs/48 B16）。

## 3. 数据模型

### 3.1 新表 `media_assets`（迁移 **0011**，**Python 唯一写方**）

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigserial PK | | **内部主键，不外露** |
| public_id | char(32) | NOT NULL, UNIQUE | `secrets.token_hex(16)`；**URL 只用它**（不可猜，docs/48 B2） |
| owner_id | bigint | NOT NULL FK users(id) ON DELETE CASCADE | 上传者 |
| kind | varchar(16) | NOT NULL, CHECK in ('image','video','avatar') | 用途 |
| mime_type | varchar(64) | NOT NULL | **魔数嗅探结果**，不信任客户端 header |
| size_bytes | bigint | NOT NULL, CHECK > 0 | |
| sha256 | char(64) | NOT NULL | 内容寻址（物理文件去重键） |
| storage_path | varchar(255) | NOT NULL | 相对 `media_dir`：`yyyy/mm/<sha256>.<ext>` |
| width / height | int | NULL | 客户端上报，服务端只做上界校验 |
| duration_s | numeric(8,2) | NULL | 视频时长 |
| status | varchar(16) | NOT NULL default 'ready', CHECK in ('ready','deleted') | 软删 |
| created_at / updated_at | timestamptz | NOT NULL | |

索引：
- `uq_media_public_id (public_id)` 唯一；
- **`uq_media_owner_sha (owner_id, sha256) WHERE status='ready'`** 部分唯一 ——
  同 owner 同内容只留一条 ready 行；软删后可重新入库；**不用全局唯一**
  （全局唯一 + 软删会让同内容永久传不上去，docs/48 B1）；
- `ix_media_owner_time (owner_id, created_at DESC)`（我的上传列表/配额统计）；
- `ix_media_status_time (status, created_at)`（S4 GC 扫描用）。

**物理文件**：按 `sha256` 共享一份（不同 owner 各自一行指向同一路径）。

### 3.2 迁移 0011 附带项

- `user_profiles` 补 **`uq_user_profiles_handle_lower` 唯一索引（`lower(handle)`）**；
  迁移内先对重复 handle 去重（保留最早一条，其余追加 `-<user_id>`），保证索引可建（docs/48 B17）。

### 3.3 复用列（**无新列**）

`posts.media`（jsonb，Java 写）扩展形状，**向后兼容 S1 已落库数据**：

```jsonc
{
  "type": "image" | "video",
  "items": [ { "id": "<public_id>", "url": "/api/v1/media/<public_id>", "width": 1280, "height": 720, "size": 204800, "mimeType": "image/jpeg" } ],
  "coverUrl": "/api/v1/media/<public_id>",
  "durationS": 12.3,
  "url": "…"            // 兼容字段：image = items[0].url，video = 视频地址
}
```

**兼容矩阵**（前端 `normalizeMedia()` 统一归一，docs/48 B8）：

| 来源 | 形状 | 归一后 |
|---|---|---|
| S1 种子 | `{"type":"video","duration_s":240}`（无 url） | `{type:'video', items:[], durationS:240}` → 只出渐变封面 |
| S1 真实 | `{type,url,coverUrl,durationS}` | `items=[{url}]` |
| S3 新发 | 上表完整形状 | 原样 |

`user_profiles.avatar_url`（已存在，Java 写）：本次打通读写。

## 4. 接口契约

### 4.1 Python `/api/v1/media`（新，3 ops）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/media` | multipart `file` + `kind`；返回 `MediaView` |
| GET | `/api/v1/media/{public_id}` | 二进制流（**Starlette `FileResponse`**：内置 206/416/If-Range/64KB 流式） |
| DELETE | `/api/v1/media/{public_id}` | 仅 owner（40302）；软删 |

`MediaView = { id, url, kind, mimeType, size, width, height, durationS }`（`id` = public_id）。

**上传校验（服务端唯一权威）**：
- 体积：`1KB ≤ size ≤ APP_MAX_UPLOAD_BYTES(20MB)`；视频另用 `APP_MAX_VIDEO_UPLOAD_BYTES(64MB)`；
  超限 → **41301**（拓宽既有码语义，不新增 41302，docs/48 B6）；
- 类型：**魔数嗅探**（`app/media/sniff.py`，零新依赖）：image `jpeg/png/webp/gif`、video `mp4/webm`；
  白名单外 → **41501**；
- 元数据：`width/height ≤ 8192`、`duration_s ≤ 600`、`items ≤ 9` → 越界 **42205**；
- 限流：新桶 `media`（`APP_MEDIA_RATE_PER_HOUR` 默认 60），走既有 `consume()`；
- 落盘：分块（1MB）写 uuid 临时名 → `os.replace`（Windows 被读句柄占用会 `PermissionError`，try/except + 先判存在）。

**鉴权口径**：
- 写（POST/DELETE）**必须 Bearer**；
- 读 GET **允许匿名**：原生 `<img>/<video>` 带不了 `Authorization`（docs/06 §11 同款问题），
  视频改 blob 会失去 Range 拖拽；URL 含随机 `public_id`（不可猜），`status='deleted'` → **40403**；
- 升级路径：签名 URL + `visibility` 列（S4）。

**错误码（先登记后用）**：新增 **40403**（媒体不存在/已删除）、**41501**（类型不在白名单）、
**42205**（媒体元数据非法）；越权复用 **40302**、限流复用 **42901**、超限拓宽 **41301**。

### 4.3 发帖 media 校验（Java 侧，只做契约校验，不碰文件）

1. `media` 为空 → 纯文本帖（**不强制** kind 与 media 一致——`CommunityApiTest.java:127-130` 锁定了
   「kind=video 无 media 合法」，docs/48 B11）；
2. `items` 1..9；`type='video'` 时 `items.length == 1`；
3. 每条 `url` 必须匹配配置前缀 `vocalverse.community.media-url-prefix`（默认 `/api/v1/media/`）——
   **拒绝外链**（防盗链/SSRF/存储型 XSS 面）；
4. `size/width/height/durationS` 上界与 Python 同口径；
5. 违规 → **42203**。

> 归属校验：Java 不查 Python 的 `media_assets`（跨服务读表破坏写方矩阵）。
> 归属由 `public_id` 不可猜 + Python 侧 DELETE 校验兜底；签名 URL 登记 S4（docs/48 §3-A/C）。

## 6. 并发与性能

| 面 | 风险 | 处置 |
|---|---|---|
| 上传并发 | 同内容重复文件 | 物理文件 sha256 共享 + `(owner_id,sha256) WHERE ready` 部分唯一 + `ON CONFLICT` 回读；前端串行队列（同时 ≤2 在飞） |
| 去重竞态 | 两请求同内容同时落盘 | uuid 临时名 + `os.replace` 原子改名；唯一键冲突回读已有行 |
| 大文件 | 20/64MB 全量进内存 | 分块写盘（1MB）；读取走 `FileResponse`（64KB 流式） |
| 视频 Range | 无 Range → 拖动即重下 | `FileResponse` 内置 206/416/If-Range |
| feed 放大 | 每条多图 → 请求数×N | 列表只渲 `items[0]` + `loading="lazy"` + `decoding="async"`；详情页才渲全量 |
| 详情页并发 | 详情/评论/互动并发 | `Promise.all` 并行，评论失败局部提示，详情失败整页错 |
| 头像 N+1 | feed 20 条 × 作者 | 头像 URL 随 `AuthorView` 一次带回（**不新增请求**） |
| 列表内存 | 长列表 DOM 增长 | 沿用 store `LIST_CAP=60` |

## 7. 日志与可观测

**前置**：先补 `dictConfig`（现状 `vocalverse` logger 无 handler → `logger.info` 零输出，docs/48 B4）：

```python
LOGGING = {
  "version": 1, "disable_existing_loggers": False,
  "filters": {"req": {"()": "app.core.trace.RequestIdLogFilter"}},
  "formatters": {"std": {"format": "%(asctime)s %(levelname)s [%(request_id)s] %(name)s: %(message)s"}},
  "handlers": {"console": {"class": "logging.StreamHandler", "formatter": "std", "filters": ["req"]}},
  "loggers": {"vocalverse": {"handlers": ["console"], "level": settings.log_level, "propagate": False},
              "app.media": {"handlers": ["console"], "level": settings.log_level, "propagate": True}},
}
```

| 级别 | 事件 | 字段 | 禁止 |
|---|---|---|---|
| info | 上传成功 | `request_id / user_id / media_id[:8] / kind / mime / size / sha256[:8] / dedup / elapsed_ms` | 原始文件名、二进制、完整 storage_path |
| warning | 上传被拒 | 上列 + `code / reason`（枚举：`too_large`/`bad_type`/`bad_meta`/`rate_limited`） | UA/IP（防日志洪泛放大） |
| info | GET 404（软删） | `media_id[:8] / code=40403` | — |
| info | DELETE | `user_id / media_id[:8]` | — |
| warn | Java 发帖 media 校验失败 | `user_id / reason` | 正文内容 |

- 新码一律 `BizError`（`HTTPException` 无 `code`，docs/48 B7）；
- 复用 `RequestIdFilter` 的 trace id（docs/20）；`APP_LOG_LEVEL` 死配置一并接上。

## 9. 风险与回退

| 风险 | 回退 |
|---|---|
| 上传写满磁盘 | 单文件上限 + 限流；磁盘满 → 50002 + 告警；物理回收登记 S4 |
