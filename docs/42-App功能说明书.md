# 第 1 章　产品概述与定位

## 1.1 一句话定位

VocalVerse（声语界）是一个**学英语**的 App：AI 陪你说、英文社区陪你浸润、英文歌陪你唱——把「练、说、浸、唱」统一在同一个学英语场景里。面向不同年龄段英语学习者（成年/青少年/老年演示画像），核心不是聊天机器人，而是**带教学闭环的口语训练 + 沉浸式英文内容**。

## 1.2 四大能力板块（贯穿全站）

说明：四大板块是全站统一的「学习坐标系」——「练」与「说」管口语开口、「浸」管语感与文化、「唱」是高强度跟读训练；各板块共用同一套语音管线与评分口径。

| 板块 | 定位 | 典型内容 |
| --- | --- | --- |
| 口语 · 酒馆跑团（练 · 2026-09-21 迁移） | AI 主持人（DM）+ TRPG 跑团：自由行动 + 系统掷骰 + 事实/任务/线索留痕（docs/52） | **场景卡开局**（管理端精选卡 + 关键词 LLM 现写 + 手动新建，用户卡可改名/删除）；打字或语音（ASR）+ DM 逐句 TTS；主持台可手改事实/切场景/桌骰；**右上角设置**：DM 语言中英切换 / 语音朗读开关 / 音色（预留） |
| 口语 · AI 自由说（说） | 无题卡，想聊就聊 | 麦克风或打字 → DeepSeek 实时对聊 + TTS 语音播报；MVP 无评分、不入库 |
| 英语社区（浸） | 英文氛围沉浸 | 新闻稿/教学分享/海外生活三领域，帖子 + 视频双形态，点赞/评论/支持/分享/关注 |
| 英文歌练唱（唱） | 高强度跟读训练 | 英文歌跟唱，音准/节奏/发音逐句评分（M3 做深） |
| 测评与个性化 | 定级 + 画像 | 入学测试定级 L1~L4、学习画像、推荐（M3 深化）；答辩导师（高校场景：论文答辩英文问答专项训练） |

# 第 2 章　用户体系与账号

## 2.1 启动与初始化流程

- 启动入口：Web 演示页（8088/5173）+ 移动端 App 壳（Capacitor 8，Android APK 加载 server.url 指向局域网 8088，WebView 同源加载）；PWA manifest 支持「添加到主屏幕」。
- 无游客模式：登录后进入社区首页（移动端框架）；演示账号一键登录（3 画像）。
- 就绪检查：三端健康检查（/healthz、/readyz、/actuator/health）通过后进入；/readyz 报 degraded 语义（Redis 断不拒绝启动）。

## 2.2 注册与登录

- 注册字段：username（≤64，大小写不敏感唯一）、email（可选）、password、nickname（≤64）、ageGroup（child|teen|adult|senior，默认 adult）。
- 登录：username + password → access JWT（HS256，15min）+ refresh token（httpOnly cookie，7d，轮换 + 哈希存储）；前端 401 自动静默续期。
- 忘记密码：演示环境无邮件/短信通道 → 自动创建工单由管理员处理。
- 强制勾选：用户协议、隐私政策【合规核心；对外发布前需补全文与上架页面】。

## 2.3 新用户引导与测评定级

- 入学测试：5 条固定朗读句 + 1 轮 QA（admin 题库预置、版本化，保证可复现）→ 综合分公式定级 L1~L4（≥85→L4 / 70~84→L3 / 55~69→L2 / <55→L1，阈值配置可调）。
- 年龄组只驱动 TTS 语速/音色/默认难度档（3 语速档 × 3 音色，默认按年龄预选、设置页可改）；内容只按难度档组织（4 档，非 age×level 全正交）。
- 兴趣/目标标签：user_profiles 的 goal/tags（学习目标与兴趣标签，供内容组织与推荐，M3 深化）。
- 社区展示身份：handle（@展示名，唯一）+ tint（头像色，六进制）+ LV 徽章（LV = CEFR 档 L1→LV1 … L4→LV4）。

## 2.4 账号安全（新增细化）

- 登录态：access 15min + refresh 7d 轮换（只存哈希）；多端登录管理【演示范围】。
- 账号状态：active/disabled（管理端禁用启用；只软禁用不物理删除，保留审计）。
- 敏感操作：管理端接口需 admin 角色；服务间内部 REST 走 service token（内网直连、不过网关，网关阻断 /manage/internal/）。
- 密钥纪律：JWT secret / service token 严禁默认值入库（缺失即启动失败 fail-fast）；trufflehog CI + detect-private-key pre-commit 双保险；密钥只进 .env。

# 第 3 章　发现（英语学习社区 · 核心内容社区）

说明：社区给「浸」提供英文氛围——新闻稿练阅读与语感、教学分享学学习法、海外生活风俗让语言带着文化；同时是口语练习成果的展示场（打卡卡由用户手动打卡生成）。

## 3.1 页面结构

- X 式顶栏：左 = 全局头像（点击开账户抽屉）；中 = 「社区」标题（真居中）；右 = 加好友（演示 toast）/ 写消息（→ /m/messages）。
- 领域文字标签行（X 式）：「为你推荐▾」+ 三领域 Tab（新闻稿/教学分享/海外生活）；激活 = 加粗墨色 + 下细分隔线。
- 帖子卡：作者行（头像 tint / 昵称 / handle / LV 徽章）→ 标题（可选，空则隐藏标题行）→ 正文 → 媒体（渐变占位/视频封面卡）→ X 式互动行（评论/点赞/支持/分享，千位缩写 1240→1.2k）。
- 独立打卡卡（kind=checkin）：总分 + 今日打卡次数 + 日期 mark；仅开放点赞（评论/投币/分享对打卡卡拒绝）；公开面 = {overall, practice_count}；无练习记录时只显示「今日已打卡」+ 日期。
- 打卡入口：学习页连续天数 chip → `/m/checkin` 打卡页（今日状态 + 连续天数 + 打卡按钮 + 最近记录）；今日首次进入 App 出现一次侧边提示「今日还没打卡 · 去打卡」（当天不再重复）。

## 3.2 双浏览模式

### 模式 A：为你推荐（默认）

- 全量混排（domain 为空 = 不过滤，含打卡卡的 NULL），按时间倒序 keyset 分页（@顶栏「为你推荐▾」下钻）。

### 模式 B：领域垂直流

- 三领域（news/teaching/overseas）服务端过滤，纯本领域内容，交互与推荐流一致。

## 3.3 内容消费交互

- 数据来源：S1 真实流（Java 社区接口）；演示种子 8 条（**虚构**英文品牌/人名作者，禁止真实媒体品牌与原文）。
- 评论：底部 sheet，keyset 分页；输入 ≤500（前端 maxlength 同步）；嵌套楼/回复楼字段预留（root_id 等，P1 后置）。
- 点赞/支持/分享：乐观更新 + 失败回滚 + toast；成功后按服务端返回的计数/总数对齐。
- 视频卡：点击给「视频播放 M3 上线」反馈；media onerror 降级渐变占位。

## 3.4 发帖功能

- 入口：社区组底栏中央「＋」→ /m/compose（X 式：顶栏右「发帖」蓝胶囊，空内容禁用；正文文本域 280 字计数；图片/视频/话题/表情工具行 = 演示 toast）。
- 流程：选领域（必选）→ 标题（可选，≤200）→ 正文（≤8000）→ 发布即入 flow（S1 纯文本，无媒体上传/话题/表情）。
- 开关：VOICEVERSE_COMMUNITY_POST_ENABLED（演示开启、生产默认关闭，关闭时发布 403）。
- 删除与下架：作者软删自己的帖（status=deleted）；管理员下架位（status=hidden）；统一可见谓词 status=visible。
- 打卡由用户手动触发（2026-09-21 改版）：`POST /api/v1/checkin` 聚合当日 dialog 练习后经内部 REST /internal/checkin 委托 Java 物化进 posts（幂等键 practice_date，同日重复打卡只刷新快照；练习收尾不再自动打卡）。

# 第 4 章　内容生产与媒体处理（新增·重点）

这是产品与工程的核心底层：没有这一层，用户「录不进去、发不出来」。VocalVerse 最复杂的链路是**语音/音频**（4.1），社区图片/视频按最小实现（4.2）。

## 4.1 语音音频处理链路（核心·重点）

- 客户端录音：MediaRecorder（audio/webm;codecs=opus，失败回退其他 mime）；v0 录完再传（非流式分片）；单次 ≤60s、唱歌 ≤180s、体积 ≤20MB（超限 413）。
- 服务端处理：ffmpeg 转码 16k wav（asyncio 子进程 + 15s 超时）→ faster-whisper small int8 CPU（信号量 2，to_thread）+ Silero VAD → ASR 文本 + 词级时间戳（喂流利度特征与词级错误定位）。
- 评分与回复：讯飞 ISE 发音/流利度（16k wav、信号量 2、整句批量）→ DeepSeek LLM 流式回复（句子级切分）→ edge-tts 逐句 TTS（Azure 备胎；开场/常用句预合成）→ SSE 推 text_delta（字幕）+ audio_chunk（音频）。
- 播放：**音频为时间轴权威、文本降级为字幕**；前端音频队列顺序播放（preload=auto）；score_delta 迟到 ≤3s 按 turn_index 回填徽章，再迟标记「未评测」。
- 性能口径（POC 实测 2026-09-01）：whisper small/int8/CPU RTF 0.328（短句）/0.258（长句）；edge-tts 单句 mean 1.34s → 流式首声目标 3~6s。
- 模型与缓存：HF 模型缓存挂卷（避免重复下载 ~500MB）；lifespan 启动预热（失败告警不阻塞）；HF 被墙一律本地缓存（HF_HOME=仓库 data/models + HF_HUB_OFFLINE=1）。
- 存储与合规：原始音频存本地卷 ./data/audio（多容器共享；生产预留 S3/MinIO，AudioStore 端口）；**24h 惰性过期**，只存评分/转写/元数据；GET /audio/{id} 回放鉴权（验归属 + 410 过期码，不与静态目录混用）。

## 4.2 图片/视频处理链路（社区·最小实现）

- S1 发帖纯文本：无图片/视频上传与转码（**【不做】**清单）；posts.media 字段集预留（type/url/coverUrl/duration_s（秒）/size/mimeType），渐变占位由前端组件层渲染（不入库 url）。
- 视频播放器：S3 后置【排期中】；视频卡点击给「M3 上线」反馈。
- 【远期】图片多规格 + 对象存储 + 视频分片上传 + 异步转码（本地模拟/云 + 回调验签）+ 先审后发 —— 企业级模板见 docs/38 §6；本期明确不做：云转码多档/HLS/CDN 签名（AudioStore 抽象预留已够）。

## 4.3 存储与分发架构

| 组件 | 作用 |
| --- | --- |
| 本地音频卷 ./data/audio | 原始音频临时存储（24h 惰性过期）；演示/测试环境多容器共享 |
| hf-cache 卷 | whisper 模型缓存（启动预热，避免重复下载 ~500MB） |
| 对象存储（S3/MinIO） | 【预留】AudioStore 端口抽象：生产环境的音频/媒体存储（本期不引入） |
| CDN | 【远期】社区图片/视频分发（本期渐变占位，无真实媒体 URL） |

| 分享 share | 一人一帖一次（幂等） | share_count +1；入互动时序（转发数语义点击不加计） |
| 关注 follow | 关注/取关（物理删行，幂等）；自关注 42203 | follows 唯一约束；关注流/推荐关注/互关标识（youFollowBack） |
| 打卡卡专项 | 仅开放点赞（评论/投币/分享对 kind=checkin 拒绝） | 公开面 {overall, practice_count}（隐私收敛） |

## 5.2 关注与粉丝

- 关注/取关、我关注的人（followedAt + youFollowBack 互关）、推荐关注（排除自己 + followed 标记）。
- 关注流：只含被关注作者的新帖（keyset；未关注任何人 → 空结果不跑 SQL）。
- 关注数/粉丝数等社交化统计：【排期中】P2 登记。

## 5.3 计数一致性（新增·工程要点）

- 冗余计数列（like/coin/comment/share_count）与互动行写入/删除放**同一事务**原子增减；自减用 GREATEST(x-1, 0) 防并发多减。
- 防重复：唯一约束兜底——likes (post_id, liker_id)、interactions (actor_id, post_id, action)、follows (follower_id, followee_id)；重复请求幂等返回当前态，不双计。
- 统一可见谓词：status=visible 一处定义（Java），feed/详情/评论/计数查询共用；非 visible 内容的互动端点返回 404。
- 防刷：发帖开关默认关闭 + 软删/下架位；按动作维度限流【登记】；机器行为识别【远期】。
- 互动通知：由 post_interactions + post_comments **派生**（不建通知表），mergeKey = (postId, action, 当日 UTC) 聚合「张三 等 N 人赞了你的内容《…》」；评论逐条。

# 第 6 章　数据推流与推荐系统（新增·核心算法）

## 10.2 语音与评测引擎（计算引擎·新增·要点）

- ASR：faster-whisper small int8 CPU + Silero VAD（RTF 实测 0.26~0.33）；词级时间戳出流利度特征（wpm / articulation_rate / 停顿统计 / pause_ratio）。
- 发音/流利度：讯飞 ISE（权威分，并发信号量 2，免费额度监控）；语法：DeepSeek 判定（0-100 + 错误类型 + 改法；不稳定则回退「砍语法项、口径改发音/流利度/完整度」）。
- 综合分 S = 0.4·发音 + 0.3·语法 + 0.3·流利度（**口径唯一归 Python**，Java 不复制公式）；内容相关度/覆盖度/语义子分（content/vocab）**不进量化总分**。
- 语言点覆盖度：规则通道（归一化子串/词序匹配，权威）+ LLM 兜底（语义等价）；命中双态「自然达意/需纠错」；跟读/提示/示范轮不计（防刷命中）；覆盖度 = 教学覆盖信号，不是能力分。
- 唱歌：librosa pyin（说话 75~300Hz、唱歌 65~800Hz；frame 2048/hop 512）；先整体 BPM 粗对齐再子序列 DTW 精对齐（Sakoe-Chiba ≤10%）；人工抽检 5 首 × 5 句、2 人打分与算法相关 r≥0.7 出验证报告。
- LLM = DeepSeek：**静态 system**（角色设定 + 输出契约 + 前缀缓存完整匹配）+ user 尾部 [context]（全部动态：难度/语料提示/画像行/已命中表达/3 轮滚动摘要）；[-META-] 尾部契约（语法分/教练笔记/命中/收尾标记），流式未输出 META 时后置补偿调用（温度 0.2）；注入隔离见第 15 章。
- wav2vec2 自研评分头（门禁化）：冻结 backbone 只训练轻量评分头（speechocean762 约 5k 条 CC-BY，GPU 5~10h）；验证集 r≥0.8 才切换，否则讯飞基线保底（「基线保底 + 自研探索性说明」）。
- 降级矩阵：Redis 断 → 进程内 TTL + /readyz 报 degraded；讯飞断 → 徽章「未评测」对话继续；LLM 断 → 备用台词缓存（预生成 2~3 句通用回应）；edge-tts 断 → 无声字幕继续；whisper 排队 >8s → 救场 L1。

## 10.3 工具通用功能

- 报告：报告页最小集（总分卡/覆盖度三栏/词级错误表/建议/再练）+ 答辩报告（每题卡片/薄弱类型/3 条建议）。

# 第 18 章　数据统计与埋点（新增）

## 18.1 埋点采集

- 15 类事件（见 6.4）；服务端落库 events 表（Python 独占写；client_event_id 唯一索引幂等）；维度：年龄组/水平档/场景/歌曲/渠道/时间。

## 18.2 核心指标（四项检查点 · docs/06 §9.1）

| 指标 | 定义 |
| --- | --- |
| 点击率 CTR | 推荐内容被点击会话数（去重）/ 推荐内容曝光会话数；窗口 = 曝光后 30min |
| 完成率 | 口语 = 单次对话达 5 轮或 2min 以上；唱歌 = 整首逐句评分结束；答辩 = 答满设定题数（会话快照）或 ≥2min；= 完成单元数 / 发起单元数（会话级去重） |
| 互动率 | 会话内互动率 = 用户主动发消息轮数 / 会话分配轮数；**救援轮（hint/自动示范/AI 代说）同时从分子+分母剔除**；答辩会话通用互动率 = N/A，专属「回答率」= 有效作答轮数 / 提问轮数 |
| 跳出率 | 进入场景/歌曲页后 30s 内无任何有效事件记 1 跳；= 跳出会话 / 进入会话 |

## 18.3 数据流与用途

- events → reports（Python 独占写、upsert 语义）→ Java 看板只读（CQRS 轻量形态）；「先 commit 后 put」会话态写入约定。
- 用途：一喂推荐算法，二供运营决策，三做异常监控（如流式首声/p95 超预算告警）。
