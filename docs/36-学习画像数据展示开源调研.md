# 36 · 学习画像数据展示开源调研（To C 向）

> 定位：学习主页（`/m/learn`）「用户学习画像」作为**主要展示焦点**的前置调研——
> 要回答三个问题：**①展示哪些数据 ②数据怎么展示 ③能否让用户扫一眼就明白大量信息**。
> 调研范围：**面向终端用户自己看**（To C）的开源项目（仪表盘/统计站/游戏化追踪），排除 To B 管理后台与分析师看板。
> 结论先行：**DuoDash（Duolingo 数据仪表盘）是最贴合的参照物**；其次参考 GitHubPoster 的年度热力图、
> Duo-Strength 的技能强度条、Skill Quest 的游戏化数字卡。全部候选已核验许可与维护状态（见 §2 表）。

## 1. 一句话结论

| 问题 | 答案（调研所得） |
|---|---|
| 展示哪些数据 | **三层**：① 状态层（等级/XP/连胜/总时长）② 过程层（年度热力图、周趋势、练习量）③ 资产层（技能/场景掌握度、薄弱点、成就徽章） |
| 怎么展示 | **四种信息块**：大数字卡（StatCard）· 年度热力图（GitHub 贡献图式）· 技能强度条 · 趋势迷你图；辅以「AI 一句话点评」把数字翻译成人话 |
| 扫一眼能明白吗 | **能**——关键是「**一屏一个视角**」：热力图一眼看全年坚持度，强度条一眼看全面掌握度；每张卡只回答一个问题，多卡并列构成完整画像 |

## 3. 四个焦点模式的详细解剖

### 3.1 DuoDash：To C 学习仪表盘的「标准结构」（首选参照）

自上而下的信息分层（每层一个视角，扫一眼成立）：

1. **头部**：用户信息 + 段位/LV + 总 XP 进度条——「我是谁、我在哪一级」；
2. **今日概览（4 张 StatCard）**：今日 XP / 今日课程数 / 连胜天数 / 学习分钟——「今天怎么样」；
3. **7 天趋势面积图**：XP + 时长双序列，渐变填充——「最近一周是升是降」；
4. **年度热力图**：GitHub 贡献图式，按年切换；窄屏自动切上下半年——「一整年坚持得怎样」；
5. **成就系统（20 枚徽章）**：连胜/单日 XP/累计天数/总 XP 四维度，含进度详情——「我解锁了什么」；
6. **课程列表**：每门课一条 XP 条——「每门课（技能）各自的深度」；
7. **AI 点评**：基于数据生成个性化人话总结 + **分享卡片**（连胜周报/成就/经验突破三模板，PNG 导出）——「数据 → 人话 → 社交传播」。

> 对我们的启发：VocalVerse 学习页（390px 移动真形态）按同样分层裁剪——
> 主卡（LV+XP 条）→ 今日四数卡 → 周趋势 → 年度热力图（折叠/横滑）→ 场景掌握度条 → 薄弱点速览 → AI 一句话点评。

### 3.2 GitHubPoster：全年热力图 = 「一眼坚持度」

- 核心概念：**把一年 365 天压成一个方块矩阵**（53 周 × 7 天），颜色深浅 = 当日学习量；
  扫一眼得到「连续性/高峰期/断档」三个信息——这是**信息密度最高的单图**；
- 已支持 **duolingo、扇贝、不背单词、开言英语、微信读书、开心词场**等学习数据源——说明「学习行为 → 热力图」是成熟且被验证的范式；
- 变体：Skyline（立体年份图）、Circular（环形）、`--with-animation`（动画）；
- 技术形态：Python 生成 SVG，`github_poster` pip 包；我们前端不引入他包，**自绘热力图**（53×7 网格，Vue+CSS Grid / SVG 均可，无需第三方图表库）。

### 3.3 Duo-Strength：技能强度条 = 「一眼全面掌握度」

- 原始 Duolingo 有「技能 strength」概念（距腐烂的百分比），官方隐藏后社区做了扩展补回；
- 展示：**每技能一条水平条**（0-100），颜色分段（绿→黄→红），一屏内 N 条并列；
- 对我们的映射：**8 套场景 + 语言点覆盖度**（`user_corpus_mastery` 已有数据）→ 每场景一条掌握度条；
  或「发音/流利度/语法」三维各一条 → 一眼看出长短板。
  这比雷达图更易读（移动端雷达图 5 边形以上就难扫读了，docs/13 也倾向简洁优先）。

### 3.4 Skill Quest / MakerSkillTree：游戏化数字卡 + 技能树形态

- Dashboard = 4 张大数字卡（Skill Trees 4 / Completed Skills 239 / Day Streak 1 / Total XP 2390）+ 进度条；
  每个卡 = 1 个数字 + 1 个语义标签 + 1 条进度——信息量极低但**绝对清晰**；
- 技能树形态：把「技能 → 前置节点 → 分支」画成 RPG 技能树（SVG 模板）；
  对 VocalVerse 偏重——8 场景是平行结构，没有严格前置依赖，**技能树形态不建议**（过度设计），
  但「成就/徽章 = 里程碑奖励」的思路可保留。

## 4. 数据可用性盘点（VocalVerse 真实数据 ↔ 展示项）

> 关键结论：**画像所需数据 90% 已经在库**（attempts 三维评分 + 词级错误 + wpm + 语言点覆盖 + 水平档），
> 无需新建表，只需一个**聚合查询层**（学习画像 API）+ 前端展示。以下为映射：

| 展示项 | 数据源（现有） | 状态 |
|---|---|---|
| 等级 / XP / 进度条 | `stores/progress.ts`（LV1~5 + xp，演示 localStorage） | ✅ 前端已真实（M3 后端化经验规则） |
| 水平档 CEFR | `placements`（入学测试 overall_score/level）+ `user_skill_state.est_level`（动态档 EWMA + 滞回 + 置信度） | ✅ 后端已真实 |
| 发音/流利度/语法分 | `attempts`（pron_score/flu_score/gram_score）——每次练习落库 | ✅ 后端已真实 |
| 词级错误/薄弱音素 | `attempts.details.word_level[]`（error_type: mispronunciation/stress/intonation + score） | ✅ 后端已真实（讯飞词级+fluency.py 特征） |
| WPM / 停顿特征 | `attempts.details.fluency`（wpm/pause_ratio/pause_count） | ✅ 后端已真实 |
| 场景/语言点覆盖度 | `user_corpus_mastery`（docs/24 学习者画像域）+ `sessions.scene_id` | ✅ 后端已真实（M3 前端接入） |
| 连续天数 / 打卡 | `attempts.created_at` 按日聚合（或埋点 events） | ✅ 可聚合，**无表可造** |
| 每周练习时长 | sessions/attempts 时间戳聚合 | ✅ 可聚合 |
| 唱歌维度（音准/节奏） | 唱歌评分（M3 进行中） | ⏳ M3 |
| AI 一句话点评 | 已有 DeepSeek 管线 + learner.py 画像注入（白名单聚合） | ✅ 后端现成，前端接一眼即可 |

## 5. 落地建议（学习页 = 画像焦点 · 供组长拍板）

### 5.1 信息架构（390px 真形态，从上到下）

1. **画像主卡**（保留现有）：LV 黑徽章 + 等级名 + 金色 XP 条 + 连续天数 🔥 + 本周时长 ⏱ ——「我是谁、几何级」；
2. **今日四数卡**（新）：今日练习数 / 今日时长 / 连续天数 / 总 XP——每卡一数一标签（DuoDash StatCard 式）；
3. **年度热力图**（新·主要焦点）：53×7 网格自绘（CSS Grid，零依赖），点按某日看当日数据；宽度不够自动切半年视图；
4. **周趋势迷你图**（升级现有迷你柱）：最近 7 天评分（发音/流利度任选或叠加）；
5. **场景掌握度条**（新）：8 场景一行一条强度条（Duo-Strength 式），绿→黄→红分段；
6. **薄弱点速览**（保留现有）：薄弱音素 / 高频错误词 chips +「去练」跳场景；
7. **AI 一句话点评**（新·可选 M3）：`learner.py` 现有聚合 → 一句话人话（复用 DeepSeek，缓存 15min）；
8. 底部注：画像数据 M3 真实化说明（沿用现有口径）。

### 5.2 技术要点（零新增依赖）

- 热力图/趋势图**全部自绘**：CSS Grid + 少量 SVG，不引 echarts/recharts（docs/13 动效可视化栈口径）；
- 聚合 API：Python 侧 `GET /api/v1/learner/profile`（test-only 或正式路由按评审），
  复用 `learner.py`/skill service 的聚合逻辑，**只读不建表**（docs/24 ③ 画像派生不建表口径）；
- 演示帧策略：接口未就绪前用演示数据（现 files 内 `weekTrend` 等改为结构化 demo 常量），页面注明。

### 5.3 明确**不做**（防过度设计）

- ❌ 技能树 RPG 形态（8 场景无前置依赖，画树是过度设计）；
- ❌ 雷达图做 5+ 维（移动端难扫读）；
- ❌ 引入第三方图表库（自绘足够，且避免许可/体积风险）；
- ❌ 成就徽章墙本轮不做（M3 有 20 枚量级再议，避免「徽章为做而做」）。
