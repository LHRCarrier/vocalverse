## 1. 用户旅程地图：新用户首次完整练习一轮

情绪曲线记号：`↓` 挫败 · `→` 平静 · `↑` 愉悦

### 阶段 A｜落地（0~15 秒）

- **用户目标**：搞清楚"这是什么，我能得到什么"。
- **当前设计**：`router/index.ts:16` 把 `/` 重定向到 `/demo`。用户看到的第一屏标题是「VocalVerse 声语界 · **框架骨架**」，副标题「M1 脚手架：三服务连通性 + 录音组件验证（docs/06 第 16 章）」，正文是 Python/Java 两个服务的健康状态（`DemoView.vue:59-69`）。
- **痛点**：产品的门面是一个**给开发者看的联调页**。没有一句话价值主张、没有"开始练习"主 CTA、没有任何示例对话截图或试听。顶栏（`UserLayout.vue:11-18`）把「骨架演示 / 唱吧 (M3) / 报表 (M3)」和真实功能并列，点进去是 `PlaceholderView`。更要命的是这页有个「开始录音」按钮，文案写「录音中…（**6 秒**后自动停止）」（`DemoView.vue:31`），而 `recorder.start()` 的默认值是 `MAX_RECORD_MS = 60_000`（`recorder.ts:7,33`）——**用户被承诺 6 秒，实际要举着手机干等 60 秒**，且此页停止按钮被 `:disabled="recordState === 'recording'"` 禁用（`DemoView.vue:84`）。第一印象直接是"这东西坏了"。
- **情绪**：`→` 起步 → `↓↓` 60 秒静默后崩塌。

### 阶段 B｜登录（15~60 秒）

- **用户目标**：进去。
- **当前设计**：点「练习」→ 路由守卫 `requiresAuth` 无 token → `/login`。登录页底部写着「还没有账号？**请先启动 Java 服务后注册**（M2 认证已接入）」（`LoginView.vue:81`）。
- **痛点**：**全站没有任何注册界面**。`stores/auth.ts:63` 有 `register()`，Java 也有 `/auth/register`（`api/specs/java-openapi.json:36`），但没有一个 `.vue` 调用它（全仓 grep `register` 仅命中 store 与生成类型）。新用户的唯一出路是猜到 `demoadult / demo123456`，或点页面上那三个演示账号胶囊。对真实用户，这是**漏斗的物理终点**。
- **情绪**：`↓`（有演示账号按钮 → `→`，但"我在用别人的账号"的疏离感全程留存）。

### 阶段 C｜选场景（60~90 秒）

- **用户目标**：挑一个不难的。
- **当前设计**：`PracticeHubView.vue` 4~8 张卡：标题、描述、`难度 L1 入门`、`约 6 轮 · 目标表达 5 个 · 含发音/语法/流利度评分`。
- **痛点**：① 通篇是**系统术语**（"目标表达 5 个""覆盖度"），没有用户语言的收益承诺（"3 分钟，学会在咖啡店点单"）；② 没有时长承诺，只有"轮"这个用户不理解的单位；③ 没有难度自测/推荐——`auth.me.level` 拿到了却只在欢迎语里当装饰（`PracticeHubView.vue:46`），**入学测试的档位没有对场景卡做任何过滤或推荐**；④ 空态文案把运维命令甩给用户：「（无后端时请先 seed：`uv run python -m app.db.seed`）」（`PracticeHubView.vue:52`）。
- **情绪**：`→`。

### 阶段 D｜进入对话 · 开场白（90~110 秒）

- **用户目标**：听懂 AI 说了什么，知道该怎么回。
- **当前设计**：`PracticeView.boot()` 依次 `fetchScenarios()` → `createSession()` → push 开场气泡 → `playTts(opening_line)` → `phase='ready'` → `armRescueTimer()`。
- **痛点**：① **没有加载骨架**，`phase='loading'` 期间界面是一个空壳，标题显示「场景 · 加载中…」；② 开场白 TTS 走 `playTts` → `audio.play()`，失败被 `catch { /* 无声字幕继续 */ }` **完全静默吞掉**（`PracticeView.vue:112-122`）——用户刷新页面或直接粘贴链接进入时（无 user activation），浏览器阻止自动播放，用户看到英文字幕但**一个字也听不到，且没有任何"点击播放"补救入口**；③ 没有任何"这轮我该说什么"的脚手架，只有一个 🎙 圆钮；④ 8 秒后 `armRescueTimer` 弹出提示卡，取的是 `firstCorpusPhrase()`——**永远是语料表第一条，与 AI 刚说的话无关**，而且 `split('|')[0]` 把中文释义丢了（`PracticeView.vue:105-110`），于是屏幕上出现一句带占位括号的英文：`I'd like a (coffee), please.`（语料原文见 `data/seed/scenarios.json`）。docs/14 §2.3 明确要求 L1 是"参考句 **+ 中文释义**"，实现只兑现了一半，还多了个用户看不懂的 `( )`。
- **情绪**：`→`（听不到声音时直接 `↓`）。

### 阶段 E｜开口（110~130 秒）★ 决定生死的 20 秒

- **用户目标**：说一句英语，不出丑。
- **当前设计**：点 🎙 → `startRecording()` → `track('recording_start')` → `recorder.start(15_000)`。按钮切成红色「■」，文案「录音中…（≤15s 自动停止）」。
- **痛点（本报告最重要的一条）**：**这个「■」是假的**。`startRecording()` 的守卫是 `if (phase.value !== 'ready') return`，而录音期间 `phase` 仍然是 `'ready'`（`phase` 只在 `sendTurn` 里才变 `'busy'`），于是再次点击会进入 `recorder.start()`，被 `if (this.state === 'recording') return`（`recorder.ts:42`）无声吞掉。全仓 `recorder.stop()` 只出现在 `DemoView.vue:28`，三个真实业务页**一次都没调用**。结论：**用户说完 "Yes, please."（1.2 秒）之后，必须对着屏幕干等 13.8 秒**，看着一个假的停止按钮，直到 `setTimeout(() => this.stop(), maxMs)`（`recorder.ts:66`）替他做主。`PlacementView.startRecord`（`if (recording.value) return`）与 `DefenseView.startAnswer` 同病。
- 附带伤害：波形动画是 `useP5Wave` 的**装饰性正弦小球**（`useP5Wave.ts:35-45`，`p.frameCount` 驱动），**与麦克风输入完全无关**。用户没在说话时它照样欢快地跳——用户无法据此判断"麦克风到底有没有收到我的声音"。
- **情绪**：`↓↓`（第 1 轮忍了，第 3 轮开始怀疑产品坏了，第 5 轮关页面）。

### 阶段 F｜等待 AI（130~145 秒）

- **用户目标**：知道系统在干什么、还要多久。
- **当前设计**：`sendTurn()` 把 `phase` 置 `'busy'`，push 一个**空的 assistant 气泡**，模板渲染成 `{{ m.text || '…' }}`（`PracticeView.vue:256`）。然后等 SSE。
- **痛点**：① 整个等待期用户看到的全部反馈就是一个灰色的「…」；没有"正在识别你的发音…"→"AI 正在思考…"的分段状态，没有进度，没有取消。② 服务端第一个事件 `turn_start` 是在 **ASR 跑完之后**才 yield 的（`orchestrator.py:141-156`），按 docs/14 §10 记录的 whisper RTF 0.328 实测，15 秒音频约 3~5 秒**全静默**。③ `openSseFetch` 的心跳注释行有解析（`sse.ts:27`），但服务端 `event_stream()` 从不发 `: ping`（`routes/practice.py:155-168`）——docs/14 §3.3 承诺的"≤30s 心跳"没有落地。④ **`onClose` 是空函数**（`api/practice.ts:79`）：只要流在没发出 `turn_end` 的情况下正常关闭（nginx 超时、服务重启、后端生成器提前 return），`phase` 就**永久卡在 `'busy'`**，录音按钮永久 `disabled`，页面既没错误也没出路。`useTurnTimers.ts` 的注释写着"30s 跳出"，**代码里根本没有这个计时器**。
- **情绪**：`↓`。

### 阶段 G｜AI 回应（145~160 秒）

- **用户目标**：听懂反馈，知道自己说得对不对。
- **当前设计**：`text_delta` 逐字上屏 → `audio_chunk` 入队播放 → `meta_block` 落教练笔记 → `score_delta` 更新评分卡。
- **痛点**：① **用户自己说的话永远不会出现在屏幕上**。`events.py` / `sse-types.ts` 的事件表里**没有任何 transcript 字段**，`PracticeView` 也只 push `role: 'assistant'` 的气泡（第 83、163 行）——`Bubble` 类型里的 `'user'` 分支与模板里的用户气泡样式（第 247-254 行）是**永远走不到的死代码**。用户被扣了分却不知道 ASR 把他的 "I'd like a latte" 听成了什么，无法自我诊断，也无法申诉。这是口语产品的元罪。② **字幕先到、声音后到**：docs/14 §3.2 白纸黑字要求"第一句 TTS 在首句文本到达后立即启动（不等整段生成）"，但 `orchestrator.py` 的 TTS 循环（第 276-282 行）位于 LLM 流**完全消费完之后**，且逐句 `await` 串行。按 docs/14 §10 的 POC-1 实测（单句 1.34s、3 句串行 4.12s），首声实际 ≈ ASR 3~5s + LLM 整段 2~4s + TTS 1.3~4.1s，**7~13 秒**，远超"流式首声 3~6s"的对外口径；同时"音频为时间轴权威"的设计前提在实现上已被打破。③ 评分卡的容器 `<NCard>` **在 `PracticeView.vue:9` 根本没有 import**（只 import 了 `NButton, NProgress, NTag`），Vue 解析不到组件，标题「本句评分」与卡片外框全部丢失、控制台刷 `Failed to resolve component: NCard`——核心页最重要的反馈模块以裸元素形态呈现。④ 评分**没有关联到具体那一句**：`lastScore` 是全局单值，本轮没评上分时旧数值原地不动，只把圆环标签改成「未评测」（第 197-207、307 行），三根进度条仍展示**上一轮的数字**。
- **情绪**：`→`（有声音、有绿色徽章时会有短暂 `↑`，但"它到底听懂了我什么"的疑云不散）。

### 阶段 H｜结束与报告（第 8 轮 / 主动结束）

- **用户目标**：拿到"我进步了吗、下一步练什么"。
- **当前设计**：`session_end` → 1.2 秒后跳 `/report/:id`。报告 = 三个数字卡 + 覆盖度三栏 + 建议列表 + 一行统计。
- **痛点**：① 「结束并查看报告」按钮**无二次确认**（`PracticeView.vue:332`），且紧挨着「继续对话」，一次误触不可逆地关单；② 报告的**「📌 待练」栏永远是空的**——`service.py:214` 的 `_coverage_summary()` 里 `"to_practice": []` 是硬编码，于是 5 条目标语料里"还没练到的"永远不会告诉用户，`ReportView` 只好显示兜底文案「尝试用不同的目标表达再练一次」。docs/14 §1 的答辩口径"一张报告告诉你这节课的语言点覆盖了哪些、**还剩哪些**"，实现上只兑现了前半句；③ docs/14 §5 的 W3 最小集要求"三维雷达（ECharts）+ **词级错误表（词/类型/改法/示范）**"，实现里雷达没有、词级错误表没有——`attempts.details.word_level` 数据采到了（`orchestrator.py:342`）却**没有任何界面消费它**；④ 「再练一次 →」只是 `router.push('/practice')`（`ReportView.vue:38`），并没有 docs/14 §5 说的"同场景进阶套 / 抽未命中语料"。
- **情绪**：`→` 然后 `…`（无高潮、无下一步）。

### 阶段 I｜第二天

- **当前设计**：无推送、无打卡、无连续天数、无历史趋势（`/stats` 是 `PlaceholderView`）、无目标设定。`events.ts` 定义了 `page_view` 事件，但**全仓没有任何一个 view 调用它**——于是 docs/14 §6.3 定义的"跳出率 = 进页 30s 无有效事件"这一指标**从数据源头就算不出来**。
- **情绪**：`→` 归零。用户没有任何回来的理由。

## 2. 体验问题清单

### P0（不修就不要给真实用户测）

**P0-1 「停止录音」是假按钮，每一轮都被强制占用 15 秒**
- 触发：任何一次录音，三个页面全中（`PracticeView.startRecording` / `PlacementView.startRecord` / `DefenseView.startAnswer` 的早退守卫 + `recorder.ts:42`；`recorder.stop()` 仅 `DemoView` 调用）。
- 用户感受："我说完了它不理我 / 这按钮点了没反应 / 我是不是又说错了"。8 轮 × 15s = **2 分钟纯尬等**。同时 15s 上限对答辩题**又太短**——`DefenseView` 用同一个 `15_000` 回答 "Why did you choose this method?" 是不可能完成的任务，被截断还没有任何提示。
- 改法：见 §3.1。

**P0-2 用户永远看不到"系统听见了什么"**
- 触发：每一轮。SSE 协议无 transcript（`events.py` / `sse-types.ts`），前端只渲染 AI 气泡。
- 用户感受：口语学习者最需要的确认信号（"它听懂我了吗"）完全缺席；发音分低时无法归因；ASR 把 "coffee" 听成 "copy" 时用户只会认为**是自己太差**。这直接放大开口羞耻。
- 改法：SSE 新增 `asr_text {type, turn_index, text, confidence}`，在 `turn_start` 之后立即下发；前端 push `role:'user'` 气泡（模板样式已经写好了，白等着）。

**P0-3 麦克风被拒 = 页面变砖，且没人告诉用户怎么办**
- 触发：首次点录音时点了"阻止"，或在 `http://<LAN-IP>:8088` 打开（非安全上下文时 `navigator.mediaDevices` 为 `undefined`，抛 `TypeError`）。
- 现状：`PlacementView.startRecord` 与 `DefenseView.startAnswer` **没有 try/catch**，`recording.value = true` 已经先执行了——Promise 静默 reject，按钮永远停在「■」，之后每次点击都被 `if (recording.value) return` 吃掉，**页面彻底失能且零提示**。`PracticeView` 有 catch，但把浏览器原文（`Permission denied`）直接塞进 12px 红字条。
- 改法：见 §3.4 的权限文案与"检测不到麦克风"的兜底面板。

**P0-4 错误文案是给后端看的，不是给人看的**
- 证据链：`main.py` 只注册了 `BizError` 与 `RequestValidationError` 两个 handler，**没有 `HTTPException` handler** → FastAPI 默认返回 `{"detail": ...}` → `client.ts:68` 读 `body.message`（不存在）→ 抛出 `` `HTTP ${resp.status}` ``。于是**限流时用户看到的字面文案就是「HTTP 429」**，入学测试题不存在是「HTTP 404」。走 `BizError` 的那一半也没好到哪去：`session state=completed`、`stale turn`、`audio too large`、`session not found or expired`，以及前端自制的「管线提示：asr_failed」（`PracticeView.vue:218`）。
- 用户感受：不知道发生了什么，更不知道能做什么，直接关页面。
- 改法：见 §3.4 错误文案对照表。

**P0-5 流断了没人管：`phase` 永久卡死在 busy**
- 触发：网络抖动、后端重启、nginx 读超时、生成器异常提前结束。
- 现状：`streamTurn` 传入的 `onClose: () => undefined`（`api/practice.ts:79`）；`turn_end` 没来 → `phase` 不回 `'ready'` → 录音按钮 `:disabled` 永久为真 → 页面只剩一个「…」气泡。`useTurnTimers` 注释里的"30s 跳出"从未实现，服务端也没有心跳。
- 改法：见 §3.3 的看门狗 + 重试卡片。

**P0-6 首声延迟超出设计口径 2 倍，等待期毫无掩护**
- 证据：`orchestrator.py:276-282` 的逐句 TTS 在 LLM 流结束后才开始且串行 `await`，违反 docs/14 §3.2"第一句 TTS 在首句文本到达后立即启动"。叠加 ASR 3~5s（docs/14 §10 POC-3）与 TTS 1.34s/句（POC-1），**首声 7~13s**。
- 用户感受：对话变成"发微信等回复"，沉浸感归零。
- 改法：见 §3.3（工程侧首句提前 + 交互侧三段式状态 + 角色"思考中"动效 + 预置口头语音频）。

**P0-7 全链路没有任何"开口羞耻"缓解机制**
- 检查结论：全仓**不存在**热身模式、试音、只听模式、跟读示范、"先看再说"、隐藏评分、匿名/静音练习、失败重说等机制中的**任何一个**。用户的第一次交互就是：陌生外国人开场 → 一个红色录音钮 → 15 秒硬录 → 打三个分数。
- 佐证细节：入学测试第 6 题 `Tell me something about yourself.`（`seed.py:61-67`）**没有任何提示**——服务端 `/placement/questions` 明明返回了 `reference_answer`（`placement.py:54`），前端的 `interface Q`（`PlacementView.vue:14-18`）**连这个字段都没定义**，参考答案被整条丢弃。一个 L1 用户面对全英文开放题、15 秒硬录、无参考、无重录（`upload()` 成功即 `index.value += 1`，`PlacementView.vue:86`），**一次口误就永久写进他的水平档**。
- 改法：见 §3.2（完整的"敢开口"设计包）。

**P0-8 学习闭环断裂：练完不知道下一步，明天没有理由回来**

4. **操作复杂度**：儿童与老人最需要的"大按钮 + 一步一提示 + 语音口令"全无；15 秒硬录对反应慢的用户是灾难（他们往往在第 12 秒才开口，然后被截断）。
5. **无语音引导**：所有引导都是中文小字，没有一句 TTS 语音提示（"轮到你说啦，点绿色大按钮"）。

## 3. 交互改进建议（可直接指导前端实现）

### 3.1 录音控件重做（P0-1 / P0-3）

```
状态机：idle → requesting(权限) → armed(试音) → recording → confirming(可回放/重录) → uploading
```

1. **点按 = 开始，再点 = 停止**：`PracticeView.startRecording()` 改为 `toggleRecording()`，录音中调用 `recorder.stop()`；`recorder.ts` 暴露 `stop()` 已具备，只需在三个 View 接上。
2. **加静音自动收尾（VAD 轻量版）**：`AnalyserNode` 计算 RMS，连续 1.2s 低于阈值即自动 `stop()`；这才是"说完就走"的手感。
3. **倒计时可视化**：环形进度 + 剩余秒数，最后 3 秒变橙并提示——文案：`还有 3 秒，先说完这句就好`。
4. **参数化上限**：对话 20s、答辩 45s、朗读 12s（`recorder.start(maxMs)` 已支持，`DefenseView` 的 `15_000` 必须改）。被自动截断时**必须**给出补救卡：
   > 「⏱ 时间到啦，这段先交上去了。**说到一半？点『接着说』补一句**。」 〔接着说〕〔重录这轮〕
5. **真波形**：`useP5Wave` 接入麦克风振幅（把 `getUserMedia` 的 stream 传进去），让用户**看得见自己的声音**——这是最便宜的"麦克风工作正常"信号。
6. **权限被拒的专用面板**（替换红字条）：
   > 🎤 **还差一步：允许使用麦克风**
   > 浏览器地址栏右侧会有一个小相机/麦克风图标 → 点它 → 选择「允许」→ 回到这里点「重试」。
   > 〔重试〕〔看图文教程〕〔先用文字打字练一轮〕
7. **非安全上下文兜底**：检测 `!navigator.mediaDevices` → 「当前地址不支持录音（需要 `localhost` 或 https）。请用 http://localhost:8088 打开本页。」

### 3.2 开口羞耻缓解包（P0-7）——本产品最该补的一块

1. **第 0 轮：30 秒零压力热身（不评分、不入档）**。进入场景后先不进对话，而是：
   > 「先热个身，不打分、不记录 😌
   > 跟我念一句就好：**"Hi!"**」 〔🔊 先听一遍〕〔🎙 跟着说〕
   说完给**无条件正向反馈**（"声音很清楚！我们开始吧 →"），只做"麦克风通了 + 我开口了"两件事。
2. **每一轮都给三档脚手架**，默认展示第 1 档：
   - 🟢 **看提示说**：给中英对照参考句（把 `firstCorpusPhrase()` 的 `|` 后半段的中文释义补回来，并把 `(coffee)` 渲染成可点选的下拉词槽）；
   - 🟡 **自己说**（默认）；
   - 🔵 **听完再说**：先播 TTS 示范，再开录。
3. **"先听后说"按钮常驻**：把 §3.1 的「🔊 听示范」改为**重听 AI 上一句**（`audio_chunk` 的 url 已在客户端，缓存即可），并新增「🐢 慢速重听」（TTS `rate=-30%`）。
4. **评分默认收起**：首个会话把三维分数收进「查看本轮细节」，一屏只留**一个绿色徽章 + 一句人话鼓励**。文案库（按分档）：
   - ≥85：「这句很地道！**they'd** 的连读很自然 👏」
   - 70~84：「意思完全传达到了 👍 再把 **would** 的元音拉长一点点会更像母语者。」
   - <70：「听清了你的意思！我们把这句拆成两半再来一次，很快就顺了。」
   - ASR 空：「这次没太听清，可能麦克风离得远了些。**离近一点，再说一遍就好**。」
5. **永不使用红色**做逐轮反馈（红色留给系统错误）。当前 `DefenseView` 的红色「🔴 建议回看要点」应改为中性蓝 + 「这题我们换个角度再来 →」。
6. **隐私安抚一次性提示**：「你的录音只用于这次评分，24 小时后自动删除。」（后端 `audio_ttl_hours=24` 已支持，**这个对用户极其友好的事实目前一个字都没告诉用户**。）

### 3.3 等待与流式体验（P0-5 / P0-6）

1. **三段式状态条**（替换孤零零的「…」），与 SSE 事件严格绑定：

| 阶段 | 触发 | 文案 | 兜底 |
|---|---|---|---|
| 1 | 上传开始 | `正在听你说…`（波形收束动画） | >6s → 「网络有点慢，还在传…」 |
| 2 | 收到 `asr_text` | `听清啦：" I'd like a coffee "`（**直接把 ASR 回显当成等待填充物**） | 空文本 → 走"没听清"分支 |
| 3 | 收到首个 `text_delta` | 角色头像"正在说话"动效 + 字幕逐字 | 3s 内无 `audio_chunk` → 「先看字幕，声音马上到」 |

2. **工程侧必改**：`orchestrator.py` 把 TTS 移进 LLM 流循环（首句 `.!?` 一到就 `asyncio.create_task` 合成），并对开场白/常用回应（"I see!"、"Sure."）做**预合成缓存**——docs/14 §10 的 POC-1 结论本来就是这么写的，实现没跟上。
3. **看门狗**：`useTurnTimers` 补 `setTimer(watchdog, 30_000)`；`streamTurn` 的 `onClose` 回调必须判断"本轮是否收到 `turn_end`"，否则：
   > 「⚠️ 这轮没能传回来。你的录音还在，**点一下就重发**。」 〔重发这轮〕〔跳过继续〕
4. 服务端补 `: ping\n\n` 心跳（docs/14 §3.3 已承诺）。

### 3.4 错误与降级文案对照表（P0-4）

| 场景 | 现在用户看到 | 应该看到（含操作） |
|---|---|---|
| 限流 429 | `HTTP 429` | 「今天的 AI 对话额度用完啦（每小时 30 轮）。**28 分钟后恢复**，先去看看这次的报告？」〔查看报告〕 |
| ASR 空/失败 | `管线提示：asr_failed` | 「没太听清 😅 可能太小声或环境有点吵。**离麦克风近一点，再说一次**。」〔🔊 听示范〕〔🎙 再说一次〕 |
| 评分服务挂 | 圆环标签变「未评测」，但三根进度条**还显示上一轮的分** | 整卡置灰 + 「这轮发音评分暂时不可用，**不影响你的对话**，我们已经记下这句了。」（并清空旧值） |
| 会话状态冲突 409 | `session state=completed` / `stale turn` | 「这轮已经结束啦，我们继续下一句 →」（自动重同步 `expected_turn`，用户无感） |
| 会话过期 404 | `session not found or expired` | 「休息太久，练习已自动保存并结束。**要接着上次的场景再来一轮吗？**」〔继续练〕〔看报告〕 |
| 音频过大 413 | `audio too large` | 「这段录得有点长，我们只保留了前 20 秒。」 |
| 401 过期 | `HTTP 401` | 自动跳登录并带回跳，toast：「登录状态过期了，重新登录后会回到刚才的场景。」 |
| 网络断 | 无提示（卡死） | 顶部常驻条：「⚡ 网络连接断开，正在重连…」+ 本地保留待发录音 |

**统一工程动作**：`main.py` 补一个 `HTTPException` handler 转成 envelope；前端建 `errorCopy(code)` 映射表，红字条永远只显示映射后的中文 + 至少一个可点操作。

| # | 动作 | 依据 |

**= 8 次点击 / 4 次页面切换 / 1 次授权 / 15 秒强制等待，最快 90~120 秒才发出第一个音节。**
若按 README 与 docs/06 §9.2 的口径先做入学测试，则是 **6 题 × (点录音 + 15s 硬录 + 3~8s 上传)**≈**2.5 分钟以上的连续考试**，且第 6 题是无参考的开放自我介绍——**这一步会在第一分钟劝退一半以上的人，尤其是最需要这个产品的低水平用户。**

2. **说完才要账号**：出分那一刻弹「保存你的第一份成绩 →」，此时再登录/注册（注册表单必须做出来，`auth.register` 已就绪）。
3. **入学测试改为"可跳过 + 分期"**：
   - 默认路径：**跳过测试，直接给 L2 入门套**，练完第 1 个场景后用真实成绩自动定档（数据比测试更准）；
   - 想测的人：从 6 题砍到 **2 题**（1 句朗读 + 1 句开放），每题带 🔊 示范 + 「重录一次」；
   - 文案：「**先不用考试**，我们边练边判断你的水平。想快速定级？做 2 道题就够（约 40 秒）。」

## 4. 可用性测试脚本（5 个任务，建议 5~8 人，每人 30 分钟）

**招募配比**：英语自评"不敢开口"的成人 3 人（核心画像）、12~15 岁 1 人、55 岁以上 1 人、答辩在即的研究生 1~2 人。
**方法**：出声思维（think-aloud）+ 屏幕录制 + 事后 SUS 量表；主持人**不提示、不解释**，除非用户连续卡 90 秒。

### 任务 1｜冷启动：「请开始你的第一次英语口语练习」

- 起点：浏览器打开 `http://localhost:8088`，不给任何说明。
- **观察点**：① 在 `/demo` 页停留多久？会不会去点那个「开始录音」（若点了，观察发现"6 秒"文案与 60 秒实际不符时的反应）；② 找不到注册入口时说了什么；③ **到"第一次开口"的秒表读数**（目标 <20s，当前预期 90~120s）；④ 首次麦克风授权弹窗的犹豫时长；⑤ 有没有人直接放弃。
- **判定**：3 人以上无法在 2 分钟内说出第一句英语 = FTUE 判定失败。

### 任务 2｜开口羞耻探针：「用英语在咖啡馆点一杯咖啡，说满 3 轮」

- 前置：已登录、已在 `/practice/:id`。
- **观察点**：① 从进页到按下录音的**犹豫时长**（>8s 记为羞耻信号，同时观察黄色提示卡弹出时用户是松了口气还是被打断）；② **说完后到 15 秒结束之间的行为**——是否反复点「■」、是否说"它卡住了"、表情/身体语言；③ 看不到自己说的话时会不会问"它听懂了吗"（**统计有多少人主动问出这句话**，这是 P0-2 的量化证据）；④ 拿到分数时的第一反应（是"好玩"还是"被评判"）；⑤ 是否用了「🔊 听示范」，用完是否理解那句话和当前对话无关。

### 任务 3｜错误恢复：「模拟三种故障，看用户能否自救」

- 主持人依次制造：① 浏览器设置里**拒绝麦克风权限**后让用户重试；② 录音时**断网 5 秒**；③ 用同一账号提前刷爆 LLM 额度制造 429。
- **观察点**：① 拒绝权限后，用户在 `PlacementView`/`DefenseView` 是否发现页面已经变砖（预期：**无人能自行恢复**）；② 看到「HTTP 429」时用户的原话（记录他们如何猜测含义）；③ 卡在「…」气泡时的等待忍耐上限（记录秒数，通常 20~30s 后关页面）；④ 用户是否尝试刷新——刷新后会**丢失整个会话并新开一轮**，记录他们发现进度没了的反应。

### 任务 4｜入学测试门槛：「完成入学测试，得到你的水平档」

- **观察点**：① 第 1 句朗读前，用户是否寻找"听一遍示范"的按钮（预期：找不到）；② 读错时是否寻找"重录"（预期：找不到，录完即提交，观察懊恼程度）；③ 第 6 题开放式「Tell me something about yourself.」的**沉默时长与实际说出的词数**（预期：大量 <10 词、大量 15 秒静默）；④ 全程放弃率与放弃发生在第几题；⑤ 结束后询问"你觉得这个 L2 准不准"，记录信任度。

### 任务 5｜价值感与回访意愿：「看完报告，告诉我你明天还会不会来」

- **观察点**：① 报告页的**首个注视点**与停留时长（<20s 视为无价值感）；② 让用户复述"我下一步该练什么"——**能否说出具体内容**（当前"📌 待练"栏永远为空，预期无人能答）；③ 三条建议是否被认为"是针对我说的"（当前是固定模板句）；④ 点「再练一次」后发现只是回到场景列表时的反应；⑤ 直接问："愿意为它每天花 10 分钟吗？为什么？"——把原话逐字记下来，这是最有价值的产出。

**汇总口径**：以"到第一次开口的秒数""主动问出'它听懂了吗'的人数""15 秒等待期的负面发声次数""能说出下一步的人数"四个指标作为改版前后的 A/B 基线。

## 5. 一页纸修复优先级（给前端的排期建议）

| 顺序 | 改动 | 工作量 | 收益 |
|---|---|---|---|
| 1 | 录音可手动停止 + 倒计时 + 截断补救卡（三个 View + `recorder`） | 0.5 人日 | 直接消除最强流失点 |
| 2 | SSE 加 `asr_text` + 前端渲染用户气泡 | 0.5 人日 | 补上口语产品的元反馈 |
| 3 | 错误文案映射表 + `HTTPException` handler + 30s 看门狗 + `onClose` 兜底 | 0.5 人日 | 消灭"HTTP 429"与卡死 |
| 4 | 权限被拒面板 + 三个 View 的 try/catch | 0.3 人日 | 消灭"页面变砖" |
| 5 | 热身轮 + 三档脚手架 + 鼓励式文案库 | 1 人日 | 正面解决开口羞耻 |
| 6 | `to_practice` 修复 + 报告 CTA + `page_view` 埋点 | 0.5 人日 | 打通闭环与指标 |
| 7 | 首页改造 + 注册表单 + 入学测试可跳过 | 1 人日 | FTUE 从 8 步压到 2 步 |
| 8 | `NCard` import、覆盖度 x/5、`aria-label`、字号/对比度 | 0.5 人日 | 完成度与无障碍 |

> 一句话总结：**这个 MVP 的"教学设计"（覆盖度、双人格、三级题库、提问依据）想得比绝大多数学生项目深，但"人机交互"停留在能跑通的水平——用户不能停止录音、看不到自己说了什么、出错只看到 HTTP 状态码、练完不知道下一步。把这四件事修掉，产品体验的档次会立刻跨一个量级，而它们的总成本不超过 2 人日。**
