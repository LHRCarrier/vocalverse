## 1. 调研结论：酒馆类产品做头像吗？

**是惯例，且玩家侧也有头像**：

| 产品 | 做法 | 来源 |
|---|---|---|
| SillyTavern（酒馆 AI 原型） | 角色卡**自带头像图片**（可上传/生成）；用户 **persona 也有头像**；设置可切「圆形/长方形头像样式」；群聊每角色独立头像 | sillytavern.wiki 使用指南（角色设计）；SillyTavern README（自定义聊天界面：切换圆形或长方形头像样式） |
| 云端酒馆 / SeaArt SillyTavern Chat | persona 可由一张图生成（"persona from a single image"） | seaart.ai/features/sillytavern-chat |
| 星野 / Talkie / 猫箱（国内 AI 角色扮演） | 角色立绘/头像 + 用户头像 | 同类产品惯例 |

**对本项目的结论**：用户侧**直接用账号头像**（与顶栏/社区/私信一致，不造「酒馆专属用户头像」）；
DM 侧用**明确的主持人身份图标**；「酒馆专用头像」的合理落点是 **DM / 场景卡封面 / NPC 实体**（SillyTavern 角色卡模式）。

## 2. 现状与两个问题的根因（实测）

| 问题 | 根因 | 证据 |
|---|---|---|
| 用户气泡只有首字母，真实头像不显示 | `TrpgMessageItem` 只渲染 `avatarLetter`，未接 `auth.me.avatarUrl`（顶栏用的是 `MobileAvatar`） | `apps/web/src/components/mobile/trpg/TrpgMessageItem.vue:297` |

| （附带）DM 头像形状不一致 | `.u-ava` 两套定义（`:915` 14px 圆角 / `:4503` pill），后定义覆盖前者 → 实为圆形 | `mobile-uic.css:915` vs `:4503` |

## 3. 头像方案（P0，纯前端小改 + 可选后端）

- **A（推荐）**：用户气泡头像换 `MobileAvatar`（真实头像 + 首字母降级，与全 App 一致）；
  DM 图标换 Tabler 主持人语义图标（候选：`tabler/dice`、`tabler/masks-theater`、`tabler/wand`、`tabler/book-2`），
  尺寸来源唯一化（`.u-ava svg` 单点）；`.u-ava` 两套定义合并（保留 pill 语义，酒馆 DM 保持圆形）。
- **B（进阶）**：场景卡封面头像（`trpg_scenario_cards` 加 `cover_media_id`，管理端可上传/生成，开局时作为 DM 头像）。
- **C（P2）**：NPC 实体头像 —— 见 §4 立绘方案（与立绘同一套基础设施）。

## 4. 角色立绘功能 · 可行性分析

### 4.1 目标

按「场景 + 剧情推进」为角色生成定制立绘；**普通情况用默认头像/图标**（无立绘不阻塞、不空白）。

### 4.2 技术路径（复用现有能力，新增三处）

```
① 实体识别：TrpgEntity（已有 kind=pc/npc + name + status）→ 需要立绘的实体清单
② 立绘描述生成：LLM（已有 agent 调用链）以 scene + facts + entity.name + 剧本卡模板为输入
   → 输出结构化立绘描述（外貌/服饰/气质/配色，禁止文本渲染）
③ 图像生成：外部文生图 API（即梦 / 通义万相 / 豆包 / SD 自建）→ PNG
④ 落库：POST /api/v1/media（已有：kind=image、sha256 去重、owner、storage_path）
   → 实体挂 portrait_media_id（新增列）→ 前端按 mediaUrl() 展示
⑤ 异步：复用「任务表 + 状态轮询/SSE 进度」既有模式（tts_tasks / pitch_extract_jobs）
   → 新增 trpg_portrait_jobs（status: queued/running/done/failed）
```

**已具备**：媒体上传/下载/去重（`app/api/routes/media.py`、`MediaAsset`）、LLM 调用链、
异步任务模式、实体表（`trpg_entities`）、移动端展示位（消息流 NPC 名、主持台实体列表）。
**需新增**：文生图客户端 + 配置开关（`APP_TRPG_PORTRAIT_ENABLED`）、`trpg_portrait_jobs` 表（迁移）、
`trpg_entities.portrait_media_id`（迁移）、限流桶、前端触发入口与展示。

### 4.3 关键难点：角色一致性

同一角色多次生成要「像同一个人」——业界做法与我们的取舍：

1. **固定描述串 + 固定 seed**（首选，零成本）：立绘描述存库（实体级），生成时固定 `seed`；
2. **参考图 image-to-image**（P1）：首张立绘作为后续变体的参考图，提升一致性；
3. **一次生成、长期复用**（硬规则）：同一实体默认**只生成一次**，除非用户主动「重绘」；
   剧情推进变体（换装/情绪）保留历史版本，不覆盖。

### 4.4 成本与延迟（量级估算，按外部 API 公开价）

| 项 | 量级 |
|---|---|
| 单图延迟 | 5~20s（异步，不阻塞对话） |
| 单图成本 | ≈ ¥0.05~0.2（视服务商/分辨率） |
| 一局成本 | 3~5 NPC ≈ ¥0.3~1；复用后边际成本 ≈ 0 |
| 存储 | 512~1024px PNG ≈ 0.3~1.5MB/张；媒体库已有 sha256 去重 |

### 4.5 风险与对策

| 风险 | 对策 |
|---|---|
| 内容合规（AI 生成图） | prompt 白名单（禁真人/敏感题材）+ 仅本人可见（不公开）+ 复用现有 moderation 思路；生成失败/超限降级默认头像 |
| 一致性差 | §4.3 的 seed + 描述串 + 复用策略；重绘入口显式 |
| 存储增长 | 媒体库配额 + 只保留最近 N 版；过期清理沿用媒体策略 |
| 外部 API 不可用 | 功能开关默认关；失败不阻塞（默认头像兜底） |
| 仓库红线 | 生成图只落 `data/media`（不入库/不入 git）；不提交模型权重 |
| 移动端流量 | 缩略图 + 懒加载 + 只在实体卡/主持台按需展示 |

### 4.6 分期建议与验收

| 期 | 范围 | 验收 |
|---|---|---|
| P0 头像修正 | 用户 `MobileAvatar` + DM Tabler 图标 + `.u-ava` 两套定义合并 | 真机截图：真实头像显示、DM 图标不扁 |
| P1 实体立绘（按需） | 主持台实体行「生成立绘」→ 任务轮询 → 实体挂图；消息流 NPC 名旁显示小头像；失败默认图标 | 生成成功可复用；重进剧本仍在；失败不阻塞 |
| P2 剧情变体 | 场景切换/关键事件后可选「更新立绘」（保留历史版本，image-to-image 参考首图） | 变体与首图同一角色可辨识（人工抽检） |
| 不做 | 每回合实时生成、视频/动态立绘、公开立绘画廊 | — |

### 使用建议

1. 分辨率 512×512（头像）或 768×768（立绘），一次生成 4 张挑 1；
2. **记录 seed**（同角色复用同 seed + 同描述串 = 一致性）；
3. DM/PC/NPC 各一张，先出 DM 与 1 个 NPC 试风格，满意后再批量；
4. 生成图放入 `data/media` 或直接上传（`POST /api/v1/media`，kind=image）——**不要提交进 git**。
