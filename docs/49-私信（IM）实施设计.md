## 0. 范围与不做项

**本轮做**：
1. 一对一私信（文本）——会话列表 / 会话消息 / 发送 / 已读上报；
2. 真实 IM 体感（近实时到达、未读即时、会话列表自动更新）；
3. 通知中心「私信」tab 由演示帧 → 真实会话列表；`/m/messages/:id` 会话页由演示收发 → 真实收发；
4. 演示种子（`demoadult` ↔ `demoteen` 等演示账号互发几段，幂等 + 生产开关同款）。

**明确不做（登记）**：群聊；消息撤回/编辑/删除（对端可见性）；图片/语音/视频消息；消息搜索；消息推送（APNs/FCM）；举报与机审后台；已读回执展示给对端；跨端消息同步冲突合并（单账号多端以服务端为权威）。

## 1. 数据模型

**写方 = Java**（社区主服务，与 posts/follows 同域；Python 不碰，零迁移外溢）。

### 1.1 `direct_messages`（迁移 0012）

| 列 | 类型 | 说明 |
|---|---|---|
| id | bigserial PK | |
| sender_id | bigint FK users(id) | 发送者 |
| recipient_id | bigint FK users(id) | 接收者 |
| body | varchar(1000) | 纯文本；长度上限见 §2 |
| status | varchar(16) | `visible` / `deleted`（为将来治理预留；本轮无删除入口） |
| created_at | timestamptz(6) | 排序权威（keyset `(created_at, id)`） |

索引：
- `ix_dm_pair_time (sender_id, recipient_id, created_at DESC, id DESC)` —— 单会话读取；
- `ix_dm_recipient_time (recipient_id, created_at DESC, id DESC)` —— 收件箱（会话列表/未读）；
- `ix_dm_sender_time (sender_id, created_at DESC, id DESC)` —— 发件箱（会话列表合并两侧）；
- CHECK `sender_id <> recipient_id`（自聊在服务层先拦 42203，DB 兜底）。

### 1.2 `dm_read_state`（迁移 0012）

| 列 | 类型 | 说明 |
|---|---|---|
| user_id | bigint FK users(id) | 读方 |
| peer_id | bigint FK users(id) | 会话对端 |
| last_read_id | bigint | 该用户在此会话中的「已读水位」= 已读到的最后一条消息 id |
| updated_at | timestamptz(6) | 水位更新时刻 |

PK `(user_id, peer_id)`；CHECK `user_id <> peer_id`。

**为什么是 `last_read_id` 而不是 `last_read_at`**（§4.3 B2）：时间戳水位在并发提交下会**永久漏未读**——客户端 A 读到 10:00:05 上报水位，对端在 10:00:04 提交的消息若晚于 A 的读请求到达 DB，就会被水位「跨过」而永不计数。消息 id 是单调序列，取 `max(现有, upTo)` 不存在跨过问题。

**未读定义**（服务端权威）：对某用户 U 与对端 P，未读 = `direct_messages` 中 `sender_id=P AND recipient_id=U AND status='visible' AND id > COALESCE(last_read_id, 0)` 的条数。

> 为什么不用「消息级已读标记」：一对一场景下会话级水位即可表达全部语义，且写入 O(1)（不随消息量放大）；消息级回执属 §4.4 不做项。

## 2. 契约（先登记后用）

服务原生路径（网关 `/manage/` 剥前缀），全部 Bearer：

| 方法/路径 | 说明 |
|---|---|
| GET `/api/v1/community/messages/conversations?cursor&limit` | 会话列表：对端 `AuthorView` + `lastMessage{body,createdAt,mine}` + `unreadCount`；按最后消息时间 DESC（keyset） |
| GET `/api/v1/community/messages/{peerId}?cursor&limit` | 会话消息（keyset `(created_at,id)` 倒序，`{items,next_cursor,has_more}`）；不修改已读水位 |
| POST `/api/v1/community/messages/{peerId}` | 发送 `{body}`；自聊 42203、对方不存在 40402 |
| PUT `/api/v1/community/messages/{peerId}/read` | 标记已读 `{upTo}`（幂等；水位 = max(现有, upTo)） |
| GET `/api/v1/community/messages/stream?since` | **SSE 长连**（§3）：实时新消息推送 + 断线按 `since` 回放 |

**错误码**：复用 `40402`（对端用户不存在）、`42203`（body 空/超长/自聊）、`40302`（未来治理）；**预计零新增码**（若裁决需要新增，先在 `docs/api/error-codes.md` 登记）。

**body 上限**：1000 字符（与前端 `maxlength` 同步；超限 42203）。

## 3. 实时通道（裁决：A · Java SSE 长连 + 进程内广播 + 轮询兜底）

> 裁决依据：`local/拷问-私信实时通道.md`（子代理拷问，2026-09-10；本地过程稿不入库）。三条阻断级前置见 §3.3。

### 3.1 选型

| 方案 | 结论 |
|---|---|
| **A · Java SSE 长连（`SseEmitter`）+ 进程内广播 + 轮询兜底** | **采用** |
| B · SSE + Redis pub/sub | 否决本轮（Java 侧首次引 Redis + 新基建；多副本升级路径登记 §3.4） |
| C · WebSocket | 否决（违反 `docs/06 §8`「不做 WebSocket」ADR；本期无双工/打断需求） |
| D · 短轮询 | 仅作**降级兜底**（SSE 不可用/断线退避时启用） |

**决定性依据**：写方 = Java（§1，与 posts/follows 同域）→ **写与推同进程，零跨服务通道**。若把流放 Python，反而要新造「Java 写 → Python 推」链路（Redis publish / PG NOTIFY / Python 轮询），成本高于本方案。

**端点**：`GET /api/v1/community/messages/stream?since=<cursor>`（网关 `/manage/api/v1/community/messages/stream`），`text/event-stream`，事件 `message`（新消息，data = MessageView）、心跳 `:ping` 每 25s。

- **投递语义**：`since` 游标（不用 `Last-Event-ID`——前端 `apps/web/src/audio/sse.ts:32-35` 会丢弃 `id:` 行），服务端按 `(created_at,id)` 回放断线期间消息后再进入实时推送；
- **不占工作线程**：`SseEmitter` 异步；连接注册表 `Map<userId, Set<SseEmitter>>`；单用户 ≤3 流、全局 ≤500（超限拒绝并让前端走降级）；
- **SSE 端点不持 DB 连接**（`docs/20:160` R6）：订阅期只在有新消息时查询；
- **前端**：`sse.ts` 仅支持 POST+FormData 且硬绑 `PYTHON_BASE`（`:50-60`）→ 新写 GET 版 `openCommunityStream()`（带 Bearer + 401 静默续期，复用 `client.ts:98-114` 的 authRefresher）；页面隐藏/离开即 abort（同源 6 连接限制：1 IM 流 + 练习流 + 2~4 XHR 已临界）；
- **降级**：SSE 建流失败或连续断线 → 会话页 3s / 列表 10s 轮询；恢复后停轮询（双通道按消息 id 去重）。

### 3.2 量化（报告实测/官方文档口径）

- 延迟：典型 **30~150ms（LAN）/ 150~600ms（4G）**；最坏 = 降级轮询 3~5s；
- 100 长连内存 <10MB，空闲 0 DB 查询、每用户 ≤5 请求/小时；对比轮询：会话页 3s + 列表 30s = **1320 请求/小时/人** → 100 人 37 req/s、74~110 DB 查询/s（连接池 20+10，`docs/20:203`）。

### 3.3 三条阻断级前置（缺一不可，随本功能同一批落地）

1. **ADR 限定修订**：`docs/06:23`、`docs/20:25/156(R2)/171/174` 现文写死「Java 严禁进 SSE 热路径 / 长连接→Python」——按原意（`docs/08:34` 只针对**语音热路径**）收窄为「**Java 可承载社区域单向 SSE；语音/LLM 热路径仍严禁**」，同步 `docs/21 §1.1/§2.2` 与 `docs/api/envelope.md`（共 7 处）；
2. **网关**：`apps/web/nginx.conf:31-41`（`/api/v1/`）已有 SSE 四件套（`proxy_buffering off` / `proxy_read_timeout` / `proxy_http_version 1.1` / `Connection ""`），`:55-59`（`/manage/`）**一件都没有**——nginx 默认 `proxy_buffering on` + `proxy_read_timeout 60s` → 生产容器里长连默认是坏的。修法：给 `…/community/messages/stream` **单开 location**（不动整个 `/manage/`）；
3. **Spring MVC 异步超时**：Tomcat `asyncTimeout` 默认 30s → 必须配 `spring.mvc.async.request-timeout`（否则每 30s 闪断）。

### 3.4 登记的不做项/已知边界

单实例内存广播（多副本下延迟可见但不丢；升级路径 = Redis pub/sub 或 PG NOTIFY）；无推送（APNs/FCM）；无消息撤回/编辑；无在线态（presence）；无群聊；无图片/语音消息；无内容审核与敏感词（S4）；无端到端加密；无消息搜索；无保留期策略；不做 `Last-Event-ID`；SSE 端点不持 DB 连接；埋点本期不加；单用户 ≤3 流、全局 ≤500。

## 4. 未读口径与红点（裁决：A+ 本轮 / B 登记下轮 / C 不做）

> 裁决依据：`local/拷问-私信未读口径.md`（子代理拷问，2026-09-10；本地过程稿不入库）。

### 4.1 真源与清零（A+）

- **真源**：服务端会话级**水位**（`dm_read_state`），未读 = 对端 `visible` 消息晚于水位的条数；
- **水位列改 `last_read_id`**（原稿 `last_read_at` 时间戳有**永久漏未读**风险：并发提交顺序会吞掉消息，见 §4.3 B2）——单调取 `max(现有, upTo)`，`upTo` = 本次已渲染的**最后一条对端消息 id**；
- **清零时机**：`PUT /messages/{peerId}/read {upTo}`——进页、页内收到新消息、离开页三处幂等；
- **可见面**：① 会话列表行未读数字（`>0` 才显示，`>99 → 99+`，色用 `--u-accent`——本项目红色是错误语义，不用红点）② 通知中心「私信」tab 的未读提示；**不碰任何全局件**（`MobileTabBar.vue` / `App.vue` / 抽屉零改动）。

### 4.2 为什么不做底栏全局红点（B 登记下轮）

- 底栏现无任何角标机制（`MobileTabBar.vue:57-91`、`:94-128` 仅 RouterLink + Icon）；
- 通知位只挂在**社区组 5 页**（`:26-36` vs `:94-128`）→ 学习组（练习/唱吧/笔记/阅读）零感知，B 是**半覆盖**；
- **阻断级**：会话列表是 keyset 分页（§2），前端求和 ≠ 总数 → B 必须先加**全局未读聚合端点/字段**；
- 三项前置（全局未读聚合 + 实时通道定稿 + bell 语义裁决）落地后再做。

### 4.3 两条阻断级（照原稿实现即错）

- **B1**：底栏数字无真源（见上）；
- **B2**：水位取「请求时刻」会吞掉未渲染的新消息 → 必须用 `upTo`（消息 id）口径。

### 4.4 登记的不做项

底栏/抽屉角标（下轮，前置见 §4.2）；已读回执给对方看；消息级已读；发送中/失败态 + 幂等键（S4）；软删回收未读；多端/多标签实时同步；未读推送；通知/关注未读持久化与红点（`docs/41:5` 原口径不变）；发起会话入口（S4，现为 toast）。
