## 1. 通用契约

### 1.1 Envelope（引用 `docs/api/envelope.md`，全部端点例外）

```json
{ "code": 0, "message": "ok", "data": {} }
```

- HTTP 状态码管传输错误（400/401/403/404/409/410/413/422/429/5xx），`code` 管业务语义；
- 时间一律 UTC ISO-8601；分页 `data = {items, total, page, page_size}`；
- **例外登记**：① SSE 端点（`POST /sessions/{id}/turns`）响应使用 SSE 事件帧而非 envelope；② `GET /api/v1/audio/{name}` 响应为音频文件流（FileResponse）。

### 1.2 鉴权（引用 docs/06 §7，全部端点适用）

- access JWT：`Authorization: Bearer <token>`，HS256 共享 secret，Java 签发 / Python 验签；
- refresh JWT：httpOnly + SameSite=Lax + Secure cookie，7d，`POST /manage/auth/refresh`；
- 内部调用：`X-Service-Token`（仅 §4 一条）；
- **现状对账问题（整改项 R-1）**：Python 快照中**没有任何 operation 带 `security`**——`practice/placement/defense/events` 端点虽在代码里有 `Depends(get_current_user_id)`，但因用的是 `Depends` 而非 `Security`，security 声明未进入 OpenAPI（机器可读性缺失，且 `audio` 四端点是真的裸奔）。

### 1.3 限流（引用 docs/06 §7，Redis 桶 + 内存降级）

| 桶 | 限制 | 现状 |
|---|---|---|
| 登录 | 5 次/分/IP（Java 侧） | ✅（Java 实现） |
| llm | 30 次/用户/时 | ⚠️ 仅 practice 回合路径接入；`/llm/chat` 裸奔（R-2） |
| asr / ise | 60 次/用户/时（代码 `config.py` L64-65） | ⚠️ 同上；**ise=60 与 docs/06 §7「评分 30/h」不符（R-16）** |
| tts | 60 次/用户/时 | ⚠️ `practice` 回合不消耗；`/tts` 裸奔（R-3） |

另：本表与 docs/api/error-codes.md 的 42901 对应；Reserved：`40910`（会话锁冲突，Redis 锁落地后启用，见 docs/20 §5.2）。

## 3. 关键域契约要点

### 3.1 `POST /sessions/{id}/turns`（SSE，全系统最复杂契约）

**请求**（multipart/form-data）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| audio | file | 条件 | action ∈ normal 时必填；hint/demo/abandon 可无（42202 兜底） |
| action | string | ✅ | normal / start / hint / demo / abandon / retry（服务端可改写） |
| expected_turn | int | 可选 | 前端乐观计数；与服务端不符 → 40903 stale turn |

**响应**：`Content-Type: text/event-stream`，事件序列（编码细节见 `app/practice/events.py`）：

```
turn_start → text_delta* → audio_chunk* → meta_block → score_delta → turn_end
                          （任一步失败 → error 事件，recoverable=true/false）
```

| 事件 | data 要点 | 前端消费 |
|---|---|---|
| turn_start | turn_index, next_expected_turn | 采纳服务端权威轮次（R-13 目标态：恢复机制） |
| text_delta | 字幕增量（文本降级为字幕） | 渲染字幕 |
| audio_chunk | 音频 URL + 句序号 | 队列顺序播放（时间轴权威） |
| meta_block | 单轮元数据（origin/action/coverage） | 状态机推进 |
| score_delta | 四维分（迟到 ≤3s 显示「未评测」） | 评分卡 |
| turn_end | 会话状态、剩余轮次 | 判结束 |
| error | code + recoverable | 降级提示（recoverable=true 可重试） |

**目标态契约增补**（R-13）：`turn_end` / `turn_start` 回带服务端权威 `next_expected_turn`，前端无条件采纳；新增 `GET /sessions/{id}` 恢复端点（刷新/断线重连用，docs/19 P2-4）。

### 3.2 `POST /placement/finalize` 与档位回写链

1. 请求：题库答案（fields 见快照 `FinalizeIn`）；
2. 响应：`{level, score, items}` + 异步（当前为同步 await）内部回调（§4）；
3. **契约保证**：回调失败不影响 finalize 的 HTTP 响应（降级=日志告警）；Java 侧 `user_profiles.cefr_level_source='placement'` 可溯；`placements` 为校对源。

### 3.3 `POST /events`（埋点）

- 幂等键：`client_event_id`（唯一索引兜底，重复到达返回 ok）；
- 10 类事件白名单 `page_view / scene_start / recording_start / recording_complete / score_event / recommend_impression / recommend_click / practice_complete / fun_action / corpus_hit`（docs/06 §9.1，M2 定为 10 类）；
- **R-9**：当前代码白名单构造用 `values()` 减 `__dict__.keys()`，混入元数据字符串（docs/19 P1-10 证据）；维度列 `age_group`/`level` 从不赋值（P1-7 证据）。

## 4. 内部 REST 契约（本次正式登记，调用方不得硬编码变体）

### `POST /internal/level`（Python → Java 唯一跨服务写通道）

| 项 | 定义 |
|---|---|
| 路径 | `/internal/level`（服务原生；**严禁经网关**——R-12 目标态 nginx `location /manage/internal/ { return 404; }`） |
| 鉴权 | `X-Service-Token: <secret>`（与 JWT 无关；Java `ServiceTokenFilter` 匹配 `/internal/**`） |
| 请求体 | `{ "userId": <Long>, "level": "<L1|L2|L3|L4>" }` —— **键名以 Java DTO `LevelRequest` 为准（camelCase）**；Jackson 无 SNAKE_CASE 策略，`user_id` 会反序列化为 null → 400 |
| 响应 | `Envelope{ code:0, data:<userId> }` |
| 错误 | 401（token 无效）、400（`@Valid` 失败：userId/level 为空）、404（profile not found——用户未建档） |
| 语义 | 更新 `user_profiles.cefr_level` + `cefr_level_source='placement'` + `updated_at=now()`；**幂等**（同值重复投递无害，可放心重试） |
| 调用方义务 | Python：`httpx` 3s 超时；`resp.raise_for_status()` + 日志（**禁止静默吞 4xx/5xx**）；失败不阻塞 finalize 响应；不做同步补偿（`placements` 为校对源；可选 P2：`placements` 加 `level_synced_at` 启动扫描重投，即 docs/19 §7 Outbox 简化版） |
| 契约测试 | Python `respx` 断言请求体键名（防 P0-6 复发）；Java `@SpringBootTest` 断言语义与 404/400 分支 |

**P0-6 现状违例**：Python `placement._callback_level` 发 `{"user_id": ...}`（`app/api/routes/placement.py` L182）→ Java 反序列化得 `userId=null` → `@Valid` 400；Python 侧 `httpx` 默认不抛 4xx，外层 `except Exception` 静默吞掉 → 档位回写链路 100% 断且零告警（docs/19 P0-6，2026-09-07 复核仍在）。**修复 = Python 请求体改 `userId` + `raise_for_status`（10 分钟）+ 双侧契约测试（0.5 人天）。**

## 7. 契约变更流程（团队强制）

1. 改后端接口 → 本地起服务（8000/8080）；
2. `.\scripts\refresh-openapi.ps1`（导出 Python/Java 双快照 + `pnpm gen:api` 重新生成前端类型）；
3. `git diff` 三重检查：① 快照增量 = 本次改动；② `src/api/generated/*.d.ts` 无意外漂移；③ **手工改契约时同步更新**：`docs/api/`（envelope/error-codes）+ 本文档端点表；
4. 提交时契约变更 PR 必须带：`docs(api)` 约定同步 + 错误码登记（新码先登记后使用）；
5. CI 三关卡把关：`python-ci`（快照 vs `app.openapi()`）、`java-ci`（`ContractSnapshotTest` vs springdoc 实时渲染，跑在 `mvn verify`）、`frontend-ci`（`pnpm gen:api` 后 git diff 为空）；
6. **禁止**手工编辑 `specs/*.json` 与 `generated/*.d.ts`；快照只在刷新脚本写。
