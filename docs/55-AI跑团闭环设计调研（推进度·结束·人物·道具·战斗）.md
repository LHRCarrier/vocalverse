## 0. 结论先行（TL;DR）

1. **推进度**：不发明数值，组合两个成熟范式——**进度钟**（Blades in the Dark：4/6/8 格；正向=玩家目标、负向=威胁逼近；
   「关于障碍，而非方法」）+ **进度轨**（Ironsworn：10 格 + 难度等级 + 里程碑 + 可随时结算）。
   落到我们：现有 `quest.{名}.status` 扩展为 `progress`(0..N) + `clock`(positive|threat)；场景卡模板预置主线钟；
   DM 用 `tick_clock` 工具推进，主持台显示格子。**负向钟天然回答「还有几步就出事」** —— 推进度的紧张感来源。
2. **结束**：不设「通关/Game Over」，用 **Ironsworn 式「誓言结算 + 尾声」**：进度轨不必填满，玩家可主动发起收尾
   （工具/按钮），DM 判定结局质量，产出**尾声卡**（结局标题/描述/后日谈），一局标记 finished，可开新剧本。
   参照 AITRPG 的结局系统（地点触发 + 硬条件校验 + 数据驱动结局文案）。失败结局也推进剧情（弱命中/失败仍有故事）。
3. **新增人物**：把「登场」做成**可达状态变更**：实体状态机 `arriving → active → departed`；DM 工具触发
   （扩展 `show_portrait`）→ 立绘异步生成 → UI 先显示「**XX 正在赶来…**」占位卡/头像，图好了再换。
   SillyTavern 的「群成员表 + 谁在说话谁在场」可简化为顶栏「在场角色条」。
4. **道具/攻击**：要「像游戏一样能用」= **可执行动作显式列举 + 状态真写回 + 有反馈**：
   - 道具：结构化条目（名称/数量/效果/是否消耗）+ 使用入口 + 校验（没有就不能用，F&F 同款）；
   - 攻击：`attack` 工具（目标/武器/命中/伤害）→ HP 增量写回（复用 `roll_dice.effects` 同一写路径）→ 判定卡/战报卡；
   - UI：动作面板（建议行动 3~4 个，TRPG_Agent 的 `quick_actions`）+ 回合指示 + 血量条。
5. **落码顺序建议**：P1 立绘闭环（进行中）→ P2 章节·进度·结束（纯事实+工具，最小 UI）→ P3 人物进出场 + 异步立绘
   → P4 道具/动作/战斗。**不做**：每回合强制推进、硬性 Game Over、开放结局（gal 设计文明确批评「无结局」）。

## 2. 各机制调研发现

### 2.1 推进度（「离结束还有多远」怎么表达）

| 来源 | 机制 | 可偷的点 |
|---|---|---|
| **Ironsworn SRD** | 进度轨 = 10 格（每格 4 ticks）；rank（troublesome→epic）决定每次里程碑 tick 数（3→¼）；**不必填满**，玩家随时可发起进度判定（2d10 对抗已填格数）→ 强/弱/失 | 进度**依附目标**（vow/journey/fight/bond）；填格不是自动的，是「克服有意义障碍」 |
| **Blades in the Dark** | 进度钟 = 4/6/8 段圆环；正向钟（PC 想达成）与**负向钟（威胁逼近）**；tick 数按位置/效果 1~3；满格即「该发生的事发生了」 | 负向钟 = 倒计时紧张感；「钟是关于障碍的，不是关于方法的」（玩家可自由想办法） |
| **Friends & Fables** | 任务 = steps（场景/目标） + paths（trigger → outcome 分支）+ 难度/标签/前置；世界作者可写、AI 可即兴生成 | 进度藏在**结构化任务**里；分支由「触发条件 + 结果」组成 |
| **AITRPG**（三层 AI） | 规则层（硬变化：inventory/SAN/HP/flags）+ 节奏层（软变化：NPC 位置/状态、场景阶段与张力评估）+ 文案层；**结局系统**：地点触发 + 硬条件校验 + 数据驱动结局文案 | 硬/软变化分开合并；节奏层负责「现在该推进到哪一幕」 |
| **TRPG_Agent** | 场景生命周期：`SCENE_TURN_LIMIT=10`，超限强制 AI 产出 ≤200 字场景摘要并切场（旧场景压缩成系统消息） | 用**回合预算**收束场景，控制 token 与节奏 |
| **ZRIC-AI-TRPG-Engine** | 触发器系统：scene / item / stat / ai 四种条件，hard 强制跳转 + soft 提示；NPC 情绪三轴（信任/恐惧/烦躁） | 「触发器是收束时间线的关键」——关键节点硬触发，其余软提示 |
| **Galgame 设计**（cngal） | 共通线 → 选择肢/好感度/Flag → 个人线 → 多结局；「选项决定走向，好感度决定结局」为上品；Flag 存全局/线路两档存档 | Flag + 阈值 + 分歧点：**进度=路线解锁**，不是单一百分比 |

### 2.2 一局怎么算结束

| 来源 | 结束设计 | 结论 |
|---|---|---|
| **Ironsworn** | `Fulfill Your Vow`（随时可结算）→ 经验 → `Write Your Epilogue`（写尾声=完） | **玩家自主收尾 + 尾声**；不必打满进度 |
| **Friends & Fables** | 任务可「失败完成」（照样给经验），结束一个任务 ≠ 结束一局；之后 AI 生成新任务 | 结束是**任务粒度**，一局由多个任务串成 |
| **AI Dungeon** | 没有结束（只有 Story Summary / 脚本自定义任务链） | 无限流是陪伴产品的默认，但跑团需要收束 |
| **AITRPG** | 模组可配结局标题/描述/后日谈 + 影响维度；地点触发 + 硬条件校验 | 结局=**数据驱动文案 + 触发条件** |
| **星野 / 猫箱** | 角色线分章节 + 多结局（隐藏结局需多周目）；猫箱有可视化分支剧情编辑器（节点拖拽、多结局） | 商业化靠「章节/结局包」驱动付费；分支提前编排 |

### 2.3 新增人物（登场 / 在场 / 离场）

| 来源 | 做法 | 可偷的点 |
|---|---|---|
| **SillyTavern 群聊** | 群成员表（members / activation strategy：natural·list·manual·pooled / generation mode：SWAP·APPEND）；世界书按关键词注入；「谁发言」决定用哪张角色卡 | 「在场名单 + 谁说话」；重角色卡时单卡注入（省 token） |
| **Character Visuals 扩展** | 监听流式输出 → 检测角色名（speaker/attribution/pronoun/场景名单）→ 切整套立绘/服装，带冷却与手动锁定 | **立绘跟随叙事自动切换**（对比我们的工具显式信号：显式更稳、可审计） |
| **Friends & Fables** | 世界库数千角色/怪物/物品/地点；工作上下文按需检索；AI 后处理把新实体会话入 state | 新角色=即时建档 + 局部注入 |
| **ZRIC** | NPC 实体 + 情绪状态机 + 独立记忆 + MBTI persona；地图自动生长新地点 | 人物卡片化（情绪/记忆独立） |
| **AI Dungeon** | Story Cards：关键词触发器命中才注入（AI 不知道卡片存在） | 触发式注入省 context |

### 2.4 道具

| 来源 | 做法 | 要点 |
|---|---|---|
| **Friends & Fables** | 自动追踪库存；提到就更新；不存在的物品 AI 即时生成；交易/消耗会**校验并提示「你没有」**；投掷武器用掉即扣 | 道具是**可校验的资源**，不是布景 |
| **AI Dungeon** | Story Cards 记物品；Scripts 可读写 storyCards（社区用脚本实现背包/任务） | 用数据而非 prompt 记账 |
| **Ironsworn** | Assets（能力卡）给许可与加成，不做数值堆叠 | 轻数值，重叙事许可 |

### 2.5 战斗 / 攻击

| 来源 | 做法 | 要点 |
|---|---|---|
| **Friends & Fables Combat V4** | **agentic 工具集**：更新先攻序 / 增删战斗者 / 改 HP·位置·阵营·体型 / 掷任意骰；攻击面板自动结算命中与伤害，玩家确认；NPC 回合由玩家触发、自动结算 | 工具 + 面板 + 确认；「像 5e」的观感来自**结构化战斗状态** |
| **AITRPG** | 规则层硬变化（HP/SAN/物品/flags）不可被叙事覆盖；软变化（NPC 位置/状态）由节奏层给 | 硬状态权威在引擎 |
| **trpg-agent**（COC） | 检定分类器（roll router）→ 掷骰引擎（格斗/射击/闪避/反击）→ LLM 只叙事；KP 回复中标记块自动写回游戏状态 | 模型只提议，规则引擎权威 |
| **TRPG-master** | 模型产出 ActionPlan，**规则引擎校验目标/检定/效果并持久化**，叙述只依据已提交 evidence | 审计友好；状态不可被模型改写 |
| **DiceFrame** | 「模型负责讲故事，引擎负责让 HP、物品、金币与检定真正落地」；状态变更经引擎校验写入存档 | 同一条写路径 |

**共性结论**：AI 跑团的战斗 = `工具调用 + 状态写回 + 判定卡/面板反馈`。我们的 `roll_dice + effects`
（系统算术、先落表再回文本）已经是同构雏形，缺的是「攻击语义、先攻与回合、面板入口」。

## 3. 现状 vs 差距（VocalVerse 映射）

| 能力 | 现状（2026-09-22） | 差距 |
|---|---|---|
| 状态事实 | `trpg_facts`：pc./scene. 白名单 + quest./clue./rel. 域 | 无进度/时钟字段；quest 只有 status |
| 工具 | 注册表：`roll_dice`（effects 增量）/`set_scene`/`show_portrait`（骨架） | 缺 `tick_clock` / `complete_quest` / `attack` / `use_item` |
| 实体 | `trpg_entities`（npc/pc/task/clue/scene，pending 懒确认） | 无「在场/离场/登场中」状态；无情绪/记忆 |
| 事件与卡片 | `trpg_events` + 系统卡（open/scene/dice） | 无结局卡/章节卡/战报卡 |
| 立绘 | `portrait` SSE 骨架 + `portrait_media_id`（待 P1） | 生成任务表、名字命中素材、NPC 展台 |
| 场景卡 | `trpg_scenario_cards.template`（pc/facts/tasks/clues，白名单校验） | 无主线钟/章节/结局模板字段 |
| 前端 | 消息流 + 主持台 + 立绘展台（重做中） | 进度条、在场角色条、动作面板、道具/战斗 UI |

## 4. 设计提案（分 P；每项标注「可推迟」等级）

### P2 · 章节 / 进度 / 结束（推荐先做；纯事实 + 工具，UI 增量小）

1. **字段扩展（facts 白名单登记）**
   - `quest.{名}.progress`：`0..N`（N 由场景卡/开局定，默认 6）；
   - `quest.{名}.clock`：`positive | threat`（威胁钟=倒计时，满格触发既成事实）；
   - `quest.{名}.stage`：当前章节/阶段名（如「调查」「对峙」「收束」）；
   - 主线用系统级 key（`scene.main_clock` / `quest.主线.…`），避免玩家删不掉。
2. **工具（注册表新增 2 个）**
   - `tick_clock(quest, delta, reason)`：DM 在「克服有意义的障碍 / 遭受重大挫折」时调用；系统落表 + 系统卡（进度条变化）；
   - `complete_quest(quest, outcome)`：玩家可主动发起（按钮）或 DM 判定；产出**尾声卡**（标题/描述/后日谈 + 本局统计），
     营地标记 finished，允许「开启新篇章」或「换剧本」。
3. **场景卡模板扩展**：`template.main_clock {name, segments, kind}`、`stages[]`、`ending_texts {strong|weak|miss}`。
4. **UI**：主持台 + 顶栏显示格子进度（正向/威胁两色）；结局卡（尾声）；不做全屏 CG。

### P3 · 人物闭环（「XX 正在赶来…」）

1. **实体状态机**：`trpg_entities.status` 扩展 `arriving | active | departed`（现 active/pending/cleared 语义映射）；
2. **工具**：`enter_character(entity, role?, scene?)`（扩展 `show_portrait`：生成中→占位，完成后→立绘）、`exit_character(entity)`；
3. **异步生成**：复用任务表模式（`tts_tasks`/`pitch_extract_jobs`）建 `trpg_portrait_jobs`；前端先出**占位卡**
   「老陈正在赶来…」+ 进度/失败重试；图好后原地替换（消息流 NPC 小头像 + 立绘展台）；
4. **在场角色条**：顶栏/主持台列当前场景 `active` 实体（SillyTavern members 简化版），可点开人物卡；
5. 可选（可推迟）：NPC 情绪三轴（rel.attitude/trust 已有部分）、离场清理。

### P4 · 道具 / 动作 / 战斗（工程量最大，可推迟）

1. **道具**：`pc.{名}.inventory` 由字符串升级为结构化条目（或新 `item` 实体）：`{name, qty, effect, consumable}`；
   工具 `grant_item` / `use_item`（校验+扣减+效果）；UI 道具面板（点用）；DM 叙述提到物品时由提取器落库（已有 extractor 可扩）。
2. **攻击**：`attack(target, weapon?, effects?)` 工具 → 命中判定 + 伤害骰 + HP 写回（复用 `apply_dice_delta` 路径）；
   产出**战报卡**（现有 dice 卡升级：攻击者/目标/命中/伤害）。
3. **遭遇（encounter）状态**：先攻序、当前回合、参战者 HP/状态（facts 或新表）；`start_encounter` / `next_turn` / `end_encounter`；
   DM 在工具循环里按回合顺序推进；「NPC 回合由玩家触发」（F&F 做法，适合异步聊天节奏）。
4. **动作面板**：每回合 AI 给 3~4 个建议行动（`quick_actions`，TRPG_Agent）；点击=快捷输入或直接工具调用；
   属性检定沿用现有 D20 桌骰（立绘展台已有入口）。
5. **反馈**：HP 条实时刷新、武器/道具消耗可见、战斗结束给经验（我们的 XP 已有 `stats/progress` 口径，需定跑团经验来源）。

### 明确不做（本轮）
- 每回合实时生成立绘（成本/延迟）；视频立绘；
- 硬性 Game Over 删档（挫败感；失败=故事转折）；
- 开放结局/无限流（gal 设计文的批评点；跑团必须有收束点）；
- 完整 D&D 规则模拟（属性/职业/法术全栈）——保留 `pc/scene` 轻数值。

## 5. 风险与取舍

| 风险 | 对策 |
|---|---|
| 复杂度爆炸（战斗/道具全模拟） | 三层分离的最小版：引擎管硬状态 + 工具收提案 + LLM 只叙事（AITRPG/TRPG-master/DiceFrame 共识） |
| 自由度 vs 收束 | 硬触发只放章节门/结局（ZRIC 的 hard 触发），其余 soft 提示 |
| 数值通胀/口径漂移 | 新字段先登记 `constants.DOMAIN_PROPERTIES` 白名单；不进 DnD 全属性 |
| LLM 不遵守工具约定 | 现状已有：工具是唯一写路径 + 错误文本回填 + 系统卡兜底（docs/52 口径不变） |
| 成本 | 进度/结局用规则+模板渲染（零 LLM）；立绘/生成走异步任务与开关 |

## 6. 待拍板（组长）

1. 推进度：**威胁钟 + 正向钟**（BitD）还是 **进度轨 + 结算判定**（Ironsworn）或两者混用？（建议混用：主线=钟，支线=轨）
2. 结束：是否允许玩家**主动发起收尾**（Ironsworn 式）？尾声卡作为一局归档？
3. 战斗做到哪一档：A 判定卡增强（attack 工具，无回合）｜B 轻遭遇（先攻/回合/HP）｜C 完整面板（道具+技能+状态）
4. 道具：facts 扩展 还是 新 `item` 表？（建议先 facts 扩展，量大再迁表）
5. 跑团是否给 XP（并入现有 `stats/progress`）？
