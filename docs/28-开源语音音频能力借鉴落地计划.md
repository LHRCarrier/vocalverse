## 3. 详细设计（P0）

### 3.1 P0-A · 前端音频底座（分层地基，本期实现）

> **⚠️ 依赖名勘误（地基教训）**：`pnpm add wavesurfer` 装到的是社区同名占位包 `wavesurfer@1.3.4`（官方包名是 `wavesurfer.js`）。**已修正为 `wavesurfer.js@7.12.11`**（v7，带 `regions`/`timeline`/`zoom`/`minimap` 插件）。基础依赖必须装对包、并核验 `dist/plugins/*.d.ts` 后才动工。

**分层（由低到高，逐层可单测/可复用）**：

1. **格式层 `src/audio/wav.ts`**（纯函数，无浏览器专属依赖，可单测）：PCM(Float32)↔WAV 编码 `encodeWav(samples, sampleRate)`；演示旋律合成 `synthesizeDemoMelody()` 返回 `{ samples, phrases[] }`（零素材、可复现，用于演示/跟唱 demo）。**是「音频数据能被前端认识」的地基。**
2. **交互层 `src/audio/waveform.ts`**（类 `WaveformController`，仿 `recorder.ts` 的类式封装）：初始化/销毁、`load`/`loadBlob`、播放/暂停、`seek`/`jumpTo`、`addRegion`/`clearRegions`、`on(ready/timeupdate/finish/error)`；静默封装 wavesurfer v7 + Regions plugin。**组件层只依赖它，不直接碰 wavesurfer DOM 细节。**
3. **展示层 `src/components/WaveformPlayer.vue`**：薄 Vue 包装器，props（`src|blob`、`height`、`regions[]`）、emit（ready/timeupdate/finish/error）、`defineExpose`（togglePlay/seek/getTime/getDuration）。不掺业务逻辑，可被 ReportView / Shadow 复用。
4. **演示层 `src/views/preview/WavePreview.vue`**（dev-only，走 docs/13 §8 预览工作流 + 删除清单）：示例旋律 / 本地音频 / 麦克风录音 → 同一 WaveformPlayer 渲染波形 + 逐句 region 跳转。

**与既有可视化栈**：`useP5Wave.ts` 是**录音中实时波形预览**，wavesurfer 是**音频文件回放 + region 标注**，定位不同、**并存不冲突**（M3 唱歌逐帧 F0 由服务端 pyin 给，前端仅配 region 图表化）。合并可视化栈需与轴线E选型结论对齐（§3.5）。

**recorder 兜底（P0-A 后续小项）**：`recorder.ts` 在 `MediaRecorder` 不可用或编码不支持时回退 `audio-recorder-polyfill`（MIT），处理 opus/webm→mp3，补 WebView 兼容矩阵。

**本期实测验收**：`/preview/wave` 页可 ① 一键生成示例旋律看波形+3 个 region 逐句跳转、② 选取本地音频、③ 麦克风录音后看波形——三者均能播放/seek/显示时间。门禁：前端 `pnpm lint && pnpm typecheck && pnpm test:run && pnpm build` 全绿 + 生产构建确认预览子树零残留。

### 3.2 P0-B · 服务端 ASR 降级通道（sherpa-onnx Tier-1）

- **动机**：faster-whisper 是目前主 ASR 引擎，但依赖较大、冷启/显存/网络敏感。sherpa-onnx（onnxruntime）提供轻量、离线、多平台（Python 端可直接跑）的第二引擎，可作**降级路径**（faster-whisper 失败/超时/不可用时自动切换），也是移动端原生离线 ASR 的前置技术验证。
- **实现**：`app/audio/asr.py` 增加 `SherpaOnnxASR` 引擎，遵循 app/audio/base.py 的引擎抽象；配置项 `ASR_FALLBACK_ENABLED=False`（默认关闭）；test-only 预览接口 `*_enabled=False` 默认不注册（生产零暴露）。
- **契约**：仅当触发降级时才切换，**对外接口响应外形不变**（envelope 一致），前端无感；契约快照零 diff。
- **模型**：选第 3.3 节的小型流式模型（如 paraformer / whisper tiny 档），验证「离线、体积小、速度可接受」。

### 3.3 关于「浏览器端 WASM 离线 ASR 是否值得做降级通道」的结论

- **值得做，但不是本期主通道，且优先级低于服务端降级与移动端原生。**
- 权衡：vosk-browser（Apache-2.0）与 sherpa-onnx WASM 都能在浏览器跑离线识别，但**模型体积（几十 MB）+ WebView 性能 + 精度损失**决定了它们只适合作**弱网/服务不可用时的兜底**，不适合作日常主 ASR。
- **推荐顺序**：① 先做服务端 sherpa-onnx 降级（P0-B，风险最低、收益直接、且是移动端离线的前置验证）；② 移动端（Android，对接 docs/27）走 **sherpa-onnx 原生插件**而非浏览器 WASM——原生无 WebView 性能/体积包袱，另有离线 TTS/VAD 一并解决；③ 浏览器 WASM 作为最低优先级（更前沿的 PWA 离线兜底）。
- 结论：**WASM 方案可用作降级，但"服务端降级 + 移动端原生"两条路径的性价比明显更高**，建议先做这两条。

### 3.4 发音评分（仅整理借鉴口径 · 非 P0 切片）

- ai-pronunciation-trainer 的核心思路：**语音 → Whisper 转写 → 音素化（eng_to_ipa/epitran） → DTW 对齐参考文本 → 相似度评分**。
- 与 VocalVerse 现状对齐：发音评分目前走 `app/audio/ise.py`（讯飞 ISE）；自研路线已列 wav2vec2 微调（docs/04 M3 门禁）。**建议：不引入 DTW 音素对齐作为并行实现**，仅在「自研评分」设计时参考其「转写→音素→对齐→分」的链路分层；AGPL 红线，不可复制代码。此处只记录决策，本期不动。

### 3.5 与轴线E（M3 唱歌可视化选型）对齐

- 轴线E 已对 M3 唱歌可视化作过选型结论。本计划新增的 wavesurfer.js 作为「逐句回放 + region 标记」组件，视为对轴线E 可视化栈的**补充确认**，不推翻其结论；若轴线E 另有指定可视化方案，以轴线E 为准，wavesurfer 仅作回放/交互增强。实施前由组长确认无冲突。

## 7. 答辩口径

- 调研方法：node 抓取 GitHub 元数据/README + npm 许可证核验（本机 TLS 拦截，普通 fetch 失败）。
- 许可证红线：代码级复用只接受 MIT / Apache-2.0 / BSD-3；GPL/LGPL/AGPL 仅架构借鉴；无 LICENSE 一律不碰。
- 落地选型：**回放/逐句波形 → wavesurfer.js；录音兜底 → audio-recorder-polyfill；离线 ASR → sherpa-onnx（先服务端、后移动端原生）；浏览器 WASM 仅作弱网兜底**；pitchfinder（GPL）不引入。
- 「两周能落地」：P0-A（wavesurfer + recorder）风险最低、收益最直接；P0-B（服务端 ASR 降级）为其扩展；P0-C（跟读交互）为体验增强。
