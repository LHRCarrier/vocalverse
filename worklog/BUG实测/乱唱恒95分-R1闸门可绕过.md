# BUG：v4 反乱唱闸门（R1）可被绕过 → 乱唱/不跟拍恒得节奏 95（口径升 v5）

- **发现**：2026-09-10 · 唱歌模块七路拷问（B 路：后端口径探针；主代理读码复核 + 端到端复现）。
- **修复**：2026-09-10 · 执行人：AI 代签（正式署名待组长确认）· **组长拍板：方案 A（逐句判据）+ 升口径 v5 + 新增 `reason='no_onset'`**。
- **影响面**：`app/audio/sing.py` 评分主链路（R1 起唱判据）——**所有跟唱用户的节奏维度（权重 0.2）与综合分**；`sing_attempts.scoring_version`（v4 → v5）、`lines[i].reason` 值域、`alignment` 字段（+`breath_structure`）。属**口径变化**（非纯 bug 修复），故升版本留痕。

## 复现

1. 录一段「**起始 ~1s 静音 + 之后一口气唱到底**」（手机录音几乎必然带起始静音；乱唱/哼唱同样适用）；
2. 逐句评分 → 每句窗口第 0 帧已有声；
3. 实际（v4）：`has_breath_structure` 因起始静音为真 → 放行闸门；`_first_new_run` 走 `start == 0` 分支 → `onset_dev=0` → `rhythm_score_from_dev(0)=95`；
4. 即 **v4 想修的真机「胡乱唱也拿 52.9 / 节奏 95」在常见录音形态下复活**（v4 只封住"整首一处静音都没有"这一种形态）。

探针（B 路，纯函数）：
```
has_breath_structure([0]*31 + [220]*300, hop=32)  → True      # 闸门放行
detect_onset_ms([231.7]*120, None, hop=32)        → 0.0       # 窗口全有声 → "精准起唱"
rhythm_score_from_dev(0.0)                        → 95.0
```

## 根因

两层判据各自"局部正确"，组合起来失效：

1. **闸门层次错**：`has_breath_structure`（`sing.py:473-498`）回答的是"**整轨**有没有换气"，而该问的是"**这一句**是不是新起唱"——整轨判据把"任意一处静音"当成全曲都有句结构（起始静音/前奏/句间一次换气即可满足）。
2. **`start == 0` 分支把"延续"当"精准"**：`_first_new_run`（`sing.py:781`）`if start == 0 or not flag[start-gap:start].any(): return start`——窗口第 0 帧就有声时直接返回 0 帧作为起唱点 → 偏差 0ms → 满分。该分支在 v3 是"兜底"（那时没有闸门），v4 用整轨闸门去堵它，堵漏了。
3. 结果：节奏维度对"完全不跟拍"继续失效，乱唱综合分被 `0.2×95` 抬高。

## 修复（口径 v5）

1. **新增纯函数** `onset_is_continuation(track_f0, frame_start, hop_ms)`：句窗首帧有声**且**其前 ≥`ONSET_SILENCE_GAP_MS`(150ms) 内已有声 → 判**延续**（无新起唱）。判据只看"这一句与它前面 150ms"，与录音起始静音/前奏无关，因此堵住整轨闸门的破口。
2. **逐句分支**（`sing.py` 句循环）：延续 → `onset_dev_ms=None`、`rhythm_score=None`、`reason='no_onset'`（**该行仍非 skipped**：音准/发音照常评分）；否则照旧走 `detect_onset_ms` 定位新起唱并给节奏分（**不误杀**确有起唱的真唱）。
3. **`has_breath_structure` 降级为诊断留痕**：`alignment.breath_structure` 落库供抽检/复盘，**不再作判据**（函数与既有测试保留，避免"删函数连带删覆盖"）。
4. **依赖护栏**（同一批）：`_weighted_overall` 在 `total_w <= 0` 时返回 `None` —— v5 会让更多句子 `rhythm=None`，若同时 `wp=0`（参考覆盖 <40% 的 item8 政策）且发音缺失，旧实现 `ZeroDivisionError` 会让**整次评分作废**（lines 不落库、额度已扣）。
5. **版本与契约**：`SCORING_VERSION='v5'`；docs/06 §9.4 增「口径 v5」表（R1 判据 + 留痕 + 护栏）；docs/10 §4.3 登记 `reason` 新增值 `no_onset`（非 skipped 语义）与 `alignment.breath_structure`；docs/21 §3.6 评分口径行同步。**未改动**：权重基线 / 映射表 / R2 命中率衰减 / R3 覆盖率置信度 / `ALIGN_METHOD`。

## 踩坑

1. **判据的"层次"要和问题同层**：问题出在"逐句是否新起唱"，用"整轨有没有换气"去挡，必然被"录音头部的静音"绕过——**闸门粒度错了，再严的阈值也白搭**。
2. **`start == 0` 这类"兜底分支"是长期风险点**：它在某个版本是合理的兜底，换了上下文就变成"把延续当精准"的漏洞；改判据时要专门审这种分支（本次已把它从判据路径移出）。
3. **口径变化必须升版本 + 留痕**：否则看板/抽检会把 v4/v5 的分数混在一起比较；`reason='no_onset'` 与 `alignment.breath_structure` 就是本次的可解释锚点。
4. **一个修复可能放大另一个已知缺陷**：v5 让 `rhythm=None` 更常见，正好踩到 `wp=0` 除零路径 → 依赖护栏必须同批修（否则"修好 A、炸出 B"）。
