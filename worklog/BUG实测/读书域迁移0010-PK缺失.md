# 读书域迁移 0010：PG 建表失败 InvalidForeignKey（books 无唯一键）

> 归档日期：2026-09-10 · 发现人：组长（本机 `uv run alembic upgrade head` 实跑复现）· 分支：feat/novel-reading-main

## 复现

```powershell
cd services/python
uv run alembic upgrade head
```

```
psycopg.errors.InvalidForeignKey: there is no unique constraint matching given keys for referenced table "books"
...
CREATE TABLE book_chapters (... CONSTRAINT fk_book_chapters_book_id_books FOREIGN KEY(book_id) REFERENCES books (id) ...)
```

（迁移事务回滚 → 后续 `seed_reading` 报 `relation "books" does not exist`，为连锁反应。）

## 根因

`alembic/versions/0010_reading.py` 的辅助函数 `_bigint_pk()` 漏了 `primary_key=True`：

```python
def _bigint_pk() -> sa.Column:
    return sa.Column(
        "id", sa.BigInteger().with_variant(sa.Integer(), "sqlite"),
        sa.Identity(always=False), nullable=False,   # ← 缺 primary_key=True
    )
```

→ `books.id` 生成的是**普通 BIGINT 列**（无 PK/UNIQUE 约束）；PG 对 FK 引用列要求引用目标存在
UNIQUE/PK，建 `book_chapters` 时直接拒绝。
模型侧无此问题（`app/models/base.py::bigint_pk()` 带 `primary_key=True`），故
`create_all_for_tests`（SQLite 单测）与**离线 SQL 渲染**（`test_alembic_offline_pg_render`
只拼字符串不在真库执行）都不暴露 → CI 绿、真库红。

## 修复

- `0010_reading.py::_bigint_pk()` 补 `primary_key=True`（一行），8 表全部经此辅助，一处修复全覆盖；
- **回归守卫**：`tests/test_models.py` 在 `test_alembic_offline_pg_render` 后追加逐表断言——
  从渲染输出抽 `CREATE TABLE <table> (` 块，断言含 `PRIMARY KEY`（新增 `READING_TABLES` 常量；
  修复前该断言必失败，修复后通过）。

## 踩坑

1. **离线渲染 ≠ 可执行验证**：`alembic upgrade --sql` 只产出 DDL 字符串，PG 的运行时约束
   （FK 目标须 UNIQUE/PK、类型/默认值语义）不在其验证范围；凡新建表迁移，**合入前必须在真 PG
   上跑一次 upgrade + downgrade 往返**（本机 `docker compose up -d postgres` + 方式 B 命令即可）。
2. **迁移辅助函数要与模型辅助函数同构**：迁移照抄模型风格时逐属性核对（本项目
   `base.py::bigint_pk()` 即为范本——`primary_key=True` 不可省）。
3. 种子脚本报 `relation "books" does not exist` 时先查迁移状态（`alembic current`），
   别直接改 seed——本次即迁移回滚后的连锁反应。
