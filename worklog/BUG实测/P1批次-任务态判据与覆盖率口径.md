# P1 批次（后端）：任务态 done 判据与 R3 覆盖率分母

> 来源：唱歌模块七路拷问（`local/唱歌模块全链路拷问报告-2026-09-10.md` §3.2 P1-1 / P1-10）。
> 修复：2026-09-10 · 执行人：AI 代签（正式署名待组长确认）。

## 缺陷 1（P1-1）：评分**已完成**的 attempt 被报「失败」

- **复现**：唱一首有效句覆盖率 <40% 的歌（或整段静音/极短）→ 评分完成（`status=done`）→ 等 30 分钟（Redis 任务态 TTL）或重启服务 → 再查 `GET /sing/attempts/{id}/status`。
- **实际（修复前）**：返回 `failed` +「评分任务中断（服务重启或结果超时）」50002；而同一条 attempt 的 `GET /sing/attempts/{id}` 仍返回 200 + 逐句结果 → **自相矛盾**，且前端见 failed 就不再拉结果（`composables/sing.ts` 对应分支），用户报告入口消失、重录再扣一次额度。
- **根因**：v4/v5 口径**允许 `overall_score` 为 NULL**（覆盖率 <40% → 不给综合分，`audio/sing.py:overall = None if conf <= 0`），而任务态丢失后的 DB 兜底判据是「`overall_score is not None` 才算 done」（`sing/service.py`）→ 这批"合法完成"的行被判成未完成。`docs/21:175` 当时把这个错判据写成了契约。
- **修复**：新增 `_attempt_finished(attempt)` = 「`lines` 非空 **或** `overall_score` 非空」，与结果端点的可读判据同源；两者皆无 → 仍 `failed` + 50002（真未算完）。依据：docs/06 §9.4（v4 R3/v5）、docs/10 §4.3（lines 为逐句唯一真源）、docs/21 §3.6（已同步改写该判据）。
- **验证**：`tests/test_sing_service.py::test_task_lost_overall_none_still_done`（**修复前必失败**：旧判据下 `assert 'failed' == 'done'`）+ 反向护栏 `::test_task_lost_unfinished_still_reports_interrupted`（真未算完仍报 50002）。

## 缺陷 2（P1-10）：用户把有参考的句子全唱好，仍拿不到综合分

- **复现**：一首**参考旋律只提取成功 1~2 句**的歌（`no_ref` 句多）→ 用户完整唱一遍。
- **实际（修复前）**：`user_coverage = 有效句/期望句`（分母含 `no_ref` 句）→ 例如 6 句里只有 1 句有参考且用户唱全 → `0.167 → conf=0 → overall=None`；文案还写「有效句仅 17%（<40%），不足以评分——请完整演唱一遍再评」**把服务端参考缺失说成用户漏唱**；同时同一"参考缺失"已被 item8（`ref_coverage → pitch_weight=0` + `weight_note`）惩罚一次 → **二次惩罚**。
- **根因**：R3 的语义是"**用户**漏唱程度"，分母却含了"用户无论如何都拿不到分"的 `no_ref` 句。
- **修复（口径 v5.1）**：分母 = `期望句 − no_ref 句`；覆盖率只表达用户漏唱，参考缺失仍由 item8 的 `weight_note` 说明；全为 `no_ref` 时 `user_coverage=None`（不惩罚）。**分数公式不变**（`scoring_version` 仍 `v5`，仅分母口径修正）。
- **验证**：`tests/test_sing_scorer.py::test_user_coverage_excludes_no_ref_lines_v5_1`（**修复前必失败**：`assert 0.1667 == 1.0`）+ 反向护栏 `::test_user_coverage_still_penalises_real_misses_v5_1`（用户真漏唱仍降置信度）。
- **既有用例语义更正**：`test_aggregate_ref_coverage_low_excludes_pitch` 原断言（`coverage_conf==0`、`overall is None`）**就是"参考缺失二次惩罚用户"的固化**，已按 v5.1 更正并在 docstring 写明"语义有意变更"——这是本轮唯一一处**预期行为改变**：参考覆盖不足时不再"不给分"，而是"给分但带 `weight_note` 标注 + 音准不计入"。若组长认为该类歌**仍不该给综合分**，请拍板回退（改动点仅 `aggregate_result` 一处 + 该用例）。

## 踩坑

1. **"合法空值"必须进判据设计**：任何"用某字段非空表示完成"的判据，都要先问"这个字段在什么情况下**合法为空**"——v4 引入 `overall=None` 时没同步改判据，于是"完成"被读成"丢失"。
2. **一句话文案能暴露口径错误**：「请完整演唱一遍再评」出现在"服务端缺参考"的场景，就是这个分母错了的信号（文案比代码更早讲出真相）。
3. **旧测试可能固化了旧 bug**：改正分母必然踩到把旧行为写死的用例——处理方式是"改断言 + 在 docstring 写明语义变更与依据"，而不是把实现改回错的口径。
