# BUG 实测：跟唱「重录」永久失败 —— 同会话幂等分支无条件复用失败行（P1-3）

- **日期**：2026-09-10
- **发现**：`local/唱歌模块全链路拷问报告-2026-09-10.md`（7 路对抗审计交叉命中：B-F7 / C-#3 / G-#9）
- **范围**：`services/python`（`app/sing/service.py`、`app/models/practice.py`、迁移 0012）
- **影响**：一次评分失败（算法异常、服务重启、Redis 任务态过期）后，**该会话彻底废掉**——用户点「重录/再来一次」只会拿回同一条 `failed`，既读不到结果也不能重录；且无唯一键兜底，并发双击/弱网重传可落**两行** attempt（两份 pyin/DTW CPU + 看板重复计数）。

---

## 1. 复现

真机/接口序列（修复前）：

1. `POST /api/v1/sessions`（`kind=sing` + `song_id`）→ `session_id`；
2. `POST /api/v1/sessions/{id}/audio`（整首 ≤180s）→ `{attempt_id, status:"queued"}`；
3. 评分失败（例：容器内 ffmpeg/pyin 异常；或服务重启导致任务态丢失）→ `GET /sing/attempts/{id}/status` 得 `status=failed` + `code=50003`（或 50002「任务中断」）；
4. 用户点「再来一次」，**同一会话**重新上传 → 仍然 `status=failed`（`attempt_id` 与第 2 步相同），永远不会变成 `queued`/`done`。

自动化证据（把修复回退后跑新测试，`assert` 直接打在用户可见状态上）：

```
tests/test_sing_service.py::test_submit_retry_after_failure_resets_draft_in_place
E  assert 'failed' == 'queued'      # 修复前：重传拿到的是那次失败
tests/test_sing_service.py::test_submit_retry_after_restart_recovers_draft
E  assert 'failed' == 'queued'      # 修复前：重启后遗留草稿永远报「任务中断」
```

并发落两行的证据（迁移前）：`sing_attempts` 上**没有任何唯一键**，`submit` 是「先查后插」（`select ... .first()` → `db.add`），两个并发请求可同时通过检查各插一行。

## 2. 根因

`app/sing/service.py:submit_song_audio` 的幂等分支只做了"存在即复用"：

```python
existing = db.execute(
    select(SingAttempt).where(SingAttempt.user_id == user_id, SingAttempt.session_id == session_id)
).scalars().first()
if existing is not None:
    return await _status_payload(int(existing.id))   # ← 不区分是否已定稿/在跑/失败
```

- 失败行（`lines=[]`、分数 NULL、任务态 `failed`）被**无条件**当成"已有结果"返回 → 重试入口被自己的幂等吃掉；
- 想绕开只能"再插一行"，但那时既没有唯一键约束（能落两行），也没有任何清理路径；
- DB 侧缺 `UNIQUE(user_id, session_id)`：幂等只是应用层君子协定，并发下失效。

## 3. 修复

1. **数据层兜底**（迁移 `0012_sing_attempt_idempotency_key.py` + 模型）：
   `uq_sing_attempts_user_session UNIQUE (user_id, session_id)`；`session_id` 可空（会话删除 SET NULL）→ 唯一索引对 NULL 不冲突，历史/脱离会话的行不受影响。
   迁移自带**重复行自检**：若库中已存在重复 `(user_id, session_id)`，直接 `RuntimeError` 并打印清单（**不静默删数据**——合并/清理需人工决定）。开发库实测：22 行、0 个重复组，迁移可直接执行。
2. **写侧三分支**（`submit_song_audio`）：
   - ① 已定稿（`lines` 非空 **或** 有综合分，判据同 `_attempt_finished`）→ 幂等返回既有结果；
   - ② 任务态 `queued`/`processing` → 幂等返回状态（**不重复扣 sing/ise 桶、不重复建任务**，防双击）；
   - ③ **未定稿草稿**（无逐句结果、无分、任务态已丢）→ **就地重置该行**：换素材/时长、清空 `lines`/`alignment`/`ref_version`、`scoring_version` 刷成当前世代，`attempt_id` 不变，然后正常走扣桶+建任务。
   语义依据：docs/10 §4.3「分数 NULL = 未定稿草稿」——只有未定稿行可重写，已定稿行的不可变语义不变。
3. **文档同步**：docs/10 §4.3 增「迁移 0012 增量」条；docs/21 §3.6 把「幂等」一行改写成三分支语义（含"重启遗留草稿可就地重跑"）。

## 5. 踩坑

1. **迁移里的"在线才行"的语句必须挡离线渲染**：`alembic upgrade --sql`（PG 方言离线渲染，`tests/test_models.py::test_alembic_offline_pg_render` 会跑）没有真实连接，`op.get_bind().execute(...)` 返回 `None` → `AttributeError: 'NoneType' object has no attribute 'fetchall'`，而且自检的 `SELECT` 还会被混进 DDL 脚本。修法：`if not context.is_offline_mode():` 守卫（已加注释说明原因）。
2. **任务态内存兜底是模块级 dict，会跨用例残留**：`_MEM_TASKS` 不随 SQLite 测试库重建而清空，attempt id 复用 → 直接断言「无任务态 → failed」会读到**上一个用例**留下的 `done`（实测报 `assert 'failed' == 'done'`）。要模拟"服务重启/Redis 过期"，得 monkeypatch `_task_get` 返回 `None`（这也正是线上真实语义），断言任务态时再临时换回真实实现。
3. **幂等键的语义要写进文档，否则会被读成"不可重试"**：「同会话只有一行」是人看见"唯一键"最容易误解的点——唯一键不等于"一次机会"，未定稿草稿行可重写（第 3 节 ③）必须与唯一键**同时**登记在 docs/10 + docs/21，否则下一个人来改会顺手删掉重置分支。
