# 读书域批注 · 查看已批注句子只能点空格（命中区 4.6px），无句首角标

> 归档日期：2026-09-09 · 发现人：组长手机实测（`worklog/BUG记录/读书域系列BUG9-09/已批注句子系列BUG/9-09.txt` Bug2）· 模块：`apps/web` `MobileReaderView` / `useReaderTap` / `reader-words.ts` / `reader-uic.css`
> 修复 commit：见本条目所在 PR（`fix(reading)`）

## 复现

1. 对某句做批注（高亮或笔记均可）；
2. 想再看这条批注 —— **点被批注的文字只会弹出查词卡**，点句尾的笔记角标（只有 kind='note' 才有）才可能打开；
3. 用户原话：「只能通过点击单词之间的空格（有些空格小的根本点不到）」；
4. 实测空格命中区仅 **4.6px** 宽，真机上基本点不中。

## 根因

三处叠加（修复前 HEAD `63fcaee`）：

1. `useReaderTap.ts:49-55` 点击分发**词段优先**：`segEl.dataset.word` 命中即 `openWord()` 并 return，
   被批注的词永远走不到 `:58-62` 的「非词批注段 → openNote」分支 —— 而批注整句时批注覆盖的是词；
2. 唯一可见标记 `.u-rd__annmark` 只在 `seg.noteMarker && seg.ann` 时渲染
   （`MobileReaderView.vue:325-331`），而 `noteMarker` **只对 `kind === 'note'` 的批注**打
   （`reader-words.ts:140`）→ 纯高亮批注**零标记**；
3. 该标记只有 **3px 宽**且落在**段尾**（`reader-uic.css:230-237`），即便有也难点。

## 修复

1. **句首批注角标**（用户建议的形态）：任何 `kind` 的批注都在句子开头渲染 `.u-rd__sentmark`，
   颜色取该句第一条批注色（过白名单），点击 → `openSentence(idx)`：
   - 该句 1 条 → 直接打开批注卡；
   - 该句多条 → 打开「本句批注」列表（复用 `MobileAnnotationSheet mode="list"` + `title` 属性），
     角标加 `is-multi` 圆点提示；
2. **动作条「看批注」大热区入口**：选中句子后，若该句有批注，动作条出现「看批注」按钮
   （≥44px 高，`MobileReaderSelectionBar` 新增 `has-annotation` prop + `open-note` 事件）——
   角标是快捷方式，按钮才是可靠入口；
3. 角标采用**行内**形态而非绝对定位：`.u-rd__sentence` 是 inline span，句子从行中间开始时
   `position:absolute; left:-14px` 会压到上一句文字上；行内元素永远落在句子起点、零重叠。
   视觉 5×0.9em，靠 padding 撑到约 11×29px 命中区。

## 踩坑

1. **绝对定位的「左侧沟」只在行首存在**：`.u-rd__main` 的左内边距只有 20px，`left:-14px` 看似够用，
   但行中句子的「左侧」是上一句的文字 —— 会遮挡并抢走点击。行内形态牺牲 ~11px 排版宽度，换零重叠。
2. **`outline` 不能当触控热区**：`outline` 只绘制、不参与命中测试，且被 `overflow-y:auto` 裁切；
   用 `padding` + `background-clip: content-box` 才能既扩大命中区又不改变视觉宽度。
3. **不要复用 `noteMarker` 做句首角标**：段尾笔记角标被 `reader-words.test.ts` 与
   `MobileReaderView.test.ts` 锁定，复用会同时破坏既有语义与用例。
4. **弹层必须进返回层序**：新增「本句批注」列表/批注卡后，`useReaderBackLayers` 的数组要同步插位置，
   否则安卓返回键会先退页（`MobileReadingBack.test.ts` 此前只覆盖设置弹层）。
