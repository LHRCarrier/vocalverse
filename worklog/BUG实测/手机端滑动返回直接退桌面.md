# 手机端手势滑动返回直接退到桌面（壳内无人接管系统返回）

> 归档日期：2026-09-10 · 发现人：组员手机实测（组长转达）· 模块：`apps/mobile`（Capacitor 壳）+ `apps/web` 返回桥

## 复现

真机（手势导航）在任意二级页（书详情/阅读器/私信…）从屏幕边缘右滑 —— 期望回到上一页，
实际**直接回到手机桌面**（App 被结束）；返回键同样。

## 根因

1. **Capacitor 8 核心不再处理返回**：全仓 grep `apps/mobile/node_modules/@capacitor/android/capacitor/src/main/java/com/getcapacitor`
   下 `BackPressed|canGoBack|goBack` **零命中**；`BridgeActivity.java` 也没有 `onBackPressed` 重写。
   返回处理在 Capacitor 3+ 已迁到 `@capacitor/app` 插件，而本壳工程 `package.json` 只装了
   `@capacitor/{android,cli,core}` —— **没有任何返回接管**。
2. 于是系统返回落到 `Activity` 默认行为 = `finish()` → 回桌面（WebView 历史、SPA 路由全被跳过）。
3. 附带约束：`variables.gradle` `targetSdkVersion = 36`，Android 16 起对 targetSdk 36 的应用**默认启用
   预测式返回（predictive back）** → 只重写已废弃的 `onBackPressed()` 也可能收不到回调。

## 修复

**原生（`apps/mobile/android/.../MainActivity.java`）**：用 AndroidX `OnBackPressedDispatcher`
注册回调（同时覆盖旧版返回键与 13+ 返回手势），处理顺序与 Android 通用习惯一致：

```
1) 页面弹层优先：webView.evaluateJavascript("window.__vvNativeBack()") === true → 本次返回结束
2) 否则 webView.canGoBack() → webView.goBack()（SPA 由 vue-router popstate 接管 = 回上一页）
3) 历史到底（App 首页）→ finish()（回桌面，与系统返回等价）
```

**Web（`apps/web`）**：新增 `composables/useNativeBack.ts` —— 处理器注册表（后进先出），
`main.ts` 装 `window.__vvNativeBack`，`App.vue` 注册「关账户抽屉」，阅读器注册「关词卡/批注/批注列表/
设置/目录/听书条」6 类弹层。未消费则返回 false 交给原生。

## 踩坑

1. **别只依赖 `webView.canGoBack()`**：SPA 的 pushState 条目在各版本 WebView 里行为不完全一致，
   而且弹层需要「先关弹层再回退」——所以固定顺序是「页面优先 → 历史回退 → 退出」，而不是只看 canGoBack。
2. **退出用 `finish()` 而不是再调 `dispatcher.onBackPressed()`**：后者在预测式返回模式下存在重入/
   异常风险（AndroidX 对 `onBackPressed()` 有 IllegalStateException 守卫），`finish()` 在根页面与
   系统返回等价、可预期。
3. **`evaluateJavascript` 是异步回调**：返回 "true"/"false" 字符串（JSON 形式），判等要用
   `"true".equals(value)`；页面未加载（冷启）时 `window.__vvNativeBack` 为 undefined → false → 退出，
   符合预期。
4. **浏览器里这段是死代码**：`__vvNativeBack` 只有原生壳会调用，Web 端无任何调用方，不影响 Web 形态。
