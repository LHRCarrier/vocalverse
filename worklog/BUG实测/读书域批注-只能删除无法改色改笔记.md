# 读书域批注 · 已批注句子只能删除，颜色与笔记都改不了

> 归档日期：2026-09-09 · 发现人：组长手机实测（`worklog/BUG记录/读书域系列BUG9-09/已批注句子系列BUG/9-09.txt` Bug1）· 模块：`apps/web` `MobileAnnotationNoteSheet` / `useReaderAnnotations`
> 修复 commit：见本条目所在 PR（`fix(reading)`）

## 复现

1. 进阅读器，对任意句子做批注（写笔记 + 选色）；
2. 点该句的批注角标 → 弹出批注卡；
3. 卡上只有「删除批注」「关闭」两个按钮 —— **改色无入口、笔记是只读文本**。

## 根因

纯前端缺线，后端接口早已具备：

- `MobileAnnotationNoteSheet.vue`（修复前）：emits 只有 `update:open` / `delete`，笔记渲染为只读
  `<p>{{ props.item.note }}</p>`；
- `apps/web/src/api/reading.ts:232-242` 的 `patchAnnotation()` **全仓零调用**（grep 确认）；
- 后端 `PATCH /api/v1/reading/annotations/{id}` 在 `services/python/app/api/routes/reading.py:440-461`
  已实现并已有测试（`tests/test_reading_routes.py` 绿）→ 无需任何后端改动。

## 修复

`MobileAnnotationNoteSheet.vue` 改为「查看即编辑」：

- 顶部色板（4 色，当前色高亮 `is-active`，`role=radiogroup` + `aria-checked`）→ 改色；
- 笔记改为 `textarea`（预填服务端值）→ 改内容；
- 新增「保存修改」→ emit `save: [{id, note, color}]` → `useReaderAnnotations.update()` →
  `patchAnnotation(id, {note, color, kind})` → `refresh()` → 用**服务端返回值**回填弹层；
- 笔记清空 → `kind` 回落 `highlight`（与创建语义一致，避免「note 但没笔记」的脏数据）；
- 颜色永远过 `safeAnnColor()`：后端 `update_annotation` 对 `color` 没有 `or None` 处理，
  空串/脏值会被原样存库（`services/python/app/reading/service.py:419-420`）。

并发/失败处理：保存中的禁用态由**父级** `noteBusy` 驱动（`useReaderAnnotationUi.ts`），
`finally` 复位 —— 早期实现把 `saving` 放在子组件、只在 `watch(open)` 里复位，PATCH 失败后
「保存修改」会永久禁用、无法重试（自查发现并修正）。

## 踩坑

1. **先查后端有没有现成能力**：`patchAnnotation` 从读书域上线起就存在、后端 PATCH 也早已可用，
   缺陷纯粹是「前端没接线」——直接加后端接口会白写一套。
2. **`Teleport to="body"` 的测试残留**：VTU 的 `unmount()` 不保证摘掉 teleport 节点，
   上一条用例的弹层会被下一条用例的 `document.querySelector('.u-rd-ann')` 先命中（假失败）；
   测试文件需 `afterEach(() => { document.body.innerHTML = '' })`。
3. **保存中的禁用态归属**：放在子组件里 + 只在 `watch(open)` 复位 → 失败即永久禁用；
   改由父级持有（`noteBusy`）+ `finally` 复位才是对的。
