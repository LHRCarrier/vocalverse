# 管理端控制台「登录后全页 401」：Python 密钥留空 + 续期令牌被写成 `"undefined"`

> 归档日期：2026-09-11 · 发现人：Faust-sudo（实测复现）· 分支：fix/console-post-login-401

## 复现

前置：控制台已有超管账号（否则连登录都过不去，那是另一个坑，见 `方式A`/bootstrap 类条目）。

1. `pwsh -File scripts/dev-up.ps1 start -WithConsole` → 浏览器打开 `http://localhost:5174`；
2. 用 `admin` / `demo123456` 登录 → **登录成功**，顶栏显示
   「超级管理员 · 已授予 36 个权限码」，左侧菜单完整渲染；
3. 打开 DevTools → Network，刷新页面 → 出现**两片互不相干的 401**：

| 请求 | 归属 | 数量 |
|---|---|---|
| `GET /api/v1/console/ops/overview`、`ops/services`、`ops/alerts/events`、`ops/traces/stats`、`library/books` … | **Python** :8000（`/api/v1` 代理） | 9 条左右 |
| `POST /manage/api/v1/console/auth/refresh` | **Java** :8080（`/manage` 代理） | 1 条 |

页面表现：工作台/运维各卡片全是 `—`，且报错**完全没提"密钥"**。

## 根因

**这是两个独立缺陷，必需分别修；只修任一个都仍然是坏的。**

### 根因 1：两个控制台密钥都留空 → Python 侧 fail-closed（占那 9 条 401）

`VOICEVERSE_CONSOLE_JWT_SECRET`（Java）与 `APP_CONSOLE_JWT_SECRET`（Python）**都没配**。
两侧留空的失败方式**不对称**，这正是它难排查的原因：

- **Java 侧留空 → 有显式回退分支**（`ConsoleJwtService`：回退用 `JWT_SECRET` 签发）
  → **登录看起来完全正常**，令牌也签得出来；
- **Python 侧留空 → fail-closed**（`app/console/api/deps.py`：
  `if not settings.console_jwt_secret: raise ConsoleBizError(401, 46001, …)`，
  宁可控制台不可用，也绝不用空密钥"验签通过"）→ **所有 Python 域控制台端点一律 46001/401**。

⇒ 典型症状就是本案：**能登录进控制台，但运维 / LLM trace / 书籍 / 媒体页面全报错**，
而报错里不会提"密钥没配/不一致"。

**仓库级根因（这才是关键）**：`.env.example` 把 bootstrap 账号给了**可直接复制的值**
（`VOICEVERSE_CONSOLE_BOOTSTRAP_USERNAME=admin` / `_PASSWORD=demo123456`），
却把这两个密钥**留空**。于是「照 `.env.example` 复制一份 `.env`」这条**最自然的路径必然掉坑**：
账号能建出来、能登录，然后页面全 401。文档把陷阱描述得很清楚，
但同一个文件里的示例值自相矛盾。

### 根因 2：前端按平铺读续期响应 → 令牌被写成字符串 `"undefined"`（那条 refresh 401）

`apps/admin/src/api/client.ts` → `refreshOnce()`：

```ts
const body = (await res.json()) as Envelope<{ accessToken: string; refreshToken: string }>
if (body.code !== ERR.OK || !body.data) return false
saveTokens(body.data)          // ← data.accessToken / data.refreshToken 都是 undefined
```

但后端 `POST /auth/refresh` 回的是 `ConsoleAuthController.SessionView`，
**令牌嵌在 `data.token` 下**（与登录响应同形）：

```json
{"code":0,"data":{"token":{"accessToken":"…","refreshToken":"…","tokenType":"Bearer","expiresIn":900},
                  "adminUserId":1,"username":"admin","roleCode":"super","permissions":[…]}}
```

实测确认 `data.accessToken` / `data.refreshToken` 均为空。于是
`localStorage.setItem(k, undefined)` 把令牌**存成字符串 `"undefined"`**（而不是删除该项）：

- 下一次续期发 `refreshToken:"undefined"` → 服务端 `findByRefreshTokenHash` 查不到 → **46001「刷新令牌无效」**；
- 之后所有请求带 `Authorization: Bearer undefined` → **整站 401**。

**证据链（闭合，非推测）**：Java 日志里的 `46001 刷新令牌无效` 恰好出现在每次
**成功轮换后 ~118ms**；`admin_sessions` 中 5→6 / 7→8 / 9→10 三轮轮换**各紧跟一次**该失败：

```
2026-09-11 08:27:07.467  5 revoked(rotated) → 6 issued
2026-09-11 08:27:07.585  WARN 46001 401 刷新令牌无效     ← 118ms 后
```

⇒ 不是偶发竞态，是「续期一次就坏一次」，access token 15 分钟一过期必然复现。

**登录路径一直是对的**（`stores/auth.ts` 写 `saveTokens(session.token)`）——
**只有续期路径漏了这层解包**，两条路径对同一响应形状的口径不一致。

## 修复

- **根因 1**：`.env.example` 补上同风格的**本地联调值**（与上面 `JWT_SECRET` 同款公开演示值，
  且**刻意与之不同** —— 生产档 Python 会在启动期断言"控制台密钥 ≠ App 密钥"）：
  `vocalverse-dev-console-jwt-secret-0123456789abcdef`，两个键写成同一个值。
  本机 `.env` 同步配置（`.env` 不入库）。
- **根因 2**：`client.ts` 改为 `saveTokens(body.data.token)`，类型改成真实的
  `Envelope<ConsoleSession>`，并加 `!body.data?.token` 守卫 —— 让这个字段路径**由类型和测试守**，
  而不是靠肉眼。
- **同批必须落的第二处（否则修完反而更糟）**：重试分支原为 `noRefresh: false`，
  即每次重试都会**再续期一轮**。修好令牌写入后，「续期永远成功、401 永远不消失」
  就退化成**无限续期循环**（每轮烧掉一条 `admin_sessions` 轮换）。
  此前没暴露，只是因为令牌被写坏成 `"undefined"` 后下一轮必然失败 —— **偶然的刹车**。
  改为 `noRefresh: true`：续期一次、重试一次，仍 401 就清令牌回登录页。

## 踩坑

1. **"能登录"不等于"配置对"**：控制台两侧密钥留空的失败方式不对称（Java 回退、Python fail-closed），
   所以**登录成功反而是最迷惑人的信号**。排查控制台 401 应当**先查密钥对**，
   而不是先从「令牌过期/权限不足」入手 —— 本案 9 条 401 里没有一条是权限问题。
2. **「文档写清楚了」不等于「照做就对」**：`.env.example` 用 12 行注释精确描述了本坑，
   但同一文件里的示例值自相矛盾（账号给可复制值、密钥留空），于是**照着做必然踩**。
   给示例值时要问一句："复制这个文件能不能直接跑通？"
3. **`localStorage.setItem(key, undefined)` 存的是字符串 `"undefined"`，不是删除该项** ——
   它是 truthy，会让 `getAccessToken()` 继续返回"有令牌"，故障因此**延迟一个周期才爆发**，
   且表现为"整站 401"而不是"未登录"。写入令牌前必须校验形状。
4. **修一个 bug 可能拆掉一个"偶然的刹车"**：本案原先之所以没死循环，
   仅仅因为令牌被写坏后下一轮续期必然失败。修好写入后必须**显式**补上单次重试守卫。
   凡"某个错误状态顺手兜住了另一个缺陷"，修复时都要回头看它兜住了什么。
5. **验收要打穿代理**：控制台是双上游（`/manage`→Java、`/api/v1`→Python），
   必须**分别**验证两条链路；只测登录（Java）会漏掉全部 Python 域页面。
