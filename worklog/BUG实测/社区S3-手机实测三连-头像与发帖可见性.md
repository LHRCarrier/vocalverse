# 社区 S3 手机实测三连：顶栏头像不更新 / 发帖后不可见 / 缺「我的发帖」通道

> 归档日期：2026-09-09 · 发现人：组长手机实测（截图 + 三句话）· 模块：`apps/web` `MobileTopBar` / `stores/community` / `MobileComposeView` + `services/java` feed
> 修复 commit：见本条目所在 PR（`fix(web)` / `feat(community)`）

## 复现

1. **头像**：在「我的资料」换头像成功 → 侧边抽屉显示新头像，**顶栏仍是首字母**（截图：`根`）。
2. **发帖**：手机发帖 → 自动回社区首页 → **看不到刚发的帖**；在电脑上刷新页面才出现。
3. **我的发帖**：没有任何入口能只看自己发过的内容（抽屉「社区足迹」指向写死的演示帧 `/m/learn/community`）。

## 根因

| # | 根因（文件:行） |
|---|---|
| 1 | `MobileTopBar.vue` 一直渲染 `avatarLetter`（`auth.me?.nickname.slice(0,1)`），而抽屉早已换 `MobileAvatar` —— 两处头像实现不一致，顶栏漏改 |
| 2 | `stores/community.ts` 的 `load()` 命中按 domain 的缓存就 **return，不发请求**；发帖在 `/m/compose` 页面，回 `/m/home` 时 `load(null)` 命中缓存 → 拿到发帖前的快照（电脑刷新 = 重建 store → 重新拉，所以看起来「刷新就有」） |
| 3 | feed 只有 domain 过滤，没有「按作者过滤」；前端也没有我的发帖页 |

## 修复

1. **顶栏头像**：`MobileTopBar` 换 `MobileAvatar`（`src=me.avatarUrl`，无则回退首字母）；CSS `.u-topbar__ava > .u-ava { width/height:100% }` 让头像填满原 36px 圆，尺寸/圆角/hover/active 基线不变。
2. **发帖立即可见**：store 新增
   - `prepend(post)`：插到 `items` 头部（同 id 去重 + 沿用 `LIST_CAP` 裁剪）**并同步当前 domain 的缓存**；
   - `invalidate()`：清空缓存（下次 load 强制重拉）。
   `MobileComposeView` 发布成功后先 `community.prepend(created)` 再 `router.push('/m/home')`。
3. **我的发帖**：
   - 后端 `GET /api/v1/community/posts?mine=true`（`PostRepository.feed` 增 authorId 谓词、service 传 `mine ? actorId : null`、controller 加 `@RequestParam(defaultValue="false") boolean mine`），与 domain 正交、keyset 游标语义不变；
   - 前端新页 `/m/me/posts`（`MobileMyPostsView`，列表内可删、空态给「去发帖」）；
   - 入口两处：账户抽屉「我的学习 → 社区足迹」（`/m/learn/community` → `/m/me/posts`）、资料页「我的发帖」。

## 踩坑

1. **「头像组件已统一」要逐个调用点确认**：我把 `MobileAvatar` 接进了抽屉/卡片/评论，唯独漏了顶栏 —— 而顶栏是用户最先看到的位置。统一组件后要 grep 全部旧实现（`.u-topbar__ava` / `.u-drawer__ava` / `.u-comm-item__ava` …）逐个替换。
2. **前端缓存是「看起来正常但看不到新数据」的典型来源**：store 的 domain 缓存让「同页刷新」与「跨页返回」行为分叉。跨页写入后必须显式 `prepend` 或 `invalidate`，不能指望用户下拉刷新。
3. **「我的 X」不是前端过滤**：只看当前页（10 条）再前端过滤会漏掉历史帖，必须服务端按作者过滤（`mine=true`），游标分页语义才成立。
4. **真机验收优先用 WebView devtools**：`adb forward tcp:9225 localabstract:webview_devtools_remote_<pid>` → `Runtime.evaluate` 直接读 DOM/路由，比看截图判断「有没有生效」可靠得多（脚本已落在 `local/`）。
