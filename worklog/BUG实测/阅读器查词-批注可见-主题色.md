# 阅读器三项实测：点词查义失效 / 批注不可见 / 主题色无效

> 归档日期：2026-09-10 · 发现人：组长手机实测 · 模块：`apps/web` 移动端阅读器（`/m/reader/:chapterId`）
> 三条同批报告、同一批修复，分节记录。

---

## 一、点词查义失效：只有「已在生词本」的词有反应，批注被绑在单词上

### 复现

阅读器里点任意普通单词 → 无任何反应；只有长按选中某个词才会弹出弹层，且弹层是「添加批注」而不是查词卡。

### 根因

`MobileReaderView.vue::onReaderClick` 的第一分支是：

```ts
const wordEl = target.closest('.u-rd__run.is-word') as HTMLElement | null   // ← 只匹配 .is-word
```

而 `.is-word` 的判定是 `vocabWords.has(word.toLowerCase())`（**该词已经加入生词本**）：

```html
:class="{ 'is-word': !!piece.word && vocabWords.has(piece.word.toLowerCase()) }"
```

即「查词入口」被错挂在「生词标记」上——没加过生词本的词永远点不动。长按则走
`selectionchange → createFromSelection`，直接进批注弹层，于是表现为「只能长按、只能对单词做批注」。

### 修复（组长拍板的交互口径）

- 渲染段改为 `buildSentenceSegments()` 产物（词 × 批注求交），任何带 `data-word` 的段都可点；
- `onReaderClick` 去掉 `.is-word` 门槛：**单击词 → 查词卡**（`lookupWord` + 「加入生词本」，原本就在 `MobileWordCard` 里）；
- **单击句子 → 选中该句（左侧蓝条 + 淡蓝底）+ 底部动作条**「色点×4（直接高亮）/ 批注 / 听这句 / 取消」
  （组长 2026-09-10 拍板：不直接弹批注弹层，避免滑屏误触；「听这句」顺带把句子级起播补回来）；
- 听书进行中单击句子仍是从该句续播；长按划选（自由区间）保留为高级用法；
- 单击词/批注/空白处会取消句子选中；Android 返回手势优先关闭动作条。

### 验证

`MobileReaderView.test.ts`：点未加入生词本的词 → `lookupWord('Alice')` 被调用 + 词卡出现「爱丽丝」「加入生词本」
（**修复前该断言必失败**：handler 进不去，零调用、无词卡）；单击句子 → `.is-selected` + 动作条出现且**不弹层**；
点「批注」→ 弹层带整句快照；点色点 → `createAnnotation` 收到整句范围 + 该颜色。

## 二、批注不可见：跳过去看不到内容，被批注的文本没有颜色

### 复现

写一条批注（带笔记）→ 打开「批注」列表点它 → 页面滚到对应位置，但**看不到批注内容**，被批注的文字也没有任何颜色/标记。

### 根因（两处叠加）

1. **渲染粒度错**：正文只按「词块」渲染，批注仅映射成句子级 class：

   ```ts
   function sentenceHasAnnotation(sentenceStart, sentenceEnd) {
     return annotations.value.some((a) => a.kind === 'highlight' && ...)   // ← 只认 highlight
   }
   ```
   `kind === 'note'` 的笔记批注**连下划线都没有**；即便有，也只是整句加一条下划线，
   既没有批注色，也看不出被批注的具体区间。
2. **跳转无反馈**：`jump()` 只调 `scrollIntoView`，没有任何高亮/弹层，笔记内容只能回列表里看。

### 修复

- 新增纯函数 `buildSentenceSegments(sentenceText, sentenceStart, annotations)`：把词块与批注区间**求交切段**，
  段上带 `ann`（优先带笔记的那条）+ `noteMarker`（笔记角标落在该批注在句内的最后一段）；
  段仍保留 `word`，所以词被批注边界切开后**点任一部分仍能查整词**；
- 正文按段渲染：`is-ann` 段用行内 style 上批注色，笔记批注在段尾出 3px 色条角标；
- 新增 `MobileAnnotationNoteSheet`：点批注段 / 点角标 → 直接读笔记（含快照、时间、删除）；
- `jump()` 升级为「滚动 + 目标段闪烁 1.8s（`is-flash`）+ 自动弹出批注内容」。

### 验证

`reader-words.test.ts` +6 例（整词/跨词/跨句/重叠批注、笔记角标、`note` 类也算有批注）；
`MobileReaderView.test.ts` +3 例（批注段上色 `#bbf7d0` + 角标存在 + 点角标读到笔记文字）。
**修复前必失败**：note 类批注零渲染（无 `.u-rd__seg.is-ann`、无 `.u-rd__annmark`）。

## 三、阅读设置换主题色无效

### 复现

阅读器 → 设置 → 点「米黄」「暗黑」→ 页面没有任何变化（只有句子高亮色微微变了）。

### 根因

主题变量定义在 `.u-rd-views[data-theme=...]`，但**纸面底色/墨色只写在 `.u-rd` 上**：

```css
.u-rd { background: var(--ur-theme-paper); color: var(--ur-theme-ink); }
```

而 `MobileReaderView.vue` 的正文分支里**根本没有 `.u-rd` 节点**（它只出现在 loading / error 两个分支）：

```html
<div class="u-rd" v-if="loading">…</div>
<div class="u-rd" v-else-if="error">…</div>
<template v-else-if="chapter">
  <MobileTopBar/>            <!-- 直接是 .u-rd-views 的子节点 -->
  <main class="u-rd__main">…</main>
```

→ 正文态背景永远是 `body` 的灰底（`mobile-uic.css` 里 `body{background:#edece8 !important}`），
只有吃 `--ur-theme-sentence` 的句子高亮跟着变，所以「看起来没生效」。

### 修复

底色/墨色上提到变量宿主 `.u-rd-views`，并补主题化的阅读器外壳（新增 `--ur-theme-chrome` /
`--ur-theme-muted`）：顶栏标题/头像、底部工具条（原本写死 `rgba(255,255,255,.94)`，夜间会是白底白字）随主题。

### 验证（无头 Chrome CDP 量计算样式）

| 主题 | 修复前 `.u-rd-views` 背景 / 文字 | 修复后 |
|---|---|---|
| 纸白 | `rgba(0,0,0,0)` / `rgb(0,0,0)` | `rgb(253,251,246)` / `rgb(38,36,31)` |
| 米黄 | 同上（无变化） | `rgb(247,239,221)` / `rgb(58,50,42)`，工具条 `rgba(253,248,238,.94)` |
| 暗黑 | 同上（无变化） | `rgb(27,29,32)` / `rgb(214,211,204)`，工具条 `rgba(38,41,45,.94)` |

复现页 `local/reader-theme-repro.html` + 量测脚本 `local/cdp-measure.mjs`（local/ 不入库）。
单测另锁 DOM 契约：选「暗黑」→ `.u-rd-views[data-theme=night]` + `localStorage.vv_rd_theme=night`。

## 顺带修掉的隐性缺陷：阅读进度永远不会保存

量测主题时发现 `.u-rd__main` **根本不是滚动容器**（`scrollHeight === clientHeight`，是 `body` 在滚）：

```css
.u-rd__main { flex: 1; overflow-y: auto; }   /* 父级 .u-rd-views 没有 display:flex / 高度 → 全失效 */
```

而阅读进度是**绑在 main 的 scroll 事件**上的（`@scroll.passive="scheduleSave()"`）→ 滚动时从不触发，
只有离开页面时才 flush 一次。修复：`.u-rd-views` 改 `display:flex; flex-direction:column; height:100dvh`，
`.u-rd__main` 补 `min-height:0` → main 恢复为滚动容器（CDP 实测 `mainScroll=1899/1184`，确实在内部滚动）。

## 踩坑

1. **`flex: 1 / overflow-y: auto` 在父级不是 flex 容器时是静默失效的**——不报错、不告警，只是「滚动跑到 body 上去了」。
   判断方法：量 `el.scrollHeight > el.clientHeight`，别只看 CSS 写了什么。
2. **主题变量的宿主与消费者的选择器要一致**：变量挂在 wrapper、样式写在只在某些分支出现的子节点上，
   就会出现「变量生效了但没人用」的假修复。查这类问题先看**实际 DOM**，别只看 CSS 文件。
3. **批注渲染必须与「词」这一层求交**：批注区间与词边界不对齐（长按划选常见）时，
   简单按词渲染会让批注色错位；切段后要**保留 word**，否则被切开的词就点不动了。
