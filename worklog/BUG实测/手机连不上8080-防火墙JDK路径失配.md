# 手机连不上 8080：java 进程路径不在防火墙放行名单（程序级规则失配）

> 归档日期：2026-09-10 · 发现人：组长手机实测 · 模块：Windows 防火墙（本机）+ `services/java`

## 复现

打包壳手机登录 → 「Failed to fetch」；手机→8000（python）有流量（访问日志可见 401/200），
**手机→8080（java）始终无任何流量**；本机访问 `http://192.168.0.104:8080` 一切正常。

## 根因

Windows 防火墙的入站放行规则是**程序级**（按 exe 路径匹配），既有规则放行的 java 路径：

```
C:\users\12321\.jdks\openjdk-24.0.2+12-54\bin\java.exe     ✅ 放行
C:\program files\java\jdk1.8.0_261\bin\java.exe            ✅ 放行
C:\users\12321\.jdks\ms-17.0.17\bin\java.exe               ✅ 放行
C:\users\12321\.jdks\ms-21.0.10\bin\java.exe               ✅ 放行
```

而**实际运行**的 java 是：

```
C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot\bin\java.exe   ❌ 不在任何放行名单
```

→ 手机连 8080 的 SYN 被防火墙**静默丢弃**（无 RST，客户端表现为连接超时）。python(8000) 恰好有匹配的
`python.exe` 规则所以能通——这就是「python 通、java 不通」的原因。本机自测全部通过，因为**回环/本机流量
不经过该入站规则**，属于典型「本机能测、外部不通」。

## 修复

端口级规则（不依赖程序路径，换 JDK/重启均有效）：

```powershell
New-NetFirewallRule -DisplayName "VocalVerse port 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Public,Private
New-NetFirewallRule -DisplayName "VocalVerse port 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Public,Private
```

已固化为 `scripts/firewall-phone.ps1`（需管理员运行；幂等）。

## 验证

| 项 | 结果 |
|---|---|
| 规则状态 | `VocalVerse port 8000/8080`：Enabled=True / Allow / Private,Public ✓ |
| 机器侧确认无 Block 规则 | 全部 Allow，无端口 Block ✓ |
| java 监听 | `::`（双栈）✓，`Test-NetConnection 192.168.0.104:8080` True |
| 加规则后手机重试 | 仍失败 → 暴露了下一层根因（网络隔离，见另份档案）——**本问题修复是必要前置，不是唯一根因** |

## 踩坑

1. **程序级防火墙规则随程序路径失效**：换 JDK/升级后静默失配，症状是「外网连不上、本机连得上」。
   手机联调一律用**端口级**规则。
2. **按端口杀进程重启**（`scripts/dev-up.ps1 stop/start`）时注意 uvicorn `--reload` 的父子进程结构——
   只杀父会留孤儿 worker 占端口（netstat 显示已死 PID 的僵尸 LISTENING）；按端口 `taskkill /T /F` 并核实释放。
3. **本机回环测试不能证明外部可达**：要确认手机可达性应以「手机侧访问日志出现」为准。
