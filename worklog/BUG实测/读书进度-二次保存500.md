# 读书进度 · 第二次保存起全部 500（ORM 过期属性在会话外被访问）

> 归档日期：2026-09-09 · 发现人：联调实测（S3 验收时看 python err.log 发现）· 模块：`services/python` `app/api/routes/reading.py`（进度 PUT/GET）
> 修复 commit：见本条目所在 PR（`fix(reading)`）

## 复现

1. 进阅读器翻两页以上（前端 `saveProgress` 防抖写入 `PUT /api/v1/reading/progress/{book_id}`）；
2. 看 `local/dev-logs/python-8000.err.log`：每次保存都留一条
   `sqlalchemy.orm.exc.DetachedInstanceError: Instance <UserReadingProgress ...> is not bound to a Session`；
3. 请求侧表现为 **500 Internal Server Error**（且响应体是 Spring/FastAPI 默认错误体，不是 Envelope）。

可复现的最小序列（live PG）：

```
PUT /api/v1/reading/progress/1 {chapter_id:1, char_offset:10}  → 200（第 1 次，走 INSERT）
PUT /api/v1/reading/progress/1 {chapter_id:1, char_offset:120} → 500（第 2 次，走 UPDATE）
PUT /api/v1/reading/progress/1 {chapter_id:1, char_offset:300} → 500
GET /api/v1/reading/progress/1                                 → 200（但只能看到第 1 次落库的值）
```

## 根因

`app/api/routes/reading.py` 的 `put_progress` 在**会话外**序列化 ORM 对象：

```python
def _q():
    ...
    db.commit()
    return row                     # 返回 ORM 实例
async with _db() as db:            # 退出即 db.close() → 实例 detached
    row = await _thread(_q)
return ok(_progress_dict(row))     # 访问 row.updated_at → 触发过期刷新 → DetachedInstanceError
```

- `UserReadingProgress.updated_at` 是 `onupdate=func.now()` 的**服务端生成列**；
- **UPDATE** 路径（第 2 次起）执行后该属性被标记为 expired（需要再查一次才拿到值）；
- `_db()` 退出即 `session.close()` → 实例 detached → 访问 expired 属性抛 `DetachedInstanceError`。

为什么单测一直绿：既有用例只 PUT **一次**（走 INSERT，`RETURNING` 已把 `updated_at` 取回，
`expired_attributes` 为空）→ 永远碰不到 UPDATE 路径。实测（SQLite 复现脚本）：

```
INSERT 路径 commit 后 expired = set()        → 会话外访问正常
UPDATE 路径 commit 后 expired = {'updated_at'} → 会话外访问 DetachedInstanceError
```

为什么 SQLite 单测与 PG 现场不同：差异只在「哪条路径」。与后端无关——同一段代码在两种库上
只要走到 UPDATE 都会炸。

## 修复

在**会话内**完成序列化（与 `list_annotations` / `create_annotation` 的既有写法一致）：

```python
def _q():
    ...
    db.commit()
    return _progress_dict(row)   # commit 后仍在同一会话内取值（触发一次刷新，成功）
async with _db() as db:
    data = await _thread(_q)
return ok(data)
```

`get_progress` 一并改为会话内序列化（它此前「碰巧」没问题——没有 commit 就不会过期；
但把正确性寄托在「没 commit」上太脆）。

## 踩坑

1. **「测试全绿」不等于「功能可用」**：用例只覆盖了 INSERT 路径，UPDATE 路径（用户真实的高频路径）
   从未被执行过。写用例要覆盖**第二条**写入，而不是只测一次。
2. **ORM 实例不要跨会话边界返回**：`db.commit()` 会让服务端生成列过期，`session.close()` 让实例
   detached —— 两者叠加就是 500。约定：**路由层拿到的永远是 dict，ORM 对象只活在 `_q()` 内**
   （本仓其他读书域端点已是这个写法，进度端点漏了）。
3. **前端 fire-and-forget 会掩盖后端 500**：`saveProgress` 不处理失败，用户只看到「进度没记住」，
   排查得从 `local/dev-logs/python-8000.err.log` 入手——联调时先看 err.log 再怀疑前端。
