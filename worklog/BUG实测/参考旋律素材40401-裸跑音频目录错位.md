# BUG 实测 · 裸跑「听参考旋律」40401（共享卷目录按 cwd 解析错位）

> 发现时间：2026-09-14｜环境：本机 Windows 11 + 方式 B（README §3 本地热重载）｜
> 关联登记项：**A-G7 路径三义性**（`APP_AUDIO_DIR` / `APP_MEDIA_DIR` 同一配置值在不同 cwd 下指向不同目录）
> 执行人：LHRCarrier（AI 代工）

## 1. 复现

方式 B 起四端（`scripts/dev-up.ps1 start -WithConsole`）后，`/m/sing` 里点「听参考旋律」：

- **前端表现**：按钮点了**没有任何反应**（音频不播、也无明显报错），既像"这首歌没有素材"，也像"按钮坏了"；
- **网络面板**：`GET /api/v1/audio/song_twinkle.wav` → HTTP 404

  ```json
  {"code":40401,"message":"audio asset missing","data":null}
  ```

- **直连复现**（拿到 demoadult 令牌后）：

  ```powershell
  Invoke-WebRequest "http://localhost:8000/api/v1/audio/song_twinkle.wav" -Headers @{Authorization="Bearer $tok"}
  # → 404 {"code":40401,"message":"audio asset missing","data":null}
  ```

**关键反证（排除"曲库没数据源"）**：

```sql
select id,title,status,pitch_ref_status,audio_url from songs;
--  1 | Twinkle Twinkle Little Star | published | ready | /data/audio/song_twinkle.wav
--  2 | Ode to Joy                  | published | ready | /data/audio/song_ode_to_joy.wav
--  3 | Mary Had a Little Lamb      | published | ready | /data/audio/song_mary_lamb.wav
```

三首全部 `ready` = 参考旋律（pyin）**提取成功**；文件也真实存在：

```
F:\WorkingL\vocalverse\data\audio\song_twinkle.wav   1,307,168 B
```

## 2. 根因

`services/python/app/api/routes/practice.py:542-561`（音频回放端点）：

```python
path = Path(settings.audio_dir) / name          # ← audio_dir 默认 "./data/audio"
if await asyncio.to_thread(_is_published_song_asset, name):
    if not path.exists():
        raise BizError(http_status=404, code=40401, message="audio asset missing")
```

而 `services/python/app/core/config.py:120`：

```python
audio_dir: str = "./data/audio"   # 相对路径 → **按进程 cwd 解析**
```

| 运行方式 | cwd | `./data/audio` 解析到 | 结果 |
|---|---|---|---|
| 容器（compose） | `/app`（Dockerfile `WORKDIR /app`） | `/app/data/audio`（挂载卷） | ✅ 正常 |
| 裸跑（README 方式 B） | `<仓库>/services/python` | `<仓库>/services/python/data/audio`（**只有用户录音**） | ❌ 40401 |

即：**同一个配置值在两处指向不同目录**，容器侧恰好对，裸跑侧必然错。前端只拿到一个 40401，
既不含路径也不含"配置错"语义 → 症状被误读成「曲库里没有小星星的数据源」。

补充：`scripts/setup-assets.py` 会把合成素材重建到**仓库根** `data/audio/`（音频不入库，红线），
而 `services/python/data/audio/` 是裸跑时 `save_audio_bytes` 就地创建的**用户录音**目录 —— 两个目录
同名不同义，是这个 bug 的温床。

## 3. 修复

**不做的事（有意）**：不把 `config.py` 的默认值改成"相对仓库根"。
理由：`tests/conftest.py:45` 每个用例都执行 `shutil.rmtree(get_settings().audio_dir, ignore_errors=True)`
——一旦默认值锚到仓库根，**跑一次 pytest 就会删掉真实的 `data/audio/` 素材**。风险远大于收益。

**做的三件事**（入口层收口，容器语义零变化）：

| # | 文件 | 改动 |
|---|---|---|
| ① | `scripts/dev-up.ps1` | 在 `APP_ASR_MODEL` 之后按**同款 setdefault 语义**注入 `APP_AUDIO_DIR` / `APP_MEDIA_DIR` = `<仓库根>\data\...`（仅未显式设置时注入，尊重用户覆盖） |
| ② | `services/python/.env.example` | 登记这两个键（`../../data/audio` / `../../data/media`，以 cwd=services/python 为前提）+ 说明容器为何不用配、以及"别 export 到 shell 再跑 pytest"的告警 |
| ③ | `services/python/app/main.py` | 启动期打印**实际解析到的绝对路径**，目录不存在时 WARNING ——把「静默 40401」变成一眼可见 |

## 5. 踩坑

1. **40401 的文案把排查带偏了**：「audio asset missing」读起来像"库里没这个素材"，而真实原因是
   **路径解析**。任何"资源找不到"的错误码都应把**实际查找位置**带进日志（本次已在启动期补上）。
2. **相对路径 + 同一个键名 = 三义性**：`./data/audio` 在容器里对、在裸跑里错，且**没人会怀疑它**——
   因为库里的 `audio_url` 写的是绝对样式 `/data/audio/xxx.wav`，看起来"就是个绝对路径"。
3. **想改 `config.py` 默认值前先看 conftest**：单测夹具会 `rmtree(audio_dir)`，
   "把默认值锚到仓库根"这个看起来最治本的改法，实际会让**单测删生产素材**。
4. **别用 `export APP_AUDIO_DIR=<仓库根>` 再跑 pytest**：环境变量优先级高于 conftest 的
   `os.environ.setdefault`，会盖掉 `data/audio-test` 的隔离、误删真素材。要么放 `.env`（conftest
   的 setdefault 仍生效），要么只在 dev-up 的进程内注入。
5. **「服务没起来、日志 0 字节」的另一种成因**：本机曾有一个 `uv sync` 进程挂死（占着 uv 缓存锁），
   导致不带 `--no-sync` 的 `uv run` **卡住且一个字都不打印**（输出重定向到文件时连进度条都没有）。
   判据：`Get-CimInstance Win32_Process -Filter "Name='uv.exe'"` 看有没有陈年 `uv sync`。
