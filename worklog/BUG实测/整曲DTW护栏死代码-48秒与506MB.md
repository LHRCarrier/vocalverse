# BUG 实测：整首 DTW 护栏是死代码——最长歌 48.3s / 506MB（P1-11）

- **日期**：2026-09-10
- **发现**：`local/唱歌模块全链路拷问报告-2026-09-10.md`（P1-11）
- **范围**：`services/python/app/audio/sing.py`（`align_frames` 长歌护栏 + 新增 `global_dtw_step`）
- **影响**：`max_sing_seconds=180` 的歌（**允许的最长输入**）做整首粗对齐时：成本矩阵 + 累积矩阵各 `n²×8B` ≈ **506MB**，带内 DP 是纯 Python 双层循环（≈630 万次）≈ **48.3s**。`sing_concurrency=2` 下两首并发 ≈1GB，容器内存 2GB 还要装 whisper → **OOM 风险**；48s 还长占一个线程池 worker，拖慢所有走 `to_thread` 的请求（评分/提取/ASR）。

## 1. 复现

```python
import numpy as np, time
from app.audio.sing import _dtw_path, DTW_BAND_RATIO
n = 5625                      # 180s @ hop 32ms
uu = np.cumsum(np.random.default_rng(0).normal(0, 5, n))
rr = np.cumsum(np.random.default_rng(0).normal(0, 5, n))
t0 = time.perf_counter(); _dtw_path(uu, rr, DTW_BAND_RATIO, open_end=True)
print(time.perf_counter() - t0)
```

实测（本机，2026-09-10）：

```
PRE-FIX  step=1 n=5625 elapsed=48.3s matrix=506MB
POST-FIX step=2 n=2813 elapsed=8.7s  matrix=127MB   # 5.6× 提速 / 4× 省内存
```

护栏本身就是证据：`sing.py` 写的是 `if n > 6000: step = 2`，注释还写着「180s@32ms=5660 帧，兜底上界」——**5625（或 5660）永远够不着 6000**，即护栏从未生效过。自动化断言见 §4。

## 2. 根因

1. **阈值常量与真实帧数差 375 帧**：`180s / 0.032s = 5625` 帧，判定写 `> 6000` → 恒 false，"最长歌"恰好落在护栏外侧；
2. **成本矩阵是 O(n²) 内存**：`_dtw_path` 先算 `np.abs(uu[:,None] - rr[None,:])`（253MB@5625），`_dtw_cost_matrix` 再 `np.full((n,m), inf)`（又 253MB）；
3. **带内 DP 是 Python 双层循环**：`w = 10%×n = 562` → 每行 1125 列 × 5625 行 ≈ 630 万次解释器循环（≈7.7µs/次）。

## 3. 修复（方案 A：修护栏 + 按帧数自适应降采样）

`services/python/app/audio/sing.py`：

```python
GLOBAL_DTW_FULL_FRAMES = 4000    # ≤ 此帧数：全分辨率（精度优先）
GLOBAL_DTW_TARGET_FRAMES = 3000  # 超过则压到该量级

def global_dtw_step(n: int) -> int:
    if n <= GLOBAL_DTW_FULL_FRAMES:
        return 1
    return max(1, math.ceil(n / GLOBAL_DTW_TARGET_FRAMES))
```

`align_frames` 用它替换死代码护栏，offset 仍按 `hop_ms × step` 还原（量化单位随之变成 64ms）。

**取值理由**：`TARGET=3000` 而非 2000——180s 取 step=2（64ms 量化）而不是 step=3（96ms）；offset 是**整首歌统一的窗口平移量**，96ms 的系统性偏移有可能把真实 120ms 的起唱偏差推到 150ms 分档线外，省下的 70MB 不值得牺牲对齐精度。降采样**只作用于整首粗对齐**：逐句局部 DTW（句级序列短）与起唱检测（`onset_dev_ms`）仍是全分辨率，故节奏分档口径不变。

## 5. 踩坑

1. **护栏常量的"差一点"等于没有护栏**：`> 6000` vs 真实 5625/5660 只差几百帧，代码看着有防护、测试也照不到（没人测 180s 全曲），线上就是 100% 走最坏路径。写规模护栏时**用配置上限反推帧数**（`max_sing_seconds / hop`）而不是估算一个整数。
2. **改阈值要考虑"哪些层被降采样"**：天真做法是把整条链路都降采样（省事但伤分档）；正确做法是只降**整首粗对齐**这一层——逐句局部 DTW 与 onset 检测的输入很短，是分数精度的直接来源。
3. **量化单位要写成可断言的量**：offset 量化 = `hop×step`，测试直接断言 `offset % (HOP*step) == 0`，比"看起来差不多"的口头约定更能挡住未来的改法。
4. **治本项要显式登记为"未做"**：反斜对角向量化能把全分辨率下的 48s 压到 1~2s，但那是对齐原语重写（需与现实现对拍），本次按组长选择只做止血——已写进 docs/06，避免以后有人以为"已经最优"。
