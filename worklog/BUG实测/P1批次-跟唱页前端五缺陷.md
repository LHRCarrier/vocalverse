## 1（P1-2）轮询在飞请求不被作废 → 换歌串台

- **复现**（A 路实测，RTT 放大到 5s 时 100% 命中）：录音 → 停止并评分（进入 processing）→ 等首次 status 请求发出后点面板「关闭」→ 立刻点另一首歌 → 等迟到结果落地。
- **实际（修复前）**：新歌标题下渲染**上一首的成绩**（实测 `song_id=1` 的 77.7 分），图表还把 B 的参考线与 A 的用户曲线画在一起；`reset()` 只 `clearTimeout`，已发出的 status/result 请求照样落地并写 `result/phase`。
- **修复**：`composables/sing.ts` 引入**世代号 `epoch`**——`poll()/reset()/retry()/submitAudio()` 各自自增，回调首行校验 `my !== epoch` 即静默丢弃；`stop()` 同时 `AbortController.abort()` 在飞请求（`api/sing.ts` 的 `fetchSingStatus/fetchSingResult` 增 `signal` 参数）；`openSong()` 也先 `stop() + recorder.cancel() + detail=null`（换歌即作废，且不留旧标题串台）。依据：docs/21 §3.6（轮询语义）。
- **验证**：`composables/__tests__/sing.test.ts` 三条——「重置后在飞轮询落地不得写状态」（**修复前必失败**：`expected {id:9,…} to be null`）、「reset 会 abort 在飞请求」、「openSong 换歌会作废旧轮询并取消在录录音」。
- **副产品**：该修复同时消除了缺陷 5 的**主要触发路径**（迟到结果不再落地 → 面板关闭时不再产生"有结果但没图"的状态）。

## 2（P1-5）参考旋律与录音不互斥 → 原唱被录进麦克风

- **复现**：点「听参考旋律」→ 播放中点「开始跟唱」。
- **实际（修复前）**：参考旋律继续播放（A 路实测 `pauses=0`），而「停止参考旋律」按钮此刻被 `:disabled="recording"` 锁死 → 用户停不掉；外放时原唱被一起录进去，**评分输入被污染**（评分以离线分析为准，录到的正是参考旋律）。
- **修复**：新增 `startSinging()` = `stopReference()` + `play.startRecording()`，录音按钮改绑它；`openSong()` 也先停播（换歌不再续播上一首）。
- **验证**：视图用例「点「开始跟唱」会先停参考旋律」（**修复前必失败**：`pause` 未被调用）。

## 3（P1-6）列表加载失败＝永久「加载中…」+ 谎报空态 + 无重试

- **复现**：后端 500 / token 过期 / 断网 → 进 `/m/sing`。
- **实际（修复前）**：A 路实测三种输入的页面文本**完全一致**（「加载中…」+「这个分类还没有歌」两句自相矛盾的话），`play.error` 只在跟唱面板内渲染 → 页面既无错误原因也无重试入口。
- **修复**：新增 `loadFailed` 计算（`phase==='failed' && 无歌曲`）→ 精选卡三分支（loading / error / empty）；错误态显示 `play.error` + 「重试」按钮（复用 `play.loadSongs()`）。
- **验证**：视图用例「加载失败显示错误态 + 重试」（断言错误文案、不再出现「加载中…」、点重试后重新拉取并恢复三行歌单）。

## 4（P1-7）参考旋律 ObjectURL 泄漏 + 连点叠播

- **复现**：加载未完成时连点两次「听参考旋律」；或反复试听后不关闭页面。
- **实际（修复前）**：产生两路 `Audio` 且第一路**永不可停**（`refPlaying` 只指向后一路）；`createObjectURL` 每次都是一整首歌的 blob（3 分钟曲 ≈3~5MB），而 `onended/停止/卸载` 三处都只 `pause()` → 内存随试听次数线性增长（移动 WebView 易被杀）。G 路资源矩阵把它列为**前端唯一确认泄漏**。
- **修复**：抽出 `composables/useReferenceAudio.ts`（自包含：`playing` / `toggle` / `stop`）——`stop()` 是**唯一回收点**（`revokeObjectURL`），`onended` 也走 `stop()`，`onUnmounted` 兜底；`busy` 期间重入直接忽略；错误走 `onError` 回调（与 UI 解耦）。抽出同时把视图行数拉回 `max-lines 350` 门禁内（360 → 达标）。
- **验证**：视图用例「加载中连点不叠出第二路 Audio；停止即 revoke」（**修复前必失败**：连接中即出现 1 个 Audio / 停止后 `revoked` 为空）。

## 5（P1-8）结果落地时面板关闭 → DAG 图永久空盒

- **复现**（A 路实测）：评分中关面板 → 等结果落地 → 再打开（或换歌）。
- **实际（修复前）**：报告区立刻出现，但 `#m-sing-chart` 内 `innerHTML` 长度 0（`document.getElementById` + 一次性 60ms 延时，元素不存在就**静默跳过**，且不会重画）→ 150px 空白框永不自愈。
- **修复**：改用**模板 ref**（`chartEl`）+ 监听 `[result, sheetOpen]`（`flush: 'post'` + `nextTick`）——面板打开且结果就绪时渲染；配一条**源码契约用例**（禁止再出现 `getElementById('m-sing-chart')`、必须保留 `ref="chartEl"`）。
- **验证**：视图用例「结果就绪即以模板 ref 渲染图表」（断言 `renderSingChart` 被调用且首个实参是 `HTMLElement`）+ 源码契约用例。

## 踩坑

1. **"只清定时器"挡不住已经发出去的请求**：异步轮询必须配世代号（或 abort），否则迟到响应会写进新上下文；本案的实测命中率随 RTT 线性上升。
2. **两个缺陷可以互为因果**：P1-2 修好后，P1-8 的触发路径基本消失——但**仍要保留 P1-8 的修法与守卫**（后者是结构性的：`getElementById` 依赖"元素此刻存在"，天生脆弱）。
3. **`max-lines` 门禁连续两轮逼出正确重构**（P0-4 抽出行组件、本次抽出播放组合式）：与其删注释/压行，不如把自包含关注点搬出去。
4. **`onUnmounted` 里的清理必须有对应测试**：资源泄漏类修复若只验证"停止时 revoke"，卸载路径仍可能漏（本轮 `useReferenceAudio` 在卸载时同样 revoke，且视图侧滚动锁已单独覆盖卸载还原）。
