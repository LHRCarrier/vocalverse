# BUG：demo 参考旋律被 24h 惰性过期**物理删除**（`GET /audio/{name}` 顺序错误）

- **发现**：2026-09-10 · 唱歌模块七路拷问（G 路：安全/隐私/性能/资源）静态审计 + 主代理实测复核。
- **修复**：2026-09-10 · 执行人：AI 代签（正式署名待组长确认）。
- **影响面**：`GET /api/v1/audio/{name}`（`app/api/routes/practice.py`）——**唱吧「听参考旋律」全链路**；一旦触发即**不可逆**（文件被 `unlink`，重提取因缺音源失败后按 `attempts ≥ max` 永久放弃，`pitch_ref_status` 永停 → 用户侧 40905）。同一根因还决定「素材 vs 用户录音」两套生命周期无法共存。
- **严重级**：P0（数据损坏 + 功能不可用，且**当时只差一次点击**）。

## 复现

1. 条件：`data/audio/` 下存在**已发布歌曲**的参考旋律（seed 素材 `song_*.wav`），其 mtime 距今 > `APP_AUDIO_TTL_HOURS`（默认 24h）。
   - 实测（2026-09-10）：`song_twinkle.wav` / `song_ode_to_joy.wav` / `song_mary_lamb.wav` age = **24.74h**（mtime 2026-09-09 15:11），真库中 3 首歌 `pitch_ref_status='ready'`、`audio_url=/data/audio/song_*.wav`。
2. 任一登录用户在 `/m/sing` 点一次**「听参考旋律」**（`MobileSingView.vue:80-103` → `GET /api/v1/audio/song_twinkle.wav`）；
3. 实际：**410 `{"code":41001,"message":"audio expired"}`**，且**文件被物理删除**（旧代码 `path.unlink(missing_ok=True)`）；此后该歌既无法试听，也无法重新提取参考旋律。

## 根因

`get_audio` 的判定顺序与语义分层错位（旧实现）：

```python
# ① TTL 判定 + 惰性清理（对「所有文件」无差别执行）
if not path.exists() or path.stat().st_mtime + ttl * 3600 < time.time():
    if path.exists():
        path.unlink(missing_ok=True)     # ← 素材在这里就被删了
    raise BizError(410, 41001, "audio expired")
# ② 归属校验：用户录音三条引用 **或 已发布歌曲素材**（豁免在删除之后，永远来不及）
owned = ... or db.execute(select(Song.id).where(Song.status == PUBLISHED, Song.audio_url.like(f"%/{name}")))
```

- 24h TTL 的**设计对象是用户录音**（docs/06 §9「原始音频默认 24h 过期清理」，隐私口径），**平台素材是内容库的一部分**（公有领域演示素材，随歌曲生命周期），却被同一段逻辑一并删除；
- 「已发布歌曲素材对全体登录用户公开」的豁免写在归属查询里，位置在 TTL **之后** → 豁免对「超期素材」永远不生效；
- 该 bug 与历史坑同源：`worklog/BUG实测/音频残留过期410flaky.md`（sha1 去重不刷 mtime + 惰性过期）当时记为「另案处理」，本次升级为**素材误删**。

## 修复（组长 2026-09-10 拍板：方案 A 最小止血）

把**素材分流提到 TTL 之前**，形成三段顺序（`app/api/routes/practice.py`）：

1. `_is_published_song_asset(name)`（新，模块级纯查询）：命中「已发布歌曲 `audio_url` 引用」→ **平台素材**分支：**不判 TTL、不 unlink**；文件缺失按 **40401**（服务端内容问题，可用 `scripts/setup-assets.py` 重建），不按"过期"语义；
2. **用户录音**分支：保持 24h 保留期 + 惰性清理（**隐私口径不变**，41001）；
3. `_owned_by_user(name, user_id)`（新，从原内联闭包抽出）：attempts / scenario_messages / sing_attempts 任一引用 → 否则 40301。
   - 原 `_owns` 里的「Song 已发布」条件**移除**（已由第 1 段承接，避免"豁免藏在归属里"再次踩坑，代码注释已写明）；
   - 抽出的 `_audio_stream(path)` 复用回放流（MIME 嗅探优先，BUG-5 口径不变）。
   - 依据：docs/06 §9「音频回放鉴权」（本次补 2026-09-10 修正条）、docs/06 §8 音频存储行、docs/21 §2.1 op11。

## 踩坑

1. **「同目录两类数据、一个清理策略」是这类事故的温床**：TTL 的语义对象必须与"文件用途"绑定，而不是与"目录"绑定；任何"删除"分支都应先回答"这个文件属于谁/能不能重建"。
2. **豁免逻辑的位置比豁免逻辑本身更重要**：把「素材豁免」写在归属查询里（TTL 之后）看起来"也实现了豁免"，但对超期文件永不生效——**破坏性分支（unlink）之前必须先跑完所有豁免判定**。
3. **不可逆操作要留"可重建"退路**：素材缺失用 40401（可重建）而不是 41001（已过期/不可恢复），语义上区分"服务端内容缺失"与"隐私数据过期"。
4. **测试要能证伪**：本项回归用例通过**临时改回旧顺序**验证了判别力（否则只是"绿着的断言"）。
