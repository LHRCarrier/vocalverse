# 读书域批注 · 暗黑模式下批注「浅粉底 + 浅灰字」不可读

> 归档日期：2026-09-09 · 发现人：组长手机实测（截图 `worklog/BUG记录/读书域系列BUG9-09/9-09读书暗黑模式下批注为粉色看不清/`）· 模块：`apps/web` `MobileReaderView` / `reader-uic.css` / `audio/reader-words.ts`
> 修复 commit：见本条目所在 PR（`fix(reading)`）

## 复现

1. 进阅读器 `/m/reader/:chapterId`；
2. 底部「设置」→ 主题选「暗黑」（`data-theme=night`）；
3. 对任意句子做批注（默认粉色 `#fbcfe8`）；
4. 被批注的文本变成**浅粉底 + 浅灰字**，几乎无法辨认（截图：`local/shots/reader-dark-annotation-before.jpg`，原图随 BUG记录 一并归档）。

## 根因

两处叠加（修复前 HEAD `63fcaee`）：

1. `MobileReaderView.vue:322` 把后端返回的批注色**裸写**进 `background`：
   `:style="{ background: seg.ann ? (seg.ann.color ?? 'var(--ur-theme-annotation)') : undefined }"`
   —— 主题无关，night 下底色仍是浅粉 `#fbcfe8`；
2. 文字色来自 `.u-rd-views[data-theme='night'] { --ur-theme-ink: #d6d3cc }`（`reader-uic.css:63`）
   —— 浅灰。

浅底浅字，WCAG 对比度实测：

| 批注色 | night 主题对比度（修复前） |
|---|---|
| 粉 `#fbcfe8` | **1.08** |
| 蓝 `#bfdbfe` | **1.05** |
| 黄 `#fde68a` | **1.20** |
| 绿 `#bbf7d0` | **1.23** |

（AA 正文线 4.5。讽刺的是主题自带的 `--ur-theme-annotation: #3b3420` 有 8.27，却被 `??` 兜底绕过了。）

## 修复

1. **颜色只作 CSS 变量传入**：`:style="{ '--ur-ann-color': safeAnnColor(seg.ann.color) }"`；
2. `reader-uic.css` 新增 `--ur-ann-mix`（paper 55% / cream 58% / night 24%），批注底色改为
   `color-mix(in srgb, var(--ur-ann-color) var(--ur-ann-mix), var(--ur-theme-paper))`，
   文字统一 `color: var(--ur-theme-ink)`；不支持 `color-mix` 的内核走 `@supports not` 兜底（用主题批注色）；
3. 新增 `audio/annotation-colors.ts`（色板单一真源 + `safeAnnColor` 白名单）：颜色是不可信输入
   （后端任意字符串），色板外的值一律回退默认色 —— 同时封掉「非法值让整条声明失效（批注变透明）」
   与 CSS 注入面。

night 取 24% 而非 30%：30% 时色板最亮的绿只有 4.63（勉强过线），且**色板外**的最坏色
`#ffffff` 只有 4.16（不达标）；24% 后色板四色分别为 5.66 / 5.59 / 5.95 / 5.89。

## 验证

**门禁用例**（`apps/web/src/styles/__tests__/reader-annotation-contrast.test.ts`，7 条）：
直接解析 `reader-uic.css` 源文件，对「三主题 × 色板全色」算 WCAG 对比度并断言 ≥4.5，
另加「最坏情况兜底」用例（请求 `#ffffff`/`#ffff00` → 被拦回默认色 → night 仍 ≥4.5）。

修复前必红（HEAD 63fcaee + 只拷测试文件，实测）：

```
× 每个主题都声明了 --ur-ann-mix 与纸面/墨色
× paper 主题：批注色混底后墨色对比度 ≥ 4.5
× cream 主题：…
× night 主题：…
× 批注段用 --ur-ann-color + color-mix（不再把原始色直接当 background）
× 最坏情况兜底：色板外任意亮色被拦回默认色后，night 主题对比度仍 ≥ 4.5
```

修复后：`pnpm lint` / `typecheck` / `test:run`（178 passed）全绿。

## 踩坑

1. **「主题色 token 已存在」不等于「会用上」**：`--ur-theme-annotation` 在 night 下有 8.27 的对比度，
   但 `??` 兜底只在 `color` 为 null 时生效，正常批注永远走裸色 —— 修 bug 时先看**实际取值路径**，
   不要假设 token 被消费。
2. **对比度门禁必须覆盖「实际可渲染集合」**：门禁最初只遍历色板四色，30% 混入下永远发现不了
   `#ffffff` 的 4.16 缺口；把色板收成单一真源 + 白名单后，「门禁覆盖集 = 渲染集」才成立
   （`safeAnnColor` 用例就是这条等价性的守卫）。
3. **色板原先有 4 份拷贝**（三个组件 + 对比度门禁从源码正则抠取）：改一处漏一处会让门禁**静默失去覆盖**，
   故收敛到 `audio/annotation-colors.ts`。
4. **`color-mix` 的可用性**：全仓已有先例（`reader-uic.css` 选中句高亮），无需引入 polyfill；
   但必须写 `@supports not` 兜底，否则旧内核上批注底色会变透明（比原 bug 更糟）。
