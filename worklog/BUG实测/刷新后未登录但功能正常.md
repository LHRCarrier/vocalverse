# BUG：登录后刷新页面 → 前端显示「未登录」但账号数据/功能正常

- **发现**：2026-09-07 · 用户（Faust-sudo）报告并附两张截图：左抽屉登录态「测试01 · @哈密瓜 · LV3」，
  刷新后同页变「同学 · 未登录」，但右侧社区 feed（今日打卡 88 / VocalVerse News）与功能均正常。
- **修复**：2026-09-07 · 执行人：Faust-sudo（AI 代工）。
- **影响面**：`apps/web/src/stores/auth.ts`（bootstrapAuth）+ 新增回归测试
  `apps/web/src/stores/__tests__/auth.test.ts`；App 端顶栏头像字母（MobileTopBar）与账户抽屉
  （MobileAccountDrawer）的「同学/未登录」显示均受影响，全局入口皆可复现（刷新任意页）。

## 复现

1. 登录（如 测试01）→ 进入社区页，抽屉显示「测试01 · @哈密瓜 · LV3」；
2. 按 F5 / 整页刷新（或 App 冷启）；
3. 结果：顶栏/抽屉变「同学 · 未登录」，但社区数据加载、互动等功能正常（token 仍在被使用）。

## 根因

`me`（用户资料）只在 `login()/register()` 里经 `fetchMe()` 写入，**启动恢复路径不拉取**：

| 项 | 恢复内容 | 备注 |
|---|---|---|
| `main.ts` → `bootstrapAuth()` | `setAuthToken`（localStorage 恢复 token 进 client 全局）+ `setAuthRefresher` + `store.refresh()`（`POST /auth/refresh` 换新 token） | **缺 `store.fetchMe()`** → `me` 恒为 `null` |
| `login/register` | `persist()` + `fetchMe()` | 所以登录后正常，刷新即丢 |

`MobileTopBar.vue:30`（头像字母兜底「同」）与 `MobileAccountDrawer.vue:106-108`（「同学」/「未登录」）
直接读 `auth.me` → 显示与真实登录态矛盾；而 `client.ts` 的 `authToken` 全局已恢复，所有请求照常
带上 token →「数据都在、功能正常」的表象。2026-09-05 补 401 静默续期（docs/18 F3）时同样漏了 me 恢复。

## 修复

`stores/auth.ts` `bootstrapAuth()`：`store.refresh()` 成功后补 `await store.fetchMe()`（复用既有
`GET /auth/me`，其内部 401 会自动走已注册的 refresher → 失败则 `me=null` 与 `clear()` 语义一致）。

## 验证

- 新增 `stores/__tests__/auth.test.ts` 2 例：
  1. 有 token：`bootstrapAuth` 依次 `/auth/refresh`（换新 token）→ `/auth/me`，`me` 恢复「测试01」，
     `setAuthToken` 注入 2 次（初始恢复 + refresh persist）——**修复前此断言失败**（无 fetchMe 调用，
     `me` 为 null）；
  2. 无 token：零请求，`me` 保持 null（未登录态正确）。
- 门禁：`pnpm lint` / `pnpm typecheck` / `pnpm test:run`（79+2=81）/ `pnpm build` 全绿；后端零改动。

## 踩坑

- 会话恢复 ≠ 只恢复 token：**用户态（me）也必须恢复**，二者缺一就会出现「接口正常 / 界面未登录」
  的割裂观感；凡是有持久化凭证的启动恢复路径（bootstrap/守卫），都要把「拉资料」算进恢复序列。
- 刷新首帧存在极短的 me 空窗（bootstrapAuth 异步，mount 不阻塞）→ 头像字母先显示「同」再变「测」；
  用 `me` 缓存 localStorage 可消除，但有陈旧风险，按最小修复原则本 BUG 不引入（2026-09-07 拍板）。
