# BUG：真机点收藏失败（运行中的 python-api 是旧代码 + DB 未迁移 0011）

- **发现**：2026-09-10 · 组长在 App/网页端实测 `/m/sing`：歌单行已有心形按钮，但点击后 toast「收藏操作失败，请重试」（截图，心形不亮、状态回滚）。
- **修复**：2026-09-10 · 执行人：AI 代签（正式署名待组长确认）。
- **影响面**：仅本次新增的收藏功能；旧后端 `GET /songs` 不返回 `favorited` → 心形恒为未收藏（**不报错**），容易误判成「前端没接上」。收藏落库（`song_favorites`）与契约本身无缺陷。

## 复现

1. 打开 `/m/sing`（前端为最新源码，行内有 `m-sing-fav` 心形按钮）；
2. 点心形 → toast「收藏操作失败，请重试」，状态回滚（心形不亮）。

## 定位（按链路逐段实测，五段证据）

| 环节 | 探针 | 结果 |
|---|---|---|
| 前端 | vite dev(5173) 产物含 `m-sing-fav` | ✅ 新代码到位 |
| 前端容器产物 | `docker exec vocalverse-web-1 grep -rl 'm-sing-fav' /usr/share/nginx/html/assets` | 无 → 用户走的是 **vite dev**，不是 web 容器静态产物 |
| 路由 | `GET localhost:8000/openapi.json` 过滤 `favorite` | **空**（运行中的服务无收藏路由） |
| 真实请求 | `PUT localhost:8000/api/v1/songs/1/favorite` | **404** |
| 经 vite 代理 | `PUT localhost:5173/api/v1/songs/1/favorite` | **404**（复现用户链路） |
| 容器内源码 | `docker exec vocalverse-python-api-1 grep -c 'songs/{song_id}/favorite' /app/app/api/routes/singing.py` | **0**（镜像是旧代码，文件日期 Sep 9 08:02） |
| 数据库 | `select version_num from alembic_version` | **0010**（无 `song_favorites` 表） |

## 根因

1. **代码路径**：`python-api` 的源码在**构建期打进镜像**（compose 只挂 `./data/audio`、`./data/seed`），运行中的容器启动于镜像构建之后但两者**都早于**本次代码变更 → 容器内没有收藏路由 → Starlette 返回 404 → `request()` 抛 `ApiError(-1, 'HTTP 404', 404)` → `toggleFavorite` catch → 回滚 + 通用 toast。这正是截图现象。
2. **数据路径**：即使换了代码，DB 仍停在 `0010`、没有 `song_favorites` 表 → 会立刻从 404 变成 **500（UndefinedTable）**。两条都要修，缺一不可。
3. **附带坑**：第一次 `docker compose run --rm migrate` **失败**于
   `ERROR [alembic.util.messaging] Can't locate revision identified by '0010'`（exit 255）——
   migrate 服务跑的是 **2026-09-07 构建的旧镜像** `vocalverse-migrate:latest`，其 `alembic/versions/` 里根本没有 0010/0011，连「当前版本」都解析不了。**这句报错不是 DB 损坏，是镜像旧**。

## 修复

1. `docker compose up -d --build python-api` → 镜像重建、容器 healthy，`/openapi.json` 出现 `/api/v1/songs/{song_id}/favorite`（2 个方法）；
2. `docker compose run --rm --build migrate` → `INFO [alembic.runtime.migration] Running upgrade 0010 -> 0011, 跟唱收藏：song_favorites 新表（docs/10）` + `[seed] …（跳过已存在）`，exit 0；
3. **前端可诊断性改进（本次一并做）**：新增 `favoriteErrorMessage`（`api/sing.ts`）按 HTTP 状态分流文案——404「服务端没有收藏接口（后端需重建/重启到最新版本）」/ 401「登录已过期」/ 5xx「服务端内部错误（若刚上线该功能，请确认已执行迁移 0011）」；`useSingPlay.favoriteError` 承载原因，`MobileSingView.toggleFav` 的 toast 显示该原因。首版只有一句「请重试」，本次定位靠人工五段探测；下次同类失败 toast 直接给结论。
   - 取舍说明：文案里出现「迁移 0011」属**面向团队自测/演示**的可执行提示，不是面向终端用户的纯产品文案——若后续对外发布，应把技术细节降级为日志（保留「稍后重试」）。

## 踩坑（可复用）

1. **容器里的代码是「构建期快照」**：改 `services/python/**` 后 `docker compose restart` / `up -d`（不带 `--build`）**不会生效**；最省的判断方式是 `docker exec … grep` 或 `GET /openapi.json` 看路由在不在。
2. **迁移镜像同样不会自动更新**：`run --rm migrate` 用旧镜像会让 alembic 连自己的版本目录都对不上（`Can't locate revision identified by '0010'`）——务必 `--build`（或先 `docker compose build migrate`）。
3. **「前端有按钮」≠「后端已上线」**：vite 热更新即时、后端要重建；两端不同步是本类问题的温床。新端点的联调顺序应是 **先验 `openapi.json` → 再验 UI**。
4. **通用 toast 让排查变贵**：一句「请重试」把定位成本推给人工逐段探测；按状态码分流后，同类问题下一步就能从 UI 读出结论（已落测试：`favoriteErrorMessage` 4 例 + 视图 404 集成 1 例）。
