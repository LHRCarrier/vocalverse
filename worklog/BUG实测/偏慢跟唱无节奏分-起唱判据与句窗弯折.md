# BUG 实测：偏慢跟唱整首没有「节奏」分——起唱判据恒判延续 + 句窗起点未弯折（口径 v6）

- **日期**：2026-09-10（唱歌模块全方面复测发现并修复）
- **范围**：`services/python/app/audio/sing.py`（`onset_voiced_mask`/`TimeWarp`/`align_time_warp`/`line_onset_ms`/句窗映射）、`app/sing/service.py`（发音抽样窗）、新增 `alignment.time_warp_stretch`/`windows_ms`
- **影响**：用户**唱得比参考慢**（`bpm_ratio<1`）时，整首歌**一个句子都拿不到节奏分**（`reason='no_onset'`），`overall` 静默按 `(0.5·音准 + 0.3·发音)/0.8` 重算——报告三分项缺一，且用户无从知道为什么。演示素材（`local/sing_test_user.wav`，`bpm_ratio=0.826`）恰好命中：演示链路的「节奏」维度长期是空的。

---

## 1. 复现（真容器）

1. 上传跟唱音频（`bpm_ratio=0.826`，即比参考慢 ~19%）；
2. 轮询到 `done` 后取结果：`rhythm=None`，`lines[*].reason='no_onset'`（6/6 句），
   `overall = (0.5×74.01 + 0.3×22.58)/0.8 = 54.72`（节奏维度整块消失）；
3. 换"句间插 372ms 换气"的素材（`scripts/sing_container_test.py:gapped_fixture`）结果相同（6/6 句 no_onset）；
4. PG 全量历史佐证：26 条 attempt 中仅 14 条有 `rhythm_score`，且 **`bpm_ratio<1` 的全部没有**（0.826 组 ×5），
   `bpm_ratio>1` 的都有（1.407 → 74.25、1.652 → 95.0）——方向性与下面的推演一致。

## 2. 根因（两个叠加）

### 根因 ①（主因）「有声」判定用 `f0 > 0`，而 pyin 对静音大量判浊

起唱判据 `onset_is_continuation` 与检测窗扫描都以"帧是否 `f0>0`"判有无声音。实测：

```
librosa.pyin(fill_na=0.0, frame_length=2048, hop=512) 对 37s「句间 372ms 静音」素材：
  voiced_flag=True 帧 1119 / 1119；f0==0 帧仅 39（≈1.2s，而真实换气合计 1.86s）
经 160ms 中值滤波（item6）后，一次 372ms 换气只剩 ~150-190ms 可检出
  → 恰好卡在 ONSET_SILENCE_GAP_MS=150ms 门槛上 → 判据近乎**恒判"延续"**
```

后果：节奏维度要么恒 None（窗口首帧落在有声处），要么靠"窗口首帧恰好落在少数 0 帧上"**撞运气**给分（这就是历史数据里"偏快有分"的来源——偏快时窗口起点偏早、恰好落进静音）。

### 根因 ② 句窗起点没按速度弯折（v5 遗留）

```python
scale = window_scale(tempo["bpm_ratio"])          # 只有句长乘了系数
win_start = a["start_ms"] + offset_ms              # 起点只加"全局中位偏移"
```

`offset_ms` 是 DTW 路径 `i-j` 的**中位数**：对速度比 r 的演唱，真实映射是时间弯折
`user ≈ offset₀ + r' × ref`，中位数只是"整段折中"——曲首偏大、曲尾偏小 → 后续句窗口落到**上一句句腹**
（无前置静音）→ 判"延续"。（与 BUG-4 同源：当时只补了长度，没补起点。）

## 3. 修复（口径 v6）

1. **能量口径的"有声"掩码** `onset_voiced_mask(f0, rms)`：`rms ≥ max(0.005, 0.12 × 75 分位)` **且** `f0>0`；
   无 rms（Fake 提取器/单测）时保持旧 `f0>0` 语义。能量不受中值滤波影响、对换气（≥15dB 衰减）敏感。
2. **句窗时间弯折** `TimeWarp(offset + stretch × ref)`：起点与长度同源。
   - `stretch` 优先取 onset 仲裁的 `bpm_ratio`（`window_scale`，独立于 DTW 带宽），但**必须与路径拟合斜率互证**（相差 >0.20 → 认为 onset 不可信，取路径拟合值；纯音素材实测 onset 比值会到 clamp 边界 1.49，把窗口推出曲外）；
   - 截距 = 按该 stretch 的路径残差中位数（起点偏移，与前端曲线平移口径一致）。
3. **起唱判据在检测窗内搜索**：句窗向两侧外扩 400ms（`TIME_WARP_WINDOW_PAD_MS`），在窗内**跳过开头有声段**后找第一个「前置静音 ≥150ms + 连续有声」的跳变；找不到时只有"窗口第 0 帧有声且窗口前 150ms 无声"才算起唱落在窗口起点。偏差对**期望位置**（`win_start`）计算——对窗口起点计算等于自证式打分（外扩会把偏差人为归零）。
4. **留痕**：`alignment.time_warp_stretch` + `alignment.windows_ms`（逐句用户时间轴窗口）；发音抽样直接复用 `windows_ms`（消除"评分用弯折窗、发音用仿射窗"的分叉；旧行回退 v5 公式）。
5. `SCORING_VERSION = "v6"`；docs/06 §9.4 / docs/10 §4.3 / docs/21 §3.6 同步。

## 5. 踩坑

1. **"有声/静音"不能只信 F0**：pyin 的 `voiced_flag` 在 128ms 帧窗下会把短静音"抹平"，再叠一层 160ms 中值滤波，真实换气就只剩临界长度——判据看上去有阈值、实际时灵时不灵。**能量包络才是不受这两层平滑影响的量**。
2. **速度来源要互证，不能单信一方**：onset 仲裁比值独立于 DTW 带宽（好），但纯音/onset 紊乱素材上会给出离谱值（实测 clamp 边界 1.49）；路径拟合受 ±10% 带宽压制（保守但稳定）。两者相差超阈值就取保守值——这一条是**测试直接抓出来**的（换 onset 优先后窗口跑到 -1434ms，句窗断言立刻红）。
3. **别把"窗口外扩"做成自证式打分**：检测窗放宽后，若偏差仍对**窗口起点**计算，起唱永远在窗口里、偏差永远接近 0 → 白送 95 分。偏差必须对**期望位置**（时间弯折后的 LRC 起点）计算。
4. **合成素材的"帧数"不是"采样点数"**：写测试素材时 `np.zeros(gap_frames)` 只造出 0.5ms 静音（帧数 ≠ 采样数），第一次跑出来的"仍无节奏分"是素材问题不是代码问题——判障时先把素材的实际 RMS/静音段打出来看。
5. **已知边界（未根治）**：整首 DTW 仍用 ±10% 的 Sakoe-Chiba 带，"偏慢 20% + 每句换气"这类累积形变（实测总时长 +39%）远超带宽 → 窗口放置仍有漂移（v6 用 onset 比值缓解）。后续可考虑按 onset 比值**预拉伸**用户序列后再对齐（另案，需对拍）。
